# 一品成片：产品目标与交互说明

> 历史讨论稿：其中网页优先、人工填表、强制预览、固定五件套等已由用户后续调整替代。当前以[小程序、多模态与社区预设方案](小程序优先与预设素材包-2026-10-27.md)和5份v2.1主需求为准；下文仅保留讨论记录，不作开发依据。

日期：2026-10-27｜状态：供共同讨论的产品方案，尚未制作界面或实现软件。本文细化产品定位、交互形式和载体选择；不自动改变现有5份需求基线。本文中的页面布局、两套风格名称和示例文案为设计建议；价格与性能仍待验证。

## 产品的一句话定义

一个面向小商家的商品上新素材制作工作台。用户提供一个商品的3–5张实拍、确认商品事实、选择视觉风格，先看到完整预览，再按次购买高清商品图、15秒宣传短片和文案。

首版的购买单位是“一个商品的一套上新素材”，界面围绕实际交付物组织。用户不需要理解提示词、模型、时间轴或编码参数；他们应能判断用的是哪个商品、写了哪些信息、成品是什么样、付多少钱和交付哪些文件。

## 首批用户与要解决的实际问题

先以帆布包、布艺小物等有实拍的独立卖家作为试验对象。这是便于验证的起点，尚没有真实访谈证明该人群一定愿意购买；后续可依据团队能接触到的真实商家调整。

典型情境：卖家准备上新一款米白帆布包，手机已有正面、侧面、内里和细节照片，但还需要主图、卖点说明、推广图、短片和发布文案。当前目标是缩短素材准备流程、降低多工具切换和反复排版的成本，并把可用结果组织成一套。

需要解决的痛点：

1. 信息分散：照片、商品信息和文案散在多个地方，制作前需要重新整理。
2. 排版与剪片门槛：卖家需要处理比例、字体、字幕、转场、音乐和导出规格。
3. 风格不统一：商品图、推广图和视频分别制作，视觉和卖点经常不一致。
4. 内容失真：自动文案可能编造材质/性能，图像生成可能改变商品细节。
5. 付费不确定：希望先看到具体效果，明确一次购买和修改范围，失败有处理入口。

产品效果以素材是否可用、是否节省准备时间、是否被商家实际上架/推广、是否愿意再买判断。节省时间需要记录用户原流程与本次实际耗时，不能先宣称“必省1小时”或“保证涨销量”。

## 交付目标与视频表现

| 用户得到的内容 | 初版规格 | 对用户的意义 |
| --- | --- | --- |
| 商品主图 | 1张1080×1080 PNG | 展示商品主体与核心标题 |
| 卖点图 | 1张1080×1080 PNG | 表达已确认尺寸、用途或细节 |
| 竖版推广图 | 1张1080×1920 PNG | 适合用户选择的竖版展示场景，实际平台规则另核验 |
| 商品宣传短片 | 1条1080×1920、15秒MP4 | 用实拍镜头编排、轻推拉、转场、字幕和已授权音乐展示商品 |
| 发布文案 | 一段介绍、三条卖点、视频字幕 | 用户可直接复制，再按发布渠道要求调整 |

首版短片采用原始商品照片的动效编排。它能把已有照片组织成有节奏的商品展示，商品形态与图案仍来自用户原图。生成式场景、人物演示、商品转身等能力另需验证保真、成本和交付政策，保留在后续扩展。

示例15秒结构：0–3秒商品整体及标题；3–7秒第二张照片展示已确认卖点；7–11秒细节图和尺寸；11–15秒收尾展示。用户可调图片顺序和文字，系统维护时长、字幕位置与节奏。未提供尺寸时使用其他确认信息，不为凑满画面补造商品事实。

## 交互载体建议

首版采用独立域名下的响应式Web应用：手机浏览器和电脑浏览器访问同一套服务，同一账号可继续自己的草稿和订单。用户通过链接/二维码进入，无需安装专用程序。

| 载体/界面 | 首版定位 | 使用方式 |
| --- | --- | --- |
| 买家网页 | 主要产品载体 | 手机选照片、确认信息、查看预览、购买；电脑可批量选照片、编辑和下载ZIP |
| 网页制作工作台 | 核心操作界面 | 分步任务引导＋可视预览＋有限参数编辑 |
| 我的作品/订单页 | 保存与复访入口 | 找回草稿、付款状态、任务进度、成品和售后 |
| 运营网页 | 团队内部工具 | 查失败、退款、模板版本、成本和必要的受控客服操作 |
| 支付宝支付环节 | 收款与支付确认 | 根据实际开通的网页支付能力跳转/调起/展示相应收银入口，再返回原订单 |
| 支付宝小程序、原生App、桌面安装程序 | 后续评估载体 | 需求与获客验证后再决定是否开发 |

选择网页是本项目的实施建议：手机适合现有相册输入，电脑适合排版确认和文件整理，一套业务可同时支持两端。是否支持具体内置浏览器、支付返回、下载/保存到相册，必须在真实设备上验证；不能把“手机可下载文件”直接写成“所有浏览器均可一键存相册”。

Vibe Pay官方文档明确面向网页/移动应用提供基础支付、查单与退款能力，订单和权益可由开发者自行建设。具体商户条件、网页支付产品和跨端行为以实际获准能力及联调为准。独立网页接入支付宝付款不等于已经有支付宝小程序，也不保证获得支付宝内搜索入口。[Vibe Pay官方文档](https://aipay.alipay.com/docs/vibe-pay.html)

## 交互原则

以五步主流程“上传商品 → 确认信息 → 编辑预览 → 确认购买 → 领取成品”组织任务。主要操作为选择、填写、拖动顺序、点击画面对应字段与播放预览。界面始终显示当前商品和步骤，普通用户不接触模型参数或后台执行细节。

允许少量自然语言辅助，例如用户写“想要简洁、突出尺寸”，系统将建议映射为允许的模板/文案选项；任何属性变更要重新展示并确认。首版可先提供直接文本编辑与风格选择，是否加入自由文本指令入口需下一轮原型确认，不能把尚未定义的任意指令执行纳入P0承诺。

预览修改分两种反馈：文案、顺序、色板等可直接反馈在画面示意；涉及最终视频或完整预览时，明确需要重新生成预览，并遵守免费额度。即时画面示意不是已完成高清导出，不能让用户误以为所有变更都已渲染。

## 具体页面与操作

### 1. 首页与进入制作

展示一个真实授权样例的原图、三张图、可播放短片，注明是示例；明确输入3–5张实拍、输出清单和价格假设。主按钮“开始制作”，次入口“先看示例”，以及“我的作品”。浏览样例无需登录；正式上传自己的素材前完成轻量账号登录，认证方式待接入设计确定，不默认付款本身已经创建可恢复账号。

用户进入时应能回答：这个工具服务谁、我需要准备什么、最终拿到什么、怎样收费。样例不能用预先制作成果冒充当前用户实时生成。

### 2. 上传商品

手机：从相册选择；电脑：点击选取或拖拽照片。卡片网格显示缩略图、上传/检查状态，支持删除、调整顺序、指定封面。提示建议照片角度与分辨率；对不合格素材说明哪张和原因，成功部分保留。已建立的规则是3–5张、JPG/PNG、单张不超过10MB，其他技术上限由原功能规格约束。

每次任务只有一个商品。不同款式混入时用明确提示请用户自行确认同一商品，初版不假定算法能自动判定所有SKU。主按钮“下一步：确认商品信息”。

### 3. 确认商品信息

字段包括商品名、材质、颜色、尺寸与单位、用途和用户认可卖点。用户可以填写简单文字，由系统整理为结构化表单；直接填表同样可用。AI可以从用户文字整理或提供待确认建议，未知字段显示“未提供”。首版不依赖视觉模型从照片识别材质、尺寸或性能。

示例：“米白帆布包，宽35厘米、高38厘米，单层，无拉链。”系统列出原始信息与拟用文案，用户编辑并确认。未提供的防水、防盗、耐磨认证不能自动变成卖点。缺失信息允许留空，模板改用已确认内容。主按钮“确认信息，选择风格”。

### 4. 制作工作台与预览

电脑建议三栏：左侧素材/风格，中间画面，右侧文案/商品信息；顶部步骤和保存状态，底部视频播放与图片顺序。只提供用户能理解的控制，不暴露专业时间轴轨道。两套初版风格暂命名“简洁商品展示”“温暖手作”，名称和具体美术方向待看样张后确定。

中间切换“主图、卖点图、推广图、15秒短片”，文案用单独区域展示。点击标题定位右侧字段、编辑后看示意；在素材卡片拖动排序；选择固定色板和允许构图。关键内容超框时说明原因并阻止带错版本购买。

手机采用单列：顶部步骤，中间预览，底部当前操作；风格、文案、顺序用分组面板/底部抽屉编辑，保留一个明确主按钮。不能把电脑三栏压缩到手机。视频默认不自动有声播放，用户主动播放与开声。

“生成预览”产生低清带水印的三图和短片，显示当前版本；已变更但未重新预览时标“有修改待预览”，不拿旧视频冒充新版本。看到满意效果后点击“确认这版，购买高清素材包”。

### 5. 确认购买与付款

一页列出当前预览缩略图、五类交付物、总价、预计时长/失败处置、7天领取期限、48小时内一次规定范围修改和退款规则。9.9元仍是定价假设，正式金额须根据成本与试用反馈冻结。

用户买的是刚确认的这个版本。付款后只进行约定的高清渲染，不重新随机生成另一套文案和画面。修改事实/素材/模板后重新预览与报价。付款方式用真实开通能力联调；返回网页后查原订单，不把返回动作当作付款成功。

### 6. 制作进度与异常

显示“付款待确认、准备素材、生成图片、合成视频、检查文件、可领取”等可核对阶段；无法计算精确比例时只显示阶段与合理说明。允许用户退出页面，回到“我的作品”恢复任务，不能要求始终前台等待。

付款未知：显示“正在确认，请勿重复付款”，可查询原单。制作可重试故障：显示正在恢复，重试不另扣款。平台无法完整交付：按既定失败政策进入退款，区别申请中、处理中与到账成功。等待时长目标需实际测量，当前不承诺“30秒必出片”。

### 7. 成品领取、修改与复访

成品页显示三张高清图、可播放视频、文案和“下载整套ZIP”，同时允许逐个下载和复制文案。手机根据实际浏览器能力提供下载、支持时的系统分享/保存和明确说明；电脑便于ZIP整理。用户看到具体到期日期，而不只写“有限期”。

48小时内的一次受限修改包括已确认文案、图片顺序、色板等；界面显示剩余机会和范围。平台纠错不消耗用户机会。替换商品或换一批素材是新任务，先明确报价；退款、修改失败等状态可在原订单内追踪。

“我的作品”按草稿/制作中/已完成组织，支持从作品继续操作；需要第二次上新时可复用允许的风格偏好，首版仍按一个新商品单独处理。实际使用反馈为自愿，不与下载或售后权利绑定。

## 端到端示例

手作卖家小林上传4张米白帆布包照片 → 写明尺寸、材质与无拉链 → 确认系统整理的三个真实卖点 → 选择“温暖手作”示意风格 → 调整封面和标题 → 播放15秒带水印预览并查看三张图 → 看到拟定9.9元素材包清单后决定购买 → 后端确认付款并按原版高清制作 → 在作品页领取图片、视频和文案，用于自己选择的发布渠道。

这条链路的测试重点是：用户是否看懂产物、是否无需指导就能改到满意、商品事实有无失真、预览/成品是否一致、付款后是否稳定完整交付。

## 当前建议与待共同决定项

| 议题 | 当前建议 | 下一轮需要的材料或判断 |
| --- | --- | --- |
| 首批用户/商品 | 有实拍的帆布包或布艺手作小卖家 | 用户能实际接触的商家、获授权商品照片及真实上新需求 |
| 首版载体 | 手机/电脑共用响应式网页 | 目标用户最常使用的设备、浏览器和领取方式 |
| 主交互 | 分步引导＋可视预览＋直接编辑 | 先走一遍低保真流程，验证会不会卡在表单/编辑/结算 |
| 风格方向 | 两套固定模板，暂用简洁/温暖 | 用同一商品做样张比较，避免只凭风格名定稿 |
| 视频能力 | 实拍编排的15秒商品短片 | 样片是否达到用户愿意发布的质量；若用户目标是全生成视频，需重定产品范围 |
| 价格与售后 | 9.9元/包是假设；保留现有规则基线 | 实测成本、商家付费试用和售后反馈 |

下一步制作低保真页面和一份真实商品样例，先检验“上传—确认—预览—购买—领取”主流程；进入工程实现前冻结关键输入、输出与交互，不提前把讨论建议标成已确认需求。
