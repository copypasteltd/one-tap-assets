# 02 · 组件与交互状态规范

本版固定22类组件。共用视觉与交互契约，平台原生登录、相机、权限、支付等通过适配层实现。组件表与状态枚举见[component-registry.json](../../../../assets/design/柚子创作社/v1.0/component-registry.json)，不是已存在的代码库。

## 2. 按钮与可用性

主按钮最小52高；同屏一个。图标在左、文字居中、可选方向箭头在右，避免同时放两个不一致的动词。`拍照做素材`进入拍照/选片，`用这个方案`进入方案确认，`确认并支付 ¥{total}`触发真实支付，`保存整套素材`只处理已交付媒体。

忙碌状态使用“正在上传”“正在确认订单”“正在准备保存”等真实动作；提交锁防止双击，但幂等由服务端负责。不可用按钮旁必须解释原因，例如“还需补拍整体照片”，不能只变灰。不可售方案不显示虚构金额，明确“暂未开放制作”。

整张卡与卡内收藏/举报分别定义热区，收藏不误触进入付款。可滑动标签与上下滚动不抢手势。关闭弹层或详情后保留原列表滚动位置与选项。

## 3. 作品卡固定信息顺序

先看样例与方案名，再看来源/作者，再看当前效果、图数/时长/节奏，最后看价格/预计区间与适配状态。样例附“方案样例”。进入详情才能看完整声音/人物、输入条件、清单与许可，不把所有交易条款堆成卡片小字。

一个风格可能有多个变体。卡片显示默认公开变体或“多种效果可选”；不能用最便宜的图文价格配AI人物效果且不说明。照片不足/能力停售时保持样例可浏览，选用动作明确进入补拍/换效果或被禁用。

“官方”“社区作者”“AI演绎”“已收藏”“已选”各有不同职责。官方标来源，AI标内容性质，收藏是个人状态，选中是当前制作选择；不能合并成一个模糊彩色印章。

## 4. 素材、播放与保存

清单按已售合同顺序排列，图片与视频分别计数，文案独立。图3–5张只是当前官方方案范围，未来社区按其已发布合同显示，不在组件中写死四张。视频展示实际秒数、声音状态和AI说明，讲解片不能用静音占位假装已完成。

相册保存有两种动作：“继续保存未完成项”只续存失败/未开始项；“再存一份”由用户明确触发。回调未知单独提示可能已保存，用户先检查或选择重存，不能自动当失败反复保存。相册失败不会改变云端交付状态或再扣制作费。

## 5. 弹层、反馈与异常

底部弹层只处理一个短任务，例如保存进度、变体说明、补拍原因；长清单、退款详情和创作编辑使用完整页面。支持明确关闭与系统返回，涉及正在支付/保存时说明离页影响，不阻断退出且不伪称客户端后台持续保存。

删除原图/作品、撤销发布、取消订单使用明确的确认文案和可见取消。清理云端文件不声称删除用户手机相册副本。短toast仅用于收藏、复制等低风险反馈；查单、退款、失败与权益期限用常驻状态区。

## 6. 组件扩展约束

新增组件必须登记名称、输入数据、状态、主动作、键盘/读屏语义、窄屏行为和对应页面。先复用这22类的能力；不为每页新建近似按钮、标签和卡片。业务变化由需求版本处理，不能借视觉组件加入作者提现、评论榜单、自动外部发布等未纳入P0的范围。
