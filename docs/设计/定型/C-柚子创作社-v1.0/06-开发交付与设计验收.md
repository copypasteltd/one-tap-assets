# 06 · 开发交付与设计验收

## 1. 交付资产

本轮提供9份设计文档（含README）、机器可读tokens、23页面和22组件注册表、50项需求设计映射、当前基线指针、原始C稿/3单页/提示词及来源记录、参照画册、对比核验、文件摘要和归档包。全部位于一品成片路径下。

tokens定义语义值，注册表定义页面和组件责任；它们不是小程序组件代码，不直接代表开发完成。CSS导出仅作变量参照，平台实现应从JSON映射到各端可用的样式能力并验证尺寸下限。

当前3个页面有原始高保真参照，其余20个交互单元已有规格。后续设计/开发顺序按依赖推进，不重新选风格：

1. 先做页面壳、按钮、识别摘要、作品卡、清单、错误与状态组件，校正对比和长文案。
2. 做D01–D07正常路径及选片/识别/无适配状态；绑定真实草稿与报价数据。
3. 做D08–D15/D23的付款待查、持久制作、完整交付、部分相册保存、修改和退款状态。
4. 做D16–D22基础社区创作者、审核、派生、治理与隐私设置。
5. 分别完成双端真机适配和完整v3业务验收；Plus等P1/P2单独规划，不混入首版通过结论。

该顺序不是新工期承诺。完整v3仍含10套/14变体、三条产线与生成式P0，不以做完这套UI代替模型、质量和交易准入。

## 2. 页面交付要求

每个页面交付默认态、加载、空态、局部失败、权限拒绝及相关业务状态；写明入口/返回、数据源、当前主行动、变体条件、窄屏/大字/安全区行为。只交一张成功态截图不能算页面完成。

页面中图数、时长、价格、领取与报价期限均从版本/合同读取；用于联调的示例数据显式标记，不能作为线上固定常量。官方与社区、样例与本人成品、交付与保存、退款申请与到账必须在视觉和语义上区分。

图片、图标、字体、音乐和公开样例各自登记来源和使用权。原始设计稿可以作内部参照，不把其中的虚构榨汁杯与印章当作真实商品或资质，不把展示板直接切成生产控件。

## 5. 设计变更与回归

小调整要列出影响的tokens、组件、页面和状态。主题/主导航/主流程/权益表达改变需升相应版本，保留原基线，不直接覆盖原始稿。所有方向变更遵从用户后续指示；本轮用户已选C，不再保留“等待选择”或默认推荐B作为当前状态。

复核命令：在本项目根目录运行 `python -X utf8 scripts/设计选型/定型C设计基线.py --verify`。该命令只核验已留存基线，不调用模型、不启动浏览器或虚拟化环境。
