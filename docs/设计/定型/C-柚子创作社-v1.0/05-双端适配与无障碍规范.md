# 05 · 双端适配与无障碍规范

本规范定义设计意图与验收条件，不代表已验证任何宿主版本或资质。最低基础库、接口与审核条件由实现阶段按届时官方资料确认并记录；不得用一个平台的演示替代另一个平台的证据。

## 1. 共用与分别实现

两小程序共用色彩、文字角色、间距、组件语义、页面结构、方案/清单/状态和数据权限。平台品牌、原生胶囊、系统弹层、支付页等保留宿主样式，不强行改成照片印样风格。

| 能力 | 共用的产品表达 | 两端分别核验 |
| --- | --- | --- |
| 顶部与返回 | 同一页标题、正确层级和返回目的地 | 状态区、胶囊占位、导航高度和原生返回手势 |
| 登录 | 上传/持久化/订单前取得必要身份，样例可先浏览 | 合法会话、隐私同意、过期恢复；不同平台账号不自动合并 |
| 拍照/相册输入 | 3–5张、逐项检查、失败照片可替换 | 原生选择器、权限拒绝、文件类型、临时路径与回前台 |
| 上传 | 本地与云端成功分开、成功项保留 | 网络切换、后台、恢复、平台域名配置与文件限制 |
| 视频 | 用户主动播放、完整画幅、声音与AI说明 | 真实编码/声音、全屏、控制层与回前台行为 |
| 交易 | 原单核验、明确金额、未知先查询 | 各自获准支付/订单/退款路径，审核与类目限制 |
| 相册 | 用户触发、逐项计数、未完成续存 | iOS/Android各平台真机授权、保存回调、空间不足和暂停 |
| 客服/反馈 | 订单内问题恢复与售后入口 | 可用原生能力和合法联络路径，不以外链绕过限制 |

不支持或未获准的能力给明确不可用状态，不假装成功，也不借另一平台网页收款/保存接口绕过本端限制。网页Plus不承担小程序基础功能兜底的强制跳转。

## 2. 屏幕、单位和安全区

设计基准375逻辑宽，覆盖320、375、390、430与宽屏内容约束。边距和内容采用弹性布局；文字和关键热区设置独立下限，不把整张图或375画布整体缩放。

使用rpx时以750设计宽映射，例如375基准的16间距意向为32rpx。该映射不自动适用于最小字号和最小热区：320宽时仍需至少12逻辑字号、44触达、52主按钮高。实现阶段使用平台可表达的最小值约束/适配层，不能把一套rpx当所有设备的已验证布局。

固定底部动作区应位于根页底导航之上，内容底部预留“实际动作区高度＋实际底导航高度＋设备安全区＋16”。详情页无根底栏时不重复留栏高。多行按钮、文字放大、软键盘、横屏媒体均按实际高度重新布局，最后一项内容可完整滚入视野。

系统顶部和胶囊区域由宿主数据决定，标题/返回不放到胶囊下面。原生状态栏不把生成图中的9:41当真实内容。手机外框与展示板阴影不进入实际小程序。

## 3. 可读性与对比

本项目内部基线：普通文字与背景对比至少4.5；大标题至少3；关键图标、边界和选中提示至少3或通过独立文字/形状提供同等清楚线索。禁用仍需可理解的文字原因，不仅用极低透明度。

核心按钮使用果橙＋深绿墨，对比度约4.61；文本链接深橙＋奶白约4.93；次级正文＋奶白约5.49。果橙白字约2.60，禁止直接照抄。数学比值仅检验指定纯色，不等于拍照背景、抗锯齿与实际设备已通过；文字置于照片上必须有稳定底板/遮罩并复核。

正文支持字体增大到200%的设计检查：标题允许折行，方案卡可从左右变上下，四张素材图可改两列，确认页金额与主行动不裁切。不对价格、时长、错误说明使用自动缩小字号。

## 4. 触达、读屏与焦点

所有交互区域至少44×44逻辑单位，主按钮至少52高；图标可24，但热区不能只有24。邻近收藏、选用和举报分开，删除/取消订单不紧贴主行动。

图标有可读名称；图片注明其用途而不是读文件名；方案卡说明名称、作者、当前效果与可选状态；AI与官方标识有文字。只旋转视觉照片，不让读屏顺序跟随拼贴视觉任意跳跃。

阅读顺序为标题→说明→主要内容→状态→行动→导航。弹层打开焦点进入标题/首个合理控件，关闭回触发控件；在平台可用能力内提供键盘/读屏语义。异步识别、支付待查和保存结果通过适度状态播报，不每秒播读倒计时。

颜色不作为唯一状态：选中有勾与可读状态，错误有原因，保存未知有文字。不能仅以红点区分未完成订单或待处理售后。

## 5. 动效与弱网

尊重减少动态效果偏好和宿主可用能力。无相应系统读取能力时提供无动效默认实现或产品设置，不以无法检测为由强制循环闪烁。静态文字说明能独立表达全部状态。

弱网时先显示结构和真实占位，不提前把样例/草稿认作已保存。图片加载失败独立重试，不清空页面筛选；分页失败保留已读卡片；上传失败保留已上传成功项。支付/制作未知先查询原单，不能套用通用“重新开始”动作。

## 6. 隐私与权限呈现

首次拍照/选片/保存时解释当前用途，再触发系统授权。拒绝可以返回和重试，不用满屏阻拦或模糊的“为了更好体验”索取无关权限。浏览样例不强求手机号、头像或全部相册访问。

清楚区分私有商品输入与公开方案样例。作者发布需自有/授权样例；买家照片、档案、订单、签名下载链接不因选用社区方案向作者开放。删除云端数据说明实际范围，不声称清除手机中已保存的副本。

## 7. 验证矩阵与证据

最终设计/开发验收至少覆盖：支付宝iOS、支付宝Android、抖音iOS、抖音Android；分别记录设备、宿主/基础库、屏宽、文字设置、权限与网络条件。模拟器或本地HTML画册只帮助看设计，不能证明原生相机、支付和相册能力可用。

每类至少跑通首次拒权/恢复、3–5图上传、识别与社区选择、报价/付款待查、离页制作恢复、9:16有声预览、部分保存/结果未知恢复、退款状态与创作者基础发布。当前全部真机项为待执行，不在本轮文档核验中冒称通过。
