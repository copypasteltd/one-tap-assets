## 产品目标

让商家在支付宝小程序或抖音小程序中拍摄商品，系统自动识别商品与特征、整理原本需要人工填写的信息；用户选择官方或社区预设，即可自助生成一套规范素材，并保存图片和视频到手机相册。网页Plus处理精细编辑、品牌定制和复杂批量任务。

核心单位是“一个商品档案×一个方案版本×一个执行变体的完整素材包”。方案决定创意和表达，执行变体决定制作方式、人物/声音、输入和成本，订单冻结具体执行计划。预设同时定义输入要求、视觉风格、镜头节奏、交付数量/顺序/规格、文案取用规则和失败政策。商品事实与创意表达分别管理。

要解决的核心问题包括：商家不会填写商品卖点、没有演员与拍摄场景、缺乏脚本/剪辑能力、单条生成不能形成完整素材包，以及生成画面好看但商品包装/结构不准确。系统承担识别、策划、制作、后期和验收，用户完成拍照、选效果和必要授权。

## 载体与自助路径

| 载体 | 定位 | 核心职责 |
| --- | --- | --- |
| 支付宝小程序 | 核心移动端，P0 | 拍照、自动识别、选方案、购买/制作、相册保存、社区方案的浏览和发布 |
| 抖音小程序 | 同级核心移动端，P0 | 相同业务闭环，登录/权限/交易/相册分别适配 |
| 网页Plus | 进阶版，P1 | 精细排版/字幕、复杂编排、品牌、批量商品和自定义规格 |
| 内部运营端 | 支持系统 | 预设发布审核、质量、故障和售后；正常制作不依赖人工代做 |

主流程：拍照/选照片 → 多模态自动识别并建立商品锁 → 选官方/社区方案及效果变体 → 系统规划脚本/时间轴/能力与报价 → 一键生成（收费时明确付款）→ 云端画面/视频/后期/验收 → 素材列表 → 主动保存到相册。

普通客户只提供照片并选择方案；登录、拍摄/隐私、付款与保存仍由本人授权。识别摘要可展示“米白色托特包、双提手、外侧口袋”等，默认无需确认表单。只有照片不合格或混入多个商品时提示补拍/选择主体，不要求补齐未知材质、尺寸等文字。浏览方案可先不登录，持久上传/订单使用合法平台会话。

## 多模态商品档案

照片必须进入支持视觉输入的LLM，跨图形成结构化商品档案，而不是只用文件尺寸检查或预设类别代替识别。系统应提取商品类别、建议名称、颜色、图案、外形、可见结构/纹理/细节、照片角色与质量、包装可读文字、适合展示的特征，并推荐适配方案。

| 信息层 | 系统处理 | 成品使用 |
| --- | --- | --- |
| 直接可见 | 记录值、来源照片/区域、证据和字段可靠度 | 通过校验后自动写入标题、细节文案和镜头安排，不强制客户逐项确认 |
| 包装/标签文字 | 识别并记录原文、位置及OCR可靠度，区分标注与真实性 | 允许字段核验后可用“包装标注…”；品牌真实性、有效售价、认证/功效不因OCR而自动获证 |
| 推测信息 | 如“可能是帆布”“适合通勤”，保留为候选 | 用于推荐/规划；未经其他可靠依据不转为确定的材质或性能声明 |
| 不可判定 | 精确尺寸、成分、产地、现价、功效等保留null/未知 | 省略或替换为可见特征，不要求填表，也不为凑文案编造 |

模型自报置信度不是准确率保证。字段必须通过结构、来源、跨图冲突和事实政策校验；阈值在独立样本上确定。低置信字段省略、退到宽泛类别；真正无法识别的照片仍有分析记录，可推荐通用方案。视觉服务超时不得虚称已识别：收费前有限重试后提供稍后重试，不把整个视觉环节静默跳过。识别已完成后的文案服务故障，可由同一档案按规则生成保底文案。

用户可选点“识别有误”作轻量修正，但正确识别的正常流程没有必填表、提示词或审稿关卡。档案、商品锁、模型/规则版本与证据随报价冻结，修改原图或商品信息应重新分析/报价。原图和档案默认私有，不因使用社区预设变为社区内容。

商品身份锁须记录商品本体、包装形式、数量单位、关键结构、主色、标识文字区域和附件的证据/未知。生成场景和人物可以是AI演绎，商品不能从瓶装变杯装、单件变套装或凭空增加功效。对不可见背面/内部结构采用不展示、换有证据机位或收费前补拍；通过生成画面不能反过来证明商品事实。

结构化目录见 [官方10套与14变体v3配置](../assets/presets/presets.v3.1.json)，字段、节奏和治理细节见 [小程序与社区预设专项](设计/小程序优先与预设素材包-2026-10-27.md)。v2配置保留为历史。当前配置均为DESIGN、禁售、模型/价格待定，不代表已有可用引擎或公开社区。

图片包是独立交付物，不把九宫格裁图或任意视频截图自动算作正式主图/细节图。原生生成尺寸与交付编码尺寸分别记录；720p放大为1080p不能宣传原生1080p。人物讲解必须具有约定语言的可懂语音、对应字幕和AI演绎标识；仅有嘴部动作或shots里的voiceover文本不算有声交付。

## 社区机制

普通用户：浏览官方/社区方案 → 看样例、作者、清单和节奏 → 收藏/用同款 → 套用自己的私有商品档案 → 保存自己的素材。按识别类别与可见特征推荐，用户仍可自行选方案；不要求发帖才能制作。

创作者：从允许派生的方案起步或新建 → 在小程序受控编辑器选择叙事块、画面形态、运镜、Look、人物/声音、字幕/配乐和输出槽位 → 组合准入执行能力 → 用自有或获授权照片生成样例 → 检查清单/成本/许可 → 明确同意发布许可 → 审核发布。基础版式/节奏创作可独立完成，生成式能力按已准入组件开放；网页Plus深化复杂时间轴，不能把社区创作全部锁到网页。

社区方案使用与官方相同schema和执行引擎，发布配置不发布买家的照片、识别档案或订单。允许配置已批准模块，不执行作者脚本、任意外链下载或未经准入模型工作流。审核内容、商品真实性、字体/音乐/样例许可与实际产物；发布审核可有人参与，买家正常生成仍全自助。

方案有作者、来源/派生链、版本、许可和审核状态。收藏与使用数据去重，支持举报、暂停新用、纠错与申诉。新版本不覆盖旧单；普通下架继续原合同，权利争议等强制禁用影响旧单时明确通知并退款/补偿，不静默换方案。

P0采用免费分享方案、按平台统一的制作服务报价使用（正式价格待验证）；先不设计作者付费模板、分成、打赏和提现。社区增长以有效作品/复用与质量衡量，不能让热度绕过审核或扩大用户输入权限。

## 交付、交易与指标

首版同时建设原图、逐镜AI和参考整片三条云端路线。订单冻结SourceRecipe来源、PublishedRecipeVersion、ExecutionVariantVersion和OrderExecutionSnapshot，串起事实文案、参考帧、视频、原声/配音、字幕/音乐、封面、整包验收。原生整片后必须执行显式后期，不能假定供应商已完成配方的compose设置。素材/能力不足在收费前处理；已付后无法完整履约按有限重试/失败退款，不减少必交数量。

订单冻结照片、识别档案、预设/模板/模型/规则版本、交付清单和报价，按平台分别接入支付宝/抖音批准的支付路径。官方与社区方案均不能隐形收费。网页Plus为独立深化层级，基础用户无需升级即可制作、领取和售后。

用户点“保存整套/图片/视频”，客户端逐项写相册、准确显示部分成功并只重试未完成项。服务端完整生成与相册保存分别计状态；保存失败不重复收费，云端成品默认交付后7天可领。双端×iOS/Android真实保存为P0能力门槛。

质量衡量覆盖识别准确/覆盖、商品身份误放/误拒、人物连续性、语音与字幕、自动整包成功率、逐变体成本/耗时、保存、官方10套/14变体完成度与社区有效复用。每个可售执行变体至少30组授权输入验证，14个最小变体至少420次整包执行；同一照片组可跨变体复用，但执行次数和唯一商品数分别报告，失败样本不得剔除。

时限按合同分别管理：原图产线p95目标≤120秒/硬截止600秒；逐镜AI目标≤900秒/硬截止1800秒；参考整片目标≤1800秒/硬截止3600秒。这些是待实测的初始设计值；上架前根据成本/容量冻结可履约版本，超过硬截止进入失败处置，不能沿用旧版所有任务10分钟的规则。自动修复最多一轮，受每节点和整单预算限制，重启/重试不延长截止。

验收与排期见 [实施计划](05-验收测试与实施计划.md)。本轮修订文档和配置，没有创建/审核小程序、上线社区或运行真实识别服务。

v3.0增加生成式核心能力，旧版69–99人日/2人8–12周仅是v2.1基础范围的历史估算，不适用于本版总工期。最新任务依赖与重新估算门槛见 [v3实施任务](实施/v3.0云端生成服务任务与里程碑.md)，变更对应关系见 [需求变更记录](设计/需求变更记录-v3.0.md)。小程序权限、供应商能力/费率、真实支付和质量仍需实测；本次只扩展需求和设计配置。

## v3.1 Codex服务方向

内容梳理、实际制作、后期制作、预验收全部由Codex app-server中的对应角色处理，依真实工具回执与检测证据推进。每单按选定风格、目标清单及制作路线组装SkillBundle；客户仍然只拍照、选方案、按需付款并领取，不增加聊天/填表或审片步骤。

后台使用每单原生执行实例和分角色上下文。预验收由新的事实复核、风格复核会话交叉检查，结合确定性媒体检测，全部通过后原子交付；最多一轮修复及原截止不变。交付/失败/取消即释放进程、上下文和短期能力，成品继续按7天领取规则保留，售后建立新实例。

本次新增P01-F51—F58，合计58项功能/58主用例（52 P0、4 P1、2 P2）。Codex推理、Skill加载、工具、复核与修复成本全部进入冻结预算。更高质量是待真实对照验证的目标，当前没有可运行Agent服务。[Codex总体设计](开发/14-Codex内核与分阶段编排.md)与[Skill/实例/复核/验证规范](开发/README.md)为本轮开发约束。

2026-10-28公开样例实施细化：社区公开展示单独取得作者同意，审核后复制已验收的成品，最多30天且可随时撤回。原商品照片和SAMPLE制作上下文保持私有，按原有效期清理；自然到期保留另行批准的公开副本，主动商品/账户删除则一并撤回。撤回、许可/资源失效或到期停止公开分发及方案新制作，不改写已售订单。该规则细化既有社区和隐私需求，不新增编号；实际验证边界见[公开样例专项](实施/社区公开样例独立持有与撤回-v1.0.md)。
