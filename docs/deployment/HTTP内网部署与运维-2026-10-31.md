## 普通 HTTP 下的交互

Plus、社区预设编排、下载请求以及客服/审核操作不再直接依赖 `crypto.randomUUID()`。HTTP 浏览器使用 `crypto.getRandomValues()` 产生标准随机 UUID，继续提供独立幂等键；浏览器缺少随机数能力时明确失败，不退化为时间戳或弱随机数。

文案复制在浏览器没有 Clipboard API 时使用用户主动点击触发的选中文本复制；复制失败会提示手动复制。实际普通 HTTP 浏览器已验证 `isSecureContext=false`、无 `randomUUID` 时，部署产物生成的 128 个键均独立有效，合成回放的原生复制操作返回成功。浏览器没有使用证书忽略选项或“将不安全源视为安全”的启动参数。

Plus 的本人项目仍需手机授权，浏览器回放仍为演示数据；HTTP 适配不绕过身份、费用确认或制作准入。

## 常驻与维护

`one-tap-assets-db`、`one-tap-assets-api`、`one-tap-assets-worker`、`one-tap-assets-reaper`、`one-tap-assets-media-maintenance` 和 `one-tap-assets-backup.timer` 均保持 active/enabled。每日数据库备份为台北时间约 03:30–03:35，使用原生 PostgreSQL 工具、密码文件和互斥锁；备份服务是执行后退出的 oneshot。

```bash
cd /opt/one-tap-assets/app
sudo bash deploy/linux/healthcheck.sh
sudo systemctl status one-tap-assets-api one-tap-assets-worker one-tap-assets-db
sudo journalctl -u one-tap-assets-api -u one-tap-assets-worker -n 50 --no-pager
sudo systemctl restart one-tap-assets-api one-tap-assets-worker one-tap-assets-reaper one-tap-assets-media-maintenance
sudo systemctl start one-tap-assets-backup.service
```

配置模板及重新应用脚本见 [deploy/linux](../../deploy/linux/README.md)。应用配置前保留本项目配置快照，nginx 通过检查后 reload；不会重启其他业务。后续使用模板也不会重新启用 HTTPS。删除日志与数据库恢复必须分别处理，数据库备份不包含素材、应用密钥或完整隐私/财务恢复；私有 OSS、异机备份和正式恢复验收仍待完成。
