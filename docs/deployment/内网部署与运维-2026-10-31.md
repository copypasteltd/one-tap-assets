## 常驻服务与维护

以下单位已配置 `enabled`。应用四进程、数据库和备份 timer 均为 `active`，备份任务是执行后退出的 oneshot。

| 名称 | 职责 |
| --- | --- |
| `one-tap-assets-db` | 专用 PostgreSQL 17 |
| `one-tap-assets-api` | API、Plus 与管理页面 |
| `one-tap-assets-worker` | 队列与制作调度、Skill 文件预载 |
| `one-tap-assets-reaper` | 实例释放与回收 |
| `one-tap-assets-media-maintenance` | 素材生命周期维护 |
| `one-tap-assets-backup.service` / `.timer` | 数据库备份；台北时间每日约 03:30–03:35（UTC 19:30–19:35） |

```bash
sudo systemctl status one-tap-assets-db one-tap-assets-api one-tap-assets-worker
sudo journalctl -u one-tap-assets-api -u one-tap-assets-worker -n 50 --no-pager
sudo systemctl restart one-tap-assets-api one-tap-assets-worker one-tap-assets-reaper one-tap-assets-media-maintenance
sudo systemctl start one-tap-assets-backup.service
cd /opt/one-tap-assets/app
sudo bash deploy/linux/healthcheck.sh
```

重启和配置改动仅针对本项目，nginx 通过配置校验后 reload。更换环境变量后需要重启相应应用进程。数据库原生包未注册到全局包管理，后续小版本更新需重新获取签名元数据、校验二进制后受控切换，不能依赖系统自动升级。

备份脚本使用 PostgreSQL 17 `pg_dump`、TLS 校验、root 密码文件及互斥锁，先写 `.partial` 再改名，并生成 SHA256。已生成首份数据库备份；没有执行全量灾难恢复或财务恢复演练。数据库备份**不包含**本地素材对象、TLS/应用密钥和独立删除日志，当前也未配置异机备份或自动清理策略。恢复时必须按既有隐私重放/财务恢复文档分别处理，不能用数据库包覆盖删除日志。当前素材采用本机磁盘，正式生产仍需配置私有 OSS。
