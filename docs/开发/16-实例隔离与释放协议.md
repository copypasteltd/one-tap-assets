# 16 · 实例隔离与释放协议

2026-10-27｜开发设计v1.1。对应P01-F53/F56/F57；本地不启动Docker、WSL、虚拟机或依赖它们的执行环境。

2026-10-28实施补充：独立原生回收入口、持久领取/孤儿扫描、清理代次、不可变回执与冻结输入保留已接入；专项使用真实登记Node子进程和显式测试清理端口。原生受限身份/完整进程树与真实Codex仍未准入，运行目标尚未获得生产SLO证据。见[实施细则](../实施/独立实例回收与冻结输入保留-v1.0.md)。

## 1. 分配粒度

采用“每单执行实例、每角色独立会话”。同一商家的新商品、新订单及售后修订均建立新执行实例，通过授权检查点恢复必要数据，不复用上一单的聊天历史。付费前分析/报价使用短期`preview_session_id`，报价15分钟有效；规划结束立即释放预报价进程，不占用资源等客户付款，后台按原24小时策略保留未付输入。

已付阶段只在需要推理或工具编排时启动Codex。供应商长时间运行时，回执及检查点持久化后可退出进程，普通Worker轮询原任务；收到结果后重建同单受控上下文继续。模型会话不是任务保活条件。这样满足每单专属执行上下文，同时控制大量空闲常驻进程的内存。

## 2. 原生隔离

工作目录形如`runtime/agent-instances/<opaque-instance-id>/`，包含受控Skill副本、输入引用、阶段工件、临时媒体与最小运行记录。真实服务使用任务专用低权限OS身份、目录ACL、进程树/资源限制、出站白名单及网关能力；路径按规范化后的绝对目录验证，拒绝符号链接/重解析点跨根。

同OS账号的多个目录和不同thread_id不足以证明租户隔离。Windows开发按原生受限身份/ACL/Job Object验证，生产可选择经验证的原生服务宿主与安全域；若隔离/权限模型达不到门槛，不向多租户开放。不得以关闭沙箱或共享个人用户目录解决兼容性。确切原生沙箱/配置要与锁定CLI在G0核对。[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing)。

本项目选择专用低权限用户/ACL的原生进程路径，G0优先评估官方Windows `elevated`实现及额外角色隔离；不把名称中的elevated误解为给Agent管理员权限。为固定本项目的执行方式，不启用MXC，也不使用Hyper-V、Windows Sandbox虚拟机或任何容器/WSL后备；官方给出的MXC禁用要求是`windows.allow_mxc = false`，须在锁定构建的有效管理策略中核实，本轮不修改机器策略。`unelevated`官方说明有更弱网络隔离且不支持拒读路径，不能当多租户生产隔离已充分。[Windows执行与配置依据](https://learn.chatgpt.com/docs/windows/windows-sandbox)。

实例不能读开发者桌面、全局Skill/插件、SSH目录、其他订单、真实支付私钥或整桶。核心Skill只读，制作输出限本实例，复核输入只读且结果经网关回传。实例是同单进程组：制作与两个复核分别使用受限子进程/角色目录与权限，复核只能读取封存包，不能读取生产草稿、对话或凭证；不同thread_id加同进程全目录可读不满足此要求。记录每个run的进程/身份/目录引用，并将隔离证据绑定报告。

运行时认证/配置存储为实例或服务专用路径，由启动适配器传入，不能修改开发者当前会话的全局环境或登录配置。内置shell/命令入口也须在锁定构建和OS策略层被禁用，不能仅从MCP列表移除；尤其不使用绕过线程沙箱的`thread/shellCommand`。无法证明这些边界的构建不准入。

## 3. 生命周期与回收目标

`REQUESTED → PREPARING → READY → ACTIVE → DRAINING → RELEASING → RELEASED`。申请到活动中的任何失败可转DRAINING；释放失败转CLEANUP_FAILED，允许清理器幂等重试到RELEASING。已交付订单允许实例仍在RELEASING，两个状态分别展示和监控；不能用DELIVERED假称回收已完成。

| 配置 | 初始设计值 | 说明 |
| --- | --- | --- |
| 终态后开始回收 | 立即写outbox，目标60秒内领取 | 交付/失败/取消均触发 |
| 停止新动作后宽限 | 30秒 | 尝试interrupt并收尾回执，超时终止受控进程树 |
| 正常完成回收 | 目标5分钟内 | 需实际进程/目录/凭证检查，不是定时器一到就标成功 |
| 孤儿扫描 | 每60秒 | 核对lease/fencing_token和心跳，不能仅凭进程名字杀进程 |
| 硬告警 | 终态后10分钟仍未回收 | 隔离故障身份/工作区，暂停该槽位接新单 |

这些是待G0容量/异常测试的运行目标，不修改已有制作截止，不当成已验证SLO。等待供应商期间退出属于SUSPEND检查点，不意味着已取消远端任务。

## 4. 释放顺序与回执

1. 交付事务已提交完整manifest、文件校验、双复核与检测版本，同时写`ReleaseRequested`。失败/取消事务写相应补偿与同类释放事件。
2. 管理器按实例ID和执行代次领取，封禁该实例的新工具动作，撤销短期网关能力；已在途动作仍由独立意图/回执表对账。
3. 请求`turn/interrupt`并等待有限宽限，结束本实例所有app-server、MCP桥接和媒体子进程，关闭句柄及连接。只操作已登记的本实例进程树。
4. 对本地持久thread按锁定协议删除或清理专用状态目录，删除临时媒体/会话缓存/凭证；先核实检查点和交付文件已在持久域，再删除规范化根内路径。禁止跨订单批量通配删除。
5. 核实无活动进程/能力/临时文件，持久记录`cleanup_receipt`：原因、代次、时间、进程退出证据、目录清理结果、能力撤销和未决外部任务引用。全部必需项通过才RELEASED，否则CLEANUP_FAILED并重试/告警。

管理接口的主动释放只允许终态核对、已持久化且停止新动作的SUSPEND或孤儿恢复；携带预期执行代次与审计工单。不允许普通管理查询触发在制作中删除目录，也不因释放请求直接改履约/资金状态。

官方`thread/archive`只是归档；`thread/unsubscribe`存在空闲宽限，不能作为即时释放。`thread/delete`处理运行时持久线程数据，仍不等于供应商远端数据删除。单单的进程终止/本地清理结果不应宣称模型供应商已删除请求记录。[官方线程生命周期](https://learn.chatgpt.com/docs/app-server)。

## 5. 持久域与实例域

| 数据 | 交付后释放时处理 |
| --- | --- |
| 进程、角色上下文、临时素材、临时凭证 | 立即回收并核验 |
| 已交付图片/视频/文案、可领取索引 | 默认7天，短链5分钟；不等用户逐项保存才释放实例 |
| 付费原图、档案、商品锁与必要参考 | 原7天隐私周期；修改/纠错使用授权的新实例 |
| 未付原图与档案 | 原24小时，报价进程不常驻 |
| 订单/资金/最小质量及清理证据 | 根据单独的法定/业务保留策略；禁止默认长期留原始会话/照片 |
| 供应商UNKNOWN/未结算成本 | 独立对账器继续查原任务，不能因回收而丢弃或重购 |

交付内容过期、用户删除与实例回收是三件事。用户主动隐私删除依现有流程撤销授权并清除适用媒体；审计与必要资金记录脱敏最小化，具体保留期限需上线前确定。售后新实例只读仍在授权周期内的必要快照，禁止恢复旧凭证或重用旧执行代次。
