# 07 · 社区与内容发布开发

## 1. 内容合同

官方与社区使用同一Preset/Component/ExecutionVariant版本体系。官方保底10套、至少14执行变体；社区不是用户任意上传代码执行的市场。作者改受控文案风格、镜头节奏、版式、已获准资源和效果组合，平台编译为可执行计划。

组件注册表定义type/version、允许字段、边界、支持路线、资源需求和输出槽位。所有声明式输入做结构与语义校验，禁止脚本、shell、任意URL下载、模型端点、价格、密钥、任意JSON Schema和生成命令。显示名称可以扩展，执行类型只引用平台注册ID。

Recipe来源、作者和资源有独立版本；391条来源配方是研究库存，不能一键上架。来源叙事类型、主线与Look的归一使用显式映射，未知项进入待处理，不默认覆盖成UGC或跳过compose。

## 2. 草稿到可售版本

1. 作者建草稿，编辑带expected_revision；后台校验兼容性、完整槽位、整数帧时长和事实边界。
2. 用作者本人或单独授权商品生成私有样例；消耗独立样例预算，不能取买家照片补库。
3. 申请发布，提交来源/资源许可、样例授权、fork政策、变体能力/质量/成本证据。
4. 校验、内容/权利/效果审核，失败返回可改项；审核人员的发布动作留审计。
5. 生成不可变发布版本。只有能力、价格、资源、样例和准入都通过才可售；发布文本本身不自动准入。

Publication状态与商业准入分开：草稿/审核通过不等于sale_enabled。机器契约保存review_status/admission_status/sale_enabled及reason_codes；模型/费率未知保持null与false。准入与停售信息不能由作者自报。

普通订单全自动；运营对预设发布、权利申诉和付款未知异常的审核不等于逐单人工剪辑。若人工代做样片/订单，独立标记并排除自动成功统计。

## 3. 收藏、派生与版本

收藏只引用公共preset_id，用户下单时固定具体发布版本/变体；作者更新不改变旧单。派生保留parent_version、组件版本、原作者/来源、许可及修改记录。父许可不允许派生或资源不可转授权时拒绝，不因复制JSON而获得使用权。

旧版本可停止新售，已售订单依原快照处理。资源紧急撤销导致旧单无法执行时进入影响评估/通知/合同处置，不偷偷替换声音、人物或模型。不可变历史保留审计；停止公开不等于删除交易凭据。

## 4. 数据隔离与公开样例

买家资产、Profile、IdentityLock、Plan内部字段、订单、失败日志及供应商信息只归服务端授权主体；作者只能查看自己的草稿/样例和公共发布结果。基础统计只提供聚合数据，须达到合理分组阈值，不能按单推断买家隐私。

公开样例是独立对象：独立授权记录、脱敏/EXIF清理、审核、可见性与撤回入口。不能将私有商品对象简单改ACL为public，也不能永久缓存买家短链作为社区封面。授权撤回先停止分发，再清理受控CDN/索引；既有外部下载无法承诺全网删除。

当前独立副本实现见[公开样例专项](../实施/社区公开样例独立持有与撤回-v1.0.md)。作者单独确认最多30天公开，批准后排入PUBLIC_SAMPLE_PREPARE，完整复制并核验后才可发布；源SAMPLE始终PRIVATE。`authorized_samples`与独立对象登记冻结来源、摘要和截止；短链每次核对当前授权。本人可通过发布记录撤回，结束副本并停止新售；自然私有到期保留独立公开权，主动商品/账户删除同时撤回。签名日志与恢复重放必须保留该区别，不能事后补写来源。真实OSS/CDN、生成式/有声/自带资源制作及生产准入未验。

## 5. 举报与申诉

支持来源侵权、误导效果、敏感内容、商品失真和其他明确分类；举报最小收集证据，附件私有。普通用户可查本人举报/申诉，不可见其他举报人身份。运营审核权限、证据访问和决定分别审计，避免“能审模板就能读全部订单”。

停售控制绑定preset/variant/model/resource版本，可精确到受影响内容。新报价/建单再次检查可售；旧快照履约按风险与原合同专门处理，不只隐藏列表了事。

## 6. 完成定义

用两作者、两买家验证创建→样例→提交→审核→上架→收藏/派生→实际购买→举报→停售/申诉。必须包含越权尝试、许可不足、未知组件、任意URL/脚本注入、并发改稿、原版本订单继续执行。作者收益分成/提现不作为P0依赖，也不凭空开通结算能力。
