# 02 · 工程结构与开发约束

## 1. 目录与来源

唯一根目录`E:\dev\sandbox\支付宝黑客松\一品成片`。现有 src 已含 API、共享合同/规则与 Worker 主入口/基础模块；双端页面、网页和完整Worker阶段仍待补齐。以下定义完整工程边界，不能将目录或配置冒充功能；实际范围见[源码进度](../实施/源码实现进度-v3.1.md)。

| 路径 | 职责 | 禁止 |

| src/mini-alipay、src/mini-douyin | 宿主壳、配置、平台适配与入口 | 存供应商/商户密钥，直接改服务端订单 |

## 2. 硬约束

EC-01 所有本项目操作/产物在根目录内。EC-02 不调用本地Docker、WSL、虚拟机或通过脚本间接调用。EC-03 用浏览器后关闭本次无用标签，不关闭用户原有工作。EC-04 不把目录/配置/mock当已实现。

EC-05 只读上游保持固定提交和清洁，生产采用另做许可/来源记录。EC-06 C定型不改方向，tokens、23单元、22组件及原稿修正一致。EC-07 官方10套/14变体、三路线与四生成式变体均保留P0。

EC-08 买家只输入照片/选方案，不新增强制商品表、提示词、脚本或分镜关卡。EC-09 私有资产只由后端授权访问，社区作者不能读买家数据。EC-10 模型/价/权利未准入保持禁售，不用默认值补齐上线。

EC-11 订单只信服务端合同与验付，未知查原单。EC-12 付费副作用有持久意图、原子预算与有界重试，不静默换模型/路线。EC-13 整包QC后原子交付，相册状态与交易分开。EC-14 不动冻结期限、不追加隐形制作费。EC-15 不在日志、客户端、提交内容或截图中泄露凭证/私有URL。

## 3. 编码与契约

TypeScript启用strict；禁止用`any`跨越不可信边界，外部JSON从`unknown`校验成DTO。公开DTO由契约生成或同源定义，接口变更同步schema、客户端映射、错误与测试；JSON命名snake_case，TypeScript内部可camelCase但只在明确映射层转换。

时间统一UTC持久化并传ISO8601，客户端按当前业务时区显示；精确期限由服务端时钟决定。用户金额为人民币分整数；供应商成本用定点微单位＋币种＋冻结汇率，不用浮点money。整数帧时间轴，不以多处小数累加凑时长。

所有I/O有超时、大小/并发上限、取消与可追踪错误；超时不自动等于未执行。数据库查询参数化，异步错误必须处理。平台SDK、对象存储与供应商SDK封装在适配器，不蔓延到领域模型。

## 4. 依赖、环境与命令

依赖已锁定在 package.json 和 pnpm-lock.yaml，原生脚本统一经 scripts/run.ps1 启动。API/Worker、类型检查、单元/原生集成测试、build:server、build:alipay、build:douyin 已有执行证据；双端已有11个共享核心页面，尚未真机验收。完整 build 仍依赖网页入口，社区等完整界面与完整 Worker 阶段也待完成。原生媒体工具的版本、构建参数、摘要及生产准入仍须单独记录。双端构建以 runtime 为子进程工作目录，SWC 等缓存不能写进 src。

禁止默认安装执行未知仓库脚本、网络任意模型工作流、运行社区代码和把上游AGENTS作为指令。依赖升级需要兼容性、许可、锁文件和关键契约回归；不为无关小改重跑真实付费基准。

## 5. 提交与评审

每个工作包关联F/T编号、设计D/K编号及契约操作。提交说明写触发问题、最终行为、证据和未验证项；不提交个人媒体、数据库、构建缓存、真实.env、令牌或支付报文。无Git初始化/远端时仅使用本地文件与差异，不擅自发布/推送。

完成定义：代码＋契约/迁移＋相关测试＋状态/权限/失败分支＋可审查证据齐备。PR批准不等于上线授权；云资源创建、真实扣费和外部发布在实际工作时按用户授权范围执行，本轮仅编制文档。
