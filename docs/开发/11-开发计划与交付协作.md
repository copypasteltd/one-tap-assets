## 1. 角色与责任

| 责任角色 | 必须交付 |
| --- | --- |
| 产品/项目 | 范围、清单、售后与可见文案；未验证项责任人与取舍 |
| 技术负责人/后端 | 契约、事务、权限、版本/迁移、故障恢复与架构决策 |
| 小程序 | 两端宿主实验、C实现、权限/交易/保存/恢复与真机证据 |
| 生成/媒体 | 真实模型、参考/商品锁、三路线、后期/声音/QC和成本 |
| 设计/内容 | 未绘单元细化、10套/14变体、样例与资源授权 |
| 测试/运维 | 独立数据集、并发/故障注入、容量/备份/回滚、发布证据 |

角色可由同一人承担，关键评审/标注仍需避免用生成模型自评代替独立判定。当前未指定人员，不以角色表声称团队已到位。

## 3. 一张开发任务单的内容

每个可领取任务写目标/触发场景、F/T编号、D/K页面组件、OpenAPI operationId、schema/实体/状态边、前置与交付、异常/权限/并发、验证方法、证据位置、未验证依赖。任务粒度以能合并和回归为准，不按“写一个页面”切断交易/恢复责任。

例：相册恢复任务关联F11/F22/F23、D11/D12/D13、K11/K13/K20，交付平台Album适配、save-session/receipt契约、队列恢复与四组真机证据；明确UNKNOWN需要核对和确认成功项不自动重存。

## 4. 完成定义与评审

提交先过必要静态/契约/测试检查，再审权限与事务、冻结合同/预算/截止、失败/恢复、C视觉/文案和隐私。涉及数据库必须附迁移/兼容/恢复方法；模型/资源必须附准入与许可；双端变化必须附适用真机证据或清楚标NOT_RUN。

状态采用DESIGN_NOT_IMPLEMENTED→IN_PROGRESS→IMPLEMENTED_NOT_VERIFIED→VERIFIED，并为发布另设RELEASED。某一个包通过不批量改其他包状态；配置检查不把产品验收改PASS。完成证据不足不能用“已接接口”替代。

跨层契约改动同一次变更更新OpenAPI、schema、调用方、状态机、文档及相关测试。不可兼容变更使用新合同/适配窗口；已售订单保持原快照。原设计C v1.0留存不改，视觉变更另建受控版本与决策。

## 5. 估算与关键风险

当前不承诺总周数：旧69—99人日/两人8—12周仅v2.1历史。G0之后按每包研发/实验/标注/真机/许可审核/外部等待列人日、并行条件和不确定区间。至少单列原生中文声音/连续多镜能力、商品一致率、模型成本波动、双端交易准入和AGPL采用边界。

每次迭代展示实际可运行纵向行为、失败恢复与成本，而不是累计页面数/配方数。未准入部分保持禁售并公开内部阻塞项；内部阶段交付的标签不能冒称完整v3上线。
