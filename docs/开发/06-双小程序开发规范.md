# 06 · 双小程序开发规范

## 1. 客户端责任与共享边界

支付宝、抖音分别构建、配置、审核和验收，共用Taro/React业务页面与C主题；跨端不是同一个安装包。优先验证登录、选图、直传、支付、视频播放、逐文件保存和离页恢复，实验未过不承诺兼容。网页Plus为P1，不承担P0小程序缺失的步骤。

`src/shared/platform/`定义Session、PhotoInput、Upload、Payment、Media、Album、Storage、Navigation适配接口；两个宿主目录各自实现。页面只调用接口，不散落`my/tt/window`判断。业务DTO、错误码、保存队列和页面状态共用；域名、胶囊、安全区、隐私提示、支付报文与权限跳转分别适配。

平台配置和SDK版本在G0实验后固定。不同宿主有不同的允许API、类目、商户/交易和审核要求，不能依据Taro能编译便认定业务获准；能力失败时给明确解释和原单恢复入口，不自动引导跨渠道网页付款。

## 2. 路径与页面

三个主入口为拍照制作、方案社区、我的素材；D01—D23与K01—K22以[C设计基线](../设计/定型/C-柚子创作社-v1.0/README.md)为准。路由参数只传不敏感资源ID/版本，进入页面重新校验会话和服务端权益。令牌、手机号、照片地址、支付票据不进入路由或分享参数。

主流程：D01/D02拍3—5张或从相册选择→D03上传/识别摘要→D04/D05选方案及效果→D07确认清单报价→D08宿主付款与后端查单→D09云端制作→D11/D12查看→D13保存。D06纠错可选，不强制确认识别表。D10汇总作品与在途订单，D14处理原单/退款，D15提供异常支持。

## 3. 页面状态与恢复

页面使用显式状态：初始、加载、可交互、空、可恢复错误、阻断、终态；不能只设`loading`和`success`两个布尔值。分析/计划/订单/任务/相册分别读取对应服务端或本地状态，不从一个页面动画推断另一个业务结果。

登录过期先保留非敏感草稿ID，重新取得本宿主会话后查询原资源。持久化只放恢复ID、有限草稿选择、媒体保存记录和必要会话信息；是否保存token依宿主安全能力与过期策略，不能写入调试日志。用户换号后清理前账号缓存，不能复用旧私有媒体。

回到前台查询未终结订单/任务；页面卸载取消计时器、轮询和临时监听，不取消已经付款的云端任务。轮询建议前台2秒起逐步退避到10秒，加抖动；遇429遵守Retry-After，后台停止轮询，网络恢复后先查询再续操作。实际频率在容量实验后固定。

制作进度来自已持久化阶段，等待中可显示阶段名/预计区间，不用匀速假百分比。ETA过时改为等待说明；超过合同截止由后端处置，客户端不能延时续命。

## 4. 输入、样例与确认

买家不填商品类目、材质、参数、提示词、镜头和模特表。拍照引导覆盖整体、侧面、细节，图数/可见特征不足时提示具体补拍；跨图冲突不能靠编造解决。多模态观察摘要用自然语言，未知保持未知。

上传按资产申请→宿主直传→服务端确认→绑定照片版本；失败仅续传对应项。设备压缩/旋转按统一策略，服务端仍验证真实内容、像素、大小和EXIF。不要把前端预览成功当文件已持久化。

输入接收3—5张JPG/PNG，单张≤10MB、总量≤50MB、短边≥640px、解码≤30MP；API明确按十进制MB定义字节上限。HEIC等仅在受支持转换并校验后接收，不能仅改后缀。分析用受控视觉副本，不把上传像素上限当模型参考上限。

方案卡显示作者、风格/节奏、可用效果和样例标识。官方/社区样片与“我的生成结果”必须区分；可选本人预览仍按每日5个新预览额度执行，额度不影响已购任务生成与领取。数量和规格读取所选变体合同，不把稿中4图/1视频写死。

收费前展示总价、完整清单、原生/交付规格、声音形式、预计区间、期限和售后。未准入/未定价不得出现可支付动作，不能以空价格显示为免费。

## 5. 付款与相册

点击付款沿原单取得宿主付款动作，防重复点击只改善体验；真正防重由后端幂等负责。宿主成功回调只触发查单，后端确认后显示已付；取消/未知/回跳按原order_id查询，不换键新建支付。两端支付配置和凭证隔离。

相册队列逐文件执行并存本安装记录：PENDING→DOWNLOADING→SAVING→SAVED/FAILED/UNKNOWN。每次短链失效先重新授权，不重新制作或扣费。已明确成功项续存时跳过，失败可重试；宿主无回调的UNKNOWN提示核对相册后选择，不能保证自动去重。

相册拒权解释用途并允许查看原作品；只有明确用户动作才打开权限设置。下载成功不等于写相册成功，服务端收到回执也不能替用户确认手机中存在文件。输出过期/退款等由后端拒绝新短链；已保存到手机的内容不能远程撤回。

## 6. 视觉与真机门禁

继续C果橙/奶白/深绿墨及照片印样语言；tokens是实现依据。橙底主按钮使用深色墨字，不能照抄原稿的低对比白字。375逻辑宽作参考，字号/间距/44触达/安全区按定型；胶囊与系统导航实测，视频以9:16完整可见。一个状态只设一个主要动作。

真机至少覆盖两宿主×iOS/Android四组，记录宿主/系统/机型/SDK版本、截图和结果。验证断网/弱网、拒权、离页/杀进程、token失效、大图、短链过期、付款未知、部分保存和声音播放。设计23单元不等于23页高保真已完成；现只有3页参照，其余需实现与截图核验。

## v1.1 Codex修订

复用C设计的整理信息/制作/后期/检查素材进度与完整领取页面；不增加聊天、模型参数、Skill选择或逐阶段审批。后台释放不影响7天领取，保存失败只续存，新售后实例不额外扣初始化费。

详见[Codex服务专项](14-Codex内核与分阶段编排.md)及[实施验证](18-Codex接入验证与实施计划.md)。

当前实现为两端各17个页面，新增6个社区页面复用C主题；目录、订单与收藏按服务端游标翻页，私有证明上传沿原批次恢复，离页/换号丢弃旧私有响应。完整作者样例生产、发布申请/许可、纠错/修改和真机仍待完成，详见[社区接入](../实施/社区界面与作者工作台接入-v1.0.md)。这里的构建/API证据不改变本文件设备验收要求。
