# 09 · 测试策略与验收门禁

本轮仅核验文档、schema、引用、状态图和追踪关系；以下产品测试均NOT_RUN。mock通过、配置合法和文档齐全不能证明真实模型、支付或小程序能力。

## 1. 分层测试

| 层级 | 目的与必要场景 | 运行边界 |
| --- | --- | --- |
| 纯规则 | 帧计算、证据引用、状态边、预算/退款整数、版本哈希 | 无网络，不逐行镜像实现 |
| 契约 | schema正负例、错误、分页、宿主DTO、幂等与版本冲突 | OpenAPI/Schema与实现双向校验 |
| 数据库集成 | 并发付费/退款/发布、复合外键、outbox、租约代次、迁移 | Windows原生或明确隔离的远程测试库；禁容器 |
| Worker/媒体 | 三路线、实际compose、ffprobe、原声/字幕、畸形媒体 | 原生受限进程，测试目录与对象前缀隔离 |
| 故障注入 | 响应丢失、杀进程、重复消息、迟到回调、存储故障 | 在每个副作用前后设置可复现断点 |
| 真实依赖 | 供应商实际提交/查询/声音/参考/成本、两通道交易 | 获准账户、预算与资产；不能用mock代替 |
| 四组真机 | 双宿主×iOS/Android完整操作与恢复 | 记录版本/机型、截图、真实相册与声音 |
| 发布基准 | 14变体全包、识别/高危独立集、质量/成本/耗时 | 失败包含在分母，人工代做单列 |

## 2. 必须复现的竞态与失败

- 同报价并发建单、同键不同body、一次付款重复通知20次，订单/权益/任务各只一次；晚到实付也能对账与退款。
- POST供应商已接受但响应丢失，Worker重启后UNKNOWN先查原意图；未确定不会再次购买，预算占用不丢。
- 两Worker竞争同一stage、租约到期旧Worker回写、outbox重复投递、主机重启；旧代次不能覆盖新结果。
- 两阶段并发预留预算，重试/修复碰硬截止；总成本不超冻结上限、截止不延长，失败不缩水交付。
- QC通过与取消/退款同时发生、迟到结果、交付写入中断；manifest最多一份有效完整版本，终止单不再公开。
- 跨租户/跨app/社区作者枚举assets、profiles、plans、orders、download、tickets；不得泄露内容/存在性。
- 私有URL外泄、到期续链、删除与恢复备份、图片炸弹/路径/SSRF、模板脚本/提示注入；在实际边界阻断。
- 手机杀进程/拒绝相册/短链过期/部分成功/无回调UNKNOWN；只续明确失败项，不承诺宿主无法提供的自动去重。

这些是风险测试清单，不是本轮已写/已执行的应用测试。每项关联F/T编号、触发步骤、预期不变量、证据与失败诊断，不能只比较页面截图或断言函数被调用。

## 3. 媒体和模型门槛

官方14变体逐项至少30次整包，共至少420次，按商品/图质量/风格/人物声音分层；不能30次只有同一个商品。自动完整交付目标≥90%，每次记录成功、阻断、修复、退款、成本及p50/p95/最大耗时。

识别独立100组验证观察/OCR/未知/冲突；高危独立100组负例，包装、数量、结构、标识、事实/声音等关键缺陷不得误放；正例误拒目标≤10%。阈值/抽帧方法/标注集与版本在G0冻结，与生成模型自评独立。不得用开发调参样本冒充独立集。

PNG槽位尺寸/数量、竖片1080×1920/30fps/H.264/yuv420p、合同±1帧、原生/交付区别、中文原声与实际字幕/ducking均实测。声画是否可懂/商品是否一致仍需标注听辨，不能单靠ffprobe。中途修复也计耗时和成本；超时单不能从统计移除。

## 4. 发布门禁

G0通过实际能力/权利/成本/宿主实验与工期重估；G1通过从照片到完整manifest的真实纵向执行；G2通过交易/故障恢复与四组真机；G3通过官方内容/社区、420整包及独立评测；G4通过52项P0及适用共用验收、渠道审核/容量/恢复。

任何门禁FAIL或NOT_RUN均不能标为正式完整可用。可做明确标识的小范围内部验证，但不得把未获准端、单路线、3套预设或样片展示等同于完整P0交付。P1/P2另行计划，不能拿它们替换生成式P0。

## 5. 证据与回归策略

报告记录提交/构建/配置/模型/资源/数据集版本、环境、执行人/时间、成本、失败数、trace与脱敏证据位置。应用证据放`tests/`和受控runtime/对象前缀，公共文档只留索引与汇总，不能提交买家原图/支付报文。

每次变更运行相关纯规则/契约与必要集成；变更状态/交易/模型/媒体/授权时增加对应风险回归。已经通过且没有新变化/疑点的检查不无端重复；真实付费全量基准仅在准入或相关变化需要时执行。新测试必须检验用户行为或不变量，避免为文档改字添加无效测试。
