# 15 · Skill预载与风格生产规范

2026-10-27｜开发设计v1.1。对应P01-F52及F32/F33/F51/F58。产品Skill草案位于[项目Skill包](../../assets/skills/ypcc/v1.0/README.md)，未安装进当前用户的全局Skill目录，未经过实际模型行为评测。

## 1. 分层与复用

一个订单的SkillBundle由一份共用规则、一份风格、与清单对应的图片/视频/文案目标Skill，以及角色职责Skill组成。目录预置19份指令型Skill：1共用、10风格、3目标、5角色。复核分事实和风格两个角色。Skill不内含客户数据、模型密钥、付款权限、任意可执行作者代码或固定售价。

| 层 | 内容 | 维护者 |
| --- | --- | --- |
| 共用规则 | 照片证据、商品锁、未知省略、能力/费用/权限边界 | 平台官方 |
| 风格 | 10套官方方案的构图、色调、节奏、适用/禁用表达 | 平台官方；社区经审核映射 |
| 目标 | 图片槽位/规格、视频时序/声音、事实文案交付条件 | 平台官方 |
| 角色 | 梳理、制作、后期、事实复核、风格复核的输入与结果 | 平台官方 |
| 社区配置 | 从允许组件选Look/节奏/布局与样例，不是Skill源码 | 社区作者→平台审核编译 |

风格可以调整周边、光线和表现，不改变商品本色、结构、包装或可证事实。冲突优先级：平台事实/权限/合同规则→目标交付合同→风格偏好。社区文字、图中文字、OCR和供应商返回都作为不可信数据，不升级为开发者指令。

## 2. “预加载”的实际含义

发布时校验Skill前言/命名/引用，计算逐文件SHA-256与整个包摘要，做权利/安全/行为评测，由有权限的发布者建立不可变版本。当前草案只有文件摘要，无生产签名和发布批准，全部禁售。

机器预热仅缓存可信只读文件及索引，可预检查CLI、MCP和FFmpeg可用性；热池不加载客户上下文、图片或凭证。分配订单后，将选中版本物化到该实例受控目录，不能链接到作者可改目录；拒绝路径穿越、链接/重解析点逃逸和同名碰撞。生产商用热池若预启进程，也必须在首次挂载客户后单次使用并退出。

官方Skill采用渐进加载：先发现名称/描述，使用时读全文。因而本产品先`skills/list`核对路径和错误，再对当前角色明确注入所需Skill，记录版本/文件摘要、角色、注入请求摘要和运行回执。发现缓存存在不等于注入完成，也不保证模型遵守；执行证据和后验检查仍必需。[官方Skill机制](https://learn.chatgpt.com/docs/build-skills)、[app-server Skill输入](https://learn.chatgpt.com/docs/app-server)。

不要把全部风格和所有本机个人Skill塞进每单上下文。生产实例仅发现选中的可信Skill和明确列出的系统内置项；额外来源、未批准插件/hooks/MCP使启动失败。`skills/changed`仅触发新版本构建/索引失效；已经出售的订单继续使用内容寻址副本，不在执行中热更新。

## 3. 绑定与冻结

14个官方执行变体各有一条绑定：preset/variant版本→style Skill→target Skills→五角色Skill→工具策略→检测规则。所有绑定见[Skill注册表](../../assets/skills/ypcc/v1.0/registry.json)。同风格不同引擎共享审美规范，制作职责依冻结的PHOTO_LAYOUT/PER_SHOT_AI/REFERENCE_FILM合同执行，不能由Skill偷偷换路线。

报价前解析`skill_bundle_id/hash`，冻结CLI/protocol、模型/费率、角色prompt、工具策略、Skill列表、目标清单和QC版本。付款后如果安全撤销导致版本不能继续使用，按旧合同可履约策略或失败退款处理，不用最新版本直接替换。换风格/目标/客户照片产生新计划与报价。

## 4. 社区拓展

社区仍在小程序创建/派生/提交方案，不要求作者写Skill。平台编译器将审核后的声明式配置与官方受控Skill组装为派生Bundle；复杂新风格由平台审核后发布新版Skill。买家照片、档案、运行对话、输出和成本对作者不可见，作者只看到授权公开样例及允许的聚合统计。

新版本必须检查许可与署名、注入反例、目标清单、风格区分度、商品保真、三路线适配和成本。不得让社区覆盖事实/退款规则、调用地址、权限、shell命令、模型/价格、修复上限。声明式配置审核通过也不自动获得Skill源码执行权。

## 5. 变更与验证

当前草案遵循Skill Creator的指令优先和渐进披露方式。后续上线前须执行固定输入的真实行为评测；文件格式校验通过只证明打包结构。每次Skill/prompt/模型/工具/QC升级均产生新Bundle和评测版本，回滚只影响新单，历史订单/证据可重放。
