# 客服素材纠错工作台

2026-10-30。将已有五阶段平台纠错执行链接入 `/ops/support`，客服从原工单核对商品资料、当前素材，提交更正并跟踪实际交付。沿用C「柚子创作社」果橙、奶白、深绿墨与薄荷色；冻结25份设计及原归档不变。58项需求/52项P0、三路线、10风格/至少14变体保持原范围。

## 使用流程

1. 使用独立客服令牌连接工作台，选择并接手原工单。需要 `support:read`、`support:write`、`support:repair`；素材读取和纠错仅限原接手客服。
2. 点击“核对原商品与素材”，读取冻结商品档案、当前完整交付清单和原售后截止。事实与待确认项分别显示；未知属性不提升为事实。
3. 点击“查看原图”读取真实私有PNG。服务端校验清单版本、本人商品、私有登记、有效期、摘要与尺寸；浏览器再校验实际字节摘要后展示。没有开放公共原图URL。
4. 选择更换封面、调整完整展示顺序或更正文案文件。确认实际变化，勾选核对声明，再点击“提交免费更正”。
5. 接受后显示原纠错编号。重新制作、QC、事实和风格独立复核、交付仍由原五阶段执行链完成；点击“刷新更正进展”查询。只有真实COMPLETED及新素材版本才显示交付成功。
6. 页面重载后重新连接并选择原处理中工单，可读取同一关联请求。用户在原订单领取最新素材；客服沟通状态单独处理。

| 编号 | 编辑能力 | 实际变化 |
| --- | --- | --- |
| 01 | COVER | 从当前完整包选择另一张已有图片；原媒体字节保持 |
| 02 | ALLOWED_ORDER | 对全部素材完整、不重复地重排列表展示顺序 |
| 03 | DISPLAY_TEXT | 以原商品事实为边界，写入新的实际UTF-8配套文案文件 |

文案文件不等于重绘图片或修改视频内字幕。当前仅支持冻结了售后能力、已付款交付且授权和时效仍有效的原图无声订单。原生成式、有声或不支持的合同保持明确阻断；不承诺重新生图、生视频或改口播。

## 请求、恢复与权限

当前77业务/32管理操作。新增两个只读管理接口，均要求 `support:repair`；请求体、结果和两端类型由v1.1契约同步生成。

| 编号 | 接口 | 用途 |
| --- | --- | --- |
| 01 | GET `/v1/internal/p01/support-tickets/{ticket_id}/repair-context` | 返回原档案、当前清单、关联纠错状态及可申请类型/阻断原因 |
| 02 | GET `/v1/internal/p01/support-tickets/{ticket_id}/repair-manifests/{manifest_revision}/images/{deliverable_id}` | 当前版本实际私有PNG，不跨版本、不跨素材 |
| 03 | POST `/v1/internal/p01/orders/{order_id}/platform-repairs` | 复用既有原工单/原版本/原证据绑定的五阶段执行入口 |

原工单版本和当前清单版本必须一致，一条工单只关联一个纠错；旧版本409要求刷新。读取不创建新售后额度，能申请不等于承诺交付，提交与各执行阶段仍重验原合同、实际余量和状态。全部纠错共享原售后费用、推理次数/角色次数、Token和工具上限；300秒、48小时窗口与原领取期取最早截止，UNKNOWN核对原任务，不重购也不续期。完成仍不占用户一次成功小修改。

客服回复与纠错共用一个页面内存写入门禁。结果未知时保留原请求完整内容、版本和幂等键，禁用新的写入；“继续确认原操作”分流重放原客服操作或原纠错。4xx明确拒绝后才释放该待确认操作；回执异常和网络中断保留原请求。令牌、图片、档案、文案草稿及待确认请求不落localStorage/sessionStorage；退出和换号撤销在途读取并清空。页面重载按服务端关联查询恢复状态，不重建原写入。隐私撤回后接口410，刷新移除私有工作区。
