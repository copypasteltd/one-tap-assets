# 订单取消、退款与原支付动作 / Order cancellation, refund and original payment

2026-10-30。补齐 P01-F08/F13/F16 的小程序自助处理和支付动作读取边界。需求 v3.1 全部58项/52项P0、官方10套/至少14变体、三条路线和C「柚子创作社」保持。按用户要求执行定向验证，不等待全面测试绿灯再交付源码候选。

## 1. 用户交互 / User interactions

| 编号 | 订单情况 | 页面动作与结果 |
| --- | --- | --- |
| 01 | 未开始制作，付款可继续 | 显示“继续原单付款”和“取消这笔订单”。操作前重新读取原订单；付款返回不提升为已付款。 |
| 02 | 付款 UNKNOWN | 只查询原单，不再次拉起支付。可明确取消制作；已发出的原交易继续对账，后续到账则走原单退款。 |
| 03 | 已付款、等待制作 | 显示“取消排队并申请退款”。确认后由既有服务端事务停止队列、撤销执行权限并建立唯一原路退款意图。 |
| 04 | 已付款，制作失败或已取消且无退款记录 | 显示“申请原路退款”。存在原退款编号后查询原退款，不再创建新的退款请求。 |
| 05 | 已开始制作或已交付 | 显示订单售后与问题反馈入口；不允许直接使用未执行取消或自动退款接口绕过既有政策。 |
| 06 | 退款进度 | 分别呈现已受理、处理中、结果待确认、暂未完成、需要处理、原路退款已确认，以及原金额和退款编号。只有REFUNDED显示到账确认。 |
| 07 | 用户放弃确认 | 保留订单；不发出取消或退款请求。操作失败仍查询原单，以服务端状态恢复。 |

取消的是制作和排队，不能声称取消了已经发出的宿主交易。退款按原商户、原支付渠道和原实付金额处理，不因客户端取消、返回或回调未知改写资金事实。拒绝相册权限不触发本功能，不重新制作或收费。

The shared order page restores the original order before each action. Cancellation and refund requests are explicit, while payment return remains unconfirmed until backend verification. Native payment, provider billing and actual refund arrival require separate live acceptance.

## 2. 服务端原支付动作 / Authoritative payment projection

`getOrCreatePaymentAction`保留现有公开契约和原编号；当前实现读取既有付款记录，不创建供应商交易。返回可调用宿主支付的动作之前，在原订单行锁内重新核验本人、原应用、原平台身份、当前履约/付款/退款状态、媒体撤销、付款窗口、动作到期和支付开关。

| 编号 | 边界 | 行为 |
| --- | --- | --- |
| 01 | 旧幂等回执 | 与输入资格检查相同，仅对这一纯读取投影重新执行当前检查；原响应仍保存，不改写既有资金意图或其他变更接口的幂等行为。 |
| 02 | 取消/已付款/开始制作/退款/过期/UNKNOWN/支付关闭 | 仅返回`QUERY_ORIGINAL_ORDER`；不继续返回原调用payload，不重新购买交易。 |
| 03 | 账户/应用/宿主身份不匹配 | 拒绝当前请求，不将原交易改路由至另一个小程序或账户。 |
| 04 | 原付款记录 | 不修改原记录的UNKNOWN/金额/原动作，不把关闭开关等同于交易取消。已有对账器继续按原交易处理必要资金事实。 |
| 05 | 取消后才确认付款 | 原有`confirmPayment`核验金额、买家、应用、渠道和商户；记录一次付款事实、一次原路退款，不启动新制作或重建快照。 |

该重验不放宽生产准入；全部官方方案仍禁售，原预算、原截止、修复/售后保留、调用次数、独立核验、UNKNOWN及真实账单均不变。已经交给宿主的旧动作无法由此远程撤回，迟到付款必须继续原单对账和退款。

## 3. 客户端状态与恢复 / Client recovery

所有操作先读取当前原订单；支付动作另校验原订单ID/渠道/状态/到期。取消、退款和支付动作分别使用由原订单与固定请求内容确定的幂等键，不使用新报价、新订单或随机nonce解决断网。

取消回执丢失后，若查询显示已取消，直接使用该结果；退款回执丢失后，若原退款ID已存在，直接查询原退款。迟到的另一账户回调不能写入当前页面的处理结果。这里只投影资金状态，不从宿主“返回”推断支付成功，不从“申请受理”推断退款到账。
