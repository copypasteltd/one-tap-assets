# 运营看板与窗口一致统计 v1.0

本增补落实 P01-F14、F17、F50 的履约运营部分。支付宝和抖音小程序仍是买家主入口；独立运营人员可在 `/ops/metrics` 查看付款、首版交付、已结算订单费用及待处理事项。看板不参与日常制作推进，不代替网页 Plus，也不开放买家素材访问权。

[后端统计](../../src/api/modules/metrics.ts) · [管理域接入](../../src/api/routes/management.ts) · [客户端](../../src/shared/client/metrics.ts) · [界面](../../src/preview/metrics-main.tsx) · [当前准确证据](../verification/metrics-dashboard-source.json)。

## 1. 修正的问题

原 `/metrics/summary` 已在契约要求 `window_start` / `window_end`，但实现忽略它们，固定查询近30天订单；供应商待查、退款、超时和路线用时还混入全历史数据。交付数量没有同时约束付款事实与首版交付记录，可能把未付款的状态标记或重复交付当作成功。

当前实现使用同一条数据库语句完成全部汇总，采用一致的读取快照。原管理接口及响应字段保持；不新增业务或管理操作、数据库迁移、付费调用或销售权限。

## 2. 窗口与指标口径

窗口为 `[window_start, window_end)`：开始时间计入，结束时间不计入。请求使用原契约的 UTC 时间格式，缺失、重复、非法日期、倒序或单次超过90天均拒绝。单次最多90天是本页的有界查询限制；可分段查询更长期间。前端按设备时区输入，再转换为 UTC，并核对响应对应原窗口。

这些是窗口内创建记录在查询时的当前状态，**不是还原到窗口结束时的历史快照**。例如10月创建的订单在11月交付，11月再次查询10月批次时，交付数量会变化。

| 字段 | 实际口径 |
| --- | --- |
| `paid_orders` | 窗口内创建且当前 `CONFIRMED` 的订单数；不是独立付费用户数 |
| `delivered_orders` | 同一批订单中，已付款、当前 `DELIVERED` 且存在首版交付清单的订单数 |
| `automatic_pack_success_ratio` | 上述交付数 / 上述付款数；没有已付款订单时为 `null`，不是0%或100% |
| `cost_micro_total` | 这批订单累计已结算的 `spent_micro`，包括失败订单；不把预留费用当作已花费用 |
| `unknown_submissions` | 窗口内创建、当前仍为 `UNKNOWN` 的供应商请求数 |
| `refunds_pending` | 窗口内创建、当前为待请求/处理中/待确认的退款记录数 |
| `hard_deadline_failures` | 窗口内创建且已因硬截止失败的任务，按租户/范围/任务去重；多个阶段或重试不重复计数 |
| `route_p95_seconds` | 同批已付款首版交付，从原快照的 `fulfillable_at` 到首版实际交付时间的P95，向上取整到秒 |

三条路线分别统计，售后修订不增加首版交付数或覆盖首版耗时。缺失、已脱敏、非法或倒序的原时间信息不编成零秒，也不从订单 `updated_at` 猜测。当前使用已验证的原生 PostgreSQL 17，安全转换无效的历史时间字段。整数超出精确展示范围时拒绝返回，不能因 JavaScript 浮点舍入改变资金含义。

这里的费用**只包含订单账本**，不包含平台免费识别、SAMPLE、免费尝试和其他平台费用。该比例也不表示独立模型语义质量已通过。测试/人工/真实客户流量尚未独立分群，不能拿本页证明赛事付费用户、社区有效复用或完整自助成功率。

## 3. 交互与视觉

独立运营登录 → 选择近1/7/30天或自定义起止时间 → 读取统计 → 查看付款与首版交付、异常、订单费用及路线用时 → 按需前往客服工作台 → 断开连接。

- 页面采用方案 C 的果橙 `#FF7948`、奶白 `#FFFAEE`、深绿墨 `#263B32` 和薄荷 `#CFE9D6`。共用原固定字体，数据用可比较的数字排版；不修改冻结设计原件。
- 首屏只显示连接表单，连接前不展示私人统计。运营访问令牌清空输入后只在当前连接内存中保留，不进入Cookie、localStorage、sessionStorage、URL或录制日志。
- 改变窗口先清除原统计；读取失败显示重试入口，不把旧窗口的数字继续画在新窗口下，也不把失败显示为0。
- 新查询、断开或页面离开使旧响应失效；断开清除令牌和聚合数据。客户端只请求固定同源只读地址，禁用重定向和Cookie。
- 空窗口显示真实零计数、未知比例和“暂无完整记录”；桌面和窄屏均可操作，有键盘焦点与清晰的状态说明。

客服与审核工作台均增加运营看板入口；链接本身不赋予统计权限。

## 4. 身份、权限与审计

沿用 `GET /v1/internal/p01/metrics/summary` 和独立的 `metrics:read` 权限。买家会话不能用于此接口；只有其他管理权限也不够。每次成功读取追加 `OPERATIONAL_SUMMARY_READ` 审计，仅保留操作者、窗口摘要和请求跟踪，不带商品内容、订单/用户/租户列表、供应商原报文或下载地址。

响应及页面资源禁用缓存，静态入口只提供登录壳。统计查询不修改订单、预算、供应商任务、退款状态、交付清单或销售开关。UNKNOWN 继续按原恢复链路核对，点击读取不会购买或重试制作。

## 5. 使用与复录

先按照[启动文档](../delivery/README.md)准备原生依赖和私有环境。在私有 `MANAGEMENT_TOKENS_JSON` 中给运营身份配置令牌的 SHA-256 与 `metrics:read`，不提交实际令牌。

```powershell
pnpm delivery:build --skip-mini
$env:YPCC_BUILD_ROOT = (Get-Content docs/delivery/current.json -Raw | ConvertFrom-Json).build_root
pnpm local:start
```

在服务自己的地址打开 `/ops/metrics`。源码包解压后当前可用产物位于 `runtime/build`，同样由原生 API 服务提供页面；单独运行静态网页服务器无法提供管理数据接口。示例命令不会自动配置真实模型、付款或开售。

复录使用 `pnpm docs:metrics`；先设置 `PLAYWRIGHT_BROWSERS_PATH` 为本项目的 `runtime/playwright-browsers`，以及项目内 TEMP/TMP。该脚本建立独立原生数据库测试schema，以明确的合成付款/交付/费用和运营身份检查页面。录制后关闭自己创建的页面、浏览器、API与数据库连接；开发主库进程保留。
