# 原生声音文件验收与审查封存 v1.0

2026-10-29｜需求 v3.1、开发契约 v1.1、C 设计 v1.0 不变。

## 1. 交付范围

内部两条生成路线 `PER_SHOT_AI`、`REFERENCE_FILM` 在已有原生制作/一次整轨 ASR/字幕与许可配乐 POST 后，接入实际文件 QC 和私有审查包封存。策略为 `YPCC-QC-GENERATED-NATIVE-AUDIO-1.0.0`；完整证据版本为 `YPCC-NATIVE-AUDIO-QC-EVIDENCE-1`。

**English scope:** Both private generated ORDER routes now connect technical file QC after native production, original settled ASR and POST. QC independently rebuilds the frozen mix, compares actual encoded audio and seals complete stereo source/final WAV, original transcript, actual subtitle script and QC JSON. It does not perform independent listening or final semantic approval. Public audio quotes/orders and delivery remain closed.

文件检查只产生 `SEALED`、`deterministic_pass=true`、`evidence_complete=true`、`reports=[]` 和 `publication_decision=PENDING`。声音报告保留 `semantic_review=PENDING`、`independent_listening=REQUIRED`。这些标记不授予交付权，不表示转写文字确实被说出、口型一致、商品事实正确或风格合格。

独立听音服务尚未接通。最终事实/风格角色、复核报告身份入口和交付入口均以 `INDEPENDENT_AUDIO_REVIEW_REQUIRED` 阻断。即使人工插入后续阶段、持有原审查包或准备图像报告，也不能绕过。公开报价和创建订单继续 `NATIVE_AUDIO_NOT_ADMITTED`；全部官方方案 `sale_enabled=false`。

```mermaid
flowchart LR
  Source[原生制作整轨] --> ASR[一次原任务 ASR]
  ASR --> Post[字幕与许可配乐 POST]
  Post --> QC[实际文件 QC 与混音重算]
  QC --> Pack[私有 SEALED / PENDING]
  Pack -. 待接入 .-> Listen[独立听音]
  Listen -. 待验 .-> Review[最终事实与风格复核]
  Review -. 待接通 .-> Deliver[事务交付]
```

## 2. 用户逻辑与后台流程

用户继续在支付宝/抖音小程序拍照、由多模态识别商品、选择社区方案、确认成套规格，然后等待素材。用户不填写商品表格，也不配置声音模型、ASR、混音或验收参数。Plus 是 P1 深化编辑入口。本轮没有改动页面或增加用户操作。

| 编号 | 后台检查 | 实际依据 |
| --- | --- | --- |
| 01 | 原订单/声音合同 | 原快照 SHA、时间轴、人物/声音/视频模型、许可、字幕、字体、原预算和截止 |
| 02 | 制作与后期 | 原媒体操作及不同制作/后期运行身份；完整槽位、真实视频/图片/文案和原来源 |
| 03 | 原完整转写 | 只读原成功 ASR、原费用 SETTLED、原登记视频/PCM、原转写文件字节；不再购买 ASR |
| 04 | 实际整轨解码 | 原 ALAC 中间片和最终 AAC 重新解码为 48kHz/双声道/S16LE；核对原证明 SHA/样本数 |
| 05 | 独立混音计算 | 原 PCM 单位增益；从冻结许可资源取实际配乐，按原音量、压低和循环策略重新混合 |
| 06 | 编码比较 | 重建 PCM SHA 等于原后期混音证明；最终 AAC 与期望混音执行原相关性/SNR 检查 |
| 07 | 字幕证据 | 原字级转写、字体和四种冻结样式之一重新编译 ASS，核对原脚本 SHA；取实际视频帧 |
| 08 | 私有封存 | 保存完整音轨及文本证据，绑定原合同、全部视频槽位和不可变审查摘要；事务再核验 |

独立重算指 QC 不直接接受工具声称的“混音通过”；它仍使用同一登记的确定性混音实现，属于文件/信号检查，不是独立模型或人工听音。编码比较沿用相关性至少 0.98、SNR 至少 18dB 的内核规则，不允许因失败静默改配乐、削弱原声、换模型或重购识别。

## 3. 封存材料与读取

迁移 `024_native_audio_review_evidence.sql` 只扩展已有不可变 `review_evidence.kind`，没有新增业务 API、实体、付费工具或公开下载入口。五种新材料全部位于订单私有审查命名空间，登记到现有私有对象写入账本、到期和删除链路。

| kind | 实际内容 | 格式与绑定 |
| --- | --- | --- |
| `NATIVE_AUDIO` | 原完整制作双声道 PCM | 标准 44 字节头 WAV，48kHz、16-bit、2 声道，逐采样保留，不归一化、不取均值 |
| `FINAL_AUDIO` | 实际最终 AAC 解码的完整双声道 PCM | 同一完整时间轴的 WAV，绑定成片 SHA 与实际编码后 PCM SHA |
| `TRANSCRIPT` | 原 ASR 输出登记文件的精确字节 | 原 JSON，不把脚本或计划台词伪装成识别结果 |
| `CAPTION_SCRIPT` | 由原转写生成的实际 ASS | `text/x-ass`，绑定固定字体、样式和后期脚本 SHA |
| `AUDIO_QC` | 有界技术检测 JSON | 原快照/合同/制作/成片/ASR/PCM/混音/字幕/帧编号、四文件 SHA/长度/MIME，以及待听音边界 |

沿用原图片、文案、合同、每秒/镜头边界/场景变化视频帧。另加入每个字幕句和词的起点、中点、终点前 1ms 对应的实际 30fps 帧，排序去重；不超出完整时间轴。它提高字幕出现时点的可检查性，不是 OCR、语义对齐或口型验证。

`verifySealedEvidence` 先核对持久索引与每个实际文件 SHA，再深查唯一五类材料、规范视频/全部视频槽位、完整 WAV 头和 PCM、原转写/ASS、字幕帧集合与原合同。音轨缺失、摘要变化、正文被换、遗漏必须的字幕时点帧均拒绝。审查读取材料提供逻辑音频 ID/SHA/MIME 和原文本，不向模型暴露存储路径、签名 URL、凭证或其他订单。

## 4. 事务、费用、隐私和恢复

准备阶段可以进行原生 FFmpeg 文件处理；封存提交再次锁定有效媒体主人，重新核对原订单快照、资源许可、人物/声音绑定及实际许可配乐字节。制作文件、后期文件、原转写和新审查副本必须仍由本租户/主人/商品/订单登记，`STORED`、未要求删除且未过期；并重新读取实际媒体/证据 SHA。原未决费用、操作清单、制作/后期身份和原租约代次继续检查。准备后撤权或换文件必须使同一提交回滚，不能留下 QC PASS 或封存包。

QC 不发新的模型请求、ASR、许可采购或 Codex 推理；重放只读原成功转写与回执，原预算/售后预留/一次整轨额度和截止均不重置。本轮测试验证参考身份、制作、后期三个既有角色和一次 ASR 保持不变，不能由此推定最终听音、事实/风格角色及完整产线费用容量已通过。

私有音轨不进入公开 README、录制媒体或社区样例；删除沿用现有登记副本和逻辑脱敏，完整外部删除、真实 OSS/供应商副本及生产隐私仍待验。QC 临时目录退出时回收；取消和原截止继续向原生子进程传播。
