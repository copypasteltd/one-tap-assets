# 独立视觉复核与原子交付接入

2026-10-28｜需求 v3.1 / 开发契约 v1.1 / C 设计 v1.0。本文记录新增源码和验证边界，不改变三路线、14 变体或完整产品验收要求。

## 已接入的流程

原图无声路线现有 `PRODUCTION → POST → QC → REVIEW_FACTS → REVIEW_STYLE → DELIVER` 六阶段。前两阶段执行实际媒体工具，QC 封存实际文件，两名复核使用新的运行/会话/进程，最后由平台事务发布完整交付清单。Worker 已注册这些处理器；生成式、有声、预览、修改、样例和完整回收等阶段仍须继续开发。

主要源码：

| 文件 | 职责 |
| --- | --- |
| `src/worker/review/context.ts` | 读取当前成功 QC 的封存包，核对冻结原图和全部证据，准备实际文案、合同、画面及时间码 |
| `src/worker/codex/review-images.ts` | 限定本包原始 PNG、尺寸、字节、顺序、细节级别、上下文和视觉费用上界 |
| `src/worker/review/stage.ts` | 调度独立事实/风格角色，复用已完成报告恢复父阶段，推进审查状态 |

| `tests/integration/review-delivery.test.ts` | 合成角色通过实际 HTTPS/MCP、PostgreSQL 和原生媒体完成上述流程与故障验证 |

## 实际视觉与文本输入

复核输入包括冻结的 3–5 张原图、全部候选图片、按既定规则提取的视频画面、实际文案、冻结合同和时间码索引。输入从私有存储读取并校验 SHA-256，不能使用任意 URL、外部 file ID 或缩略图替代。

app-server 的每次审查请求使用明确的 `image` / `detail: original` 输入；私有 Responses 出口只接受与运行绑定完全一致的 `input_image` PNG 数据。每次请求必须保留全部有序画面及完整封存上下文。缺图、换图、降低细节、只发图片而省略合同/文案均在费用预留前拒绝。当前采用一次提交完整材料的方式；若材料超出已准入容量，不分批丢帧或改为文字自评。

`CodexAdmission.review_vision` 绑定视觉准入证据摘要、图片数量/字节/像素/总量限制和每张图片的认证 token 上界。推理预留由文本 UTF-8 保守上界、固定协议开销、图片上界和最大输出组成；不能将 Base64 字节数直接作为实际图片计费公式。真实上界须在 G0 用锁定模型、细节级别和协议认证；测试中的数字只用于合成回执验证。报价缺少视觉准入绑定时拒绝继续，不以文本准入覆盖视觉服务。生产前还须验证各售卖规格及输入容量与模型完整上下文相容。

官方能力依据：[app-server 输入协议](https://learn.chatgpt.com/docs/app-server)、[Responses 图片输入与用量说明](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses)。本项目字段同时按本机锁定协议导出核对；文档支持不等于本服务已通过真实模型验证。

## 报告与恢复

平台分配报告 ID、run/thread/process 和运行证据引用，复核角色只能填写结论、证据完整性及问题。报告必须绑定当前 tenant/order、packet、snapshot、output set 和 QC 版本。每个问题只能引用本包证据和有效时间码。

报告持久化还要求本角色确实执行证据读取工具，所有推理请求均已结算且含全部绑定画面/上下文，Skill 发现与加载摘要正确。生产报告须对应原生准入模式；合成隔离协议仅在 `APP_ENV=test` 接受。两个报告必须来自不同的新运行/会话/进程，且不复用制作身份。报告和运行证据的更新被数据库触发器拒绝。

父阶段接管时，已成功角色的不可变报告可重新验证并提交，不再创建付费角色。旧租约提交被拒绝。未决角色不盲目重开。`FAIL`、`INSUFFICIENT_EVIDENCE` 或任何未解决问题将包置为阻断，后续复核不会继续付费，发布不能推进。当前尚未实现最多一轮自动修复；后续门禁失败沿用已有 Worker 终止/补偿流程，真实退款仍需交易准入。

## 发布和下载

`DELIVER` 要求两份报告对应成功的父阶段，封存包通过且当前候选未变化，没有未结算调用或退款处置。发布前重新执行实际原图、完整成品与封存证据校验；提交事务再次读取实际字节和报告，并对资源许可加共享锁，防止许可撤销在发布检查中穿过。

同一事务保存完整 manifest、更新订单/任务、授权封存包、统一交付文件到期时间、撤销所有订单能力并写入幂等 `ReleaseRequested`。未齐全、旧材料、撤权、损坏、中断或超时均不产生部分交付。事务结束前再次检查执行代次、租约和绝对截止，使用墙上时钟而非事务开始时间；该检查失败时连同 manifest 一起回滚。

成品权益从交付时起保留 7 天，下载链接为 300 秒。下载以当前 manifest 和资产列摘要为准，实际取出文件后再次核对 SHA-256，并复查领取权限；支持范围下载，文案通过文本复制。路由参数上限与最大签名授权长度对齐，修复真实签名 URL 被默认参数长度限制返回 414 的问题。

释放事件与实际退出/删除证明分开。合成角色的本机清理回执不能证明生产原生隔离、独立回收或隐私删除已完成。

## 验证与剩余边界

专项 8 项使用一秒合成合同、真实 PNG/MP4、原生 Sharp/FFmpeg、原生 PostgreSQL、HTTPS 和 MCP。包含完整交付与下载、缺失文本/图片、篡改/低细节、伪造身份/证据、原结果接管、未结算费用、许可撤销、报告脱离成功阶段、提交前文件变化、访问撤销、最终租约回滚，以及 FAIL/证据不足阻断。该测试不等于官方 14 变体、真实商家图像或语义质量评测。

全量测试、构建和当前源码摘要以 [实现证据](../../assets/implementation/current.json) 为准。验证期间曾出现一次 Windows `ntdll.dll / 0xc0000374` 原生测试进程退出；该轮判定失败，之后专项复测通过。未据此声称根因修复或原生稳定性认证。

真实 Codex、受限 OS 身份/网络隔离器、真实视觉计费上界、独立回收与隐私删除、三路线/音频/社区完整执行、有限修复、420 次整包基准和四类真机仍未完成。当前保持禁售和生产准入关闭。
