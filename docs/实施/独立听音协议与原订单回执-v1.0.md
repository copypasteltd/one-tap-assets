# 独立听音协议与原订单回执 v1.0

2026-10-29｜需求 v3.1、开发契约 v1.1、C 设计 v1.0 保留。

## 1. 本轮范围

实现内部平台准备服务 `NativeListeningGateway`：读取已经完成文件 QC 的原订单审查包，将完整原声与完整成片双声道 WAV、全部封存画面和商品事实交给独立音频模型，保存原请求、原响应、逐段听音结果和原订单费用。维护进程可核对已保存的原响应。

它是后续最终复核的基础组件。**没有把它注册为买家 API 或 Codex 购买工具，也没有解除最终事实/风格报告、交付或公开有声订单的门禁。** 现有 `ReviewStageService`、报告身份与 `PublicationService` 继续返回 `INDEPENDENT_AUDIO_REVIEW_REQUIRED`；公开订单继续 `NATIVE_AUDIO_NOT_ADMITTED`，全部官方方案禁售。

**English scope:** A private platform service now submits both complete sealed stereo WAV tracks, every sealed visual image and original product facts to an independent audio-capable model. Original request/response bytes, typed observations and original-order accounting persist. Saved responses can reconcile after interruption without another purchase. This foundation is not yet called by the final Codex review stages and does not admit audio reports, delivery, public orders, real speech quality or production. Native fixtures use actual media and PostgreSQL with synthetic semantic/model/rights/usage/isolation responses; tones are never labeled Chinese speech.

## 2. 服务选择与输入协议

当前适配器针对 `qwen3.8-omni-flash` 的 Chat Completions 流式文本协议。官方文档支持混合音频/图像输入，并通过 `use_multichannel=true` 保留双声道理解；本地音频使用完整 Base64 Data URI，单文件编码必须小于 10 MB。请求包含末尾用量回执，思考 token 也属于输出费用。[阿里云官方协议](https://help.aliyun.com/en/model-studio/qwen-omni)。

模型名称不是准入证据。必须冻结实际模型、模型登记 ID、能力 SHA、费率版本、区域工作区 HTTPS 地址、精确出口主机、有效期、完整输入容量和费用上界，且由登记行的 `QC` 角色绑定。实际商用费率与能力测试不在仓库中伪造。

| 输入 | 约束 |
| --- | --- |
| 原声 | 唯一 `NATIVE_AUDIO`，与原文件 QC 封存 SHA 一致 |
| 成片音轨 | 唯一 `FINAL_AUDIO`，保留实际许可配乐/压低及编码结果 |
| 音频格式 | 完整 48 kHz / PCM16 / 双声道 WAV，原增益，不截取、不混单声道 |
| 时长 | 当前内联协议最多 900 帧 / 30 秒，超过能力拒绝；需求保留，不静默缩短 |
| 画面 | 全部原照片、实际输出图片与实际视频取帧，包含字幕时间点，不抽掉中间帧 |
| 事实 | 原商品档案、身份锁、字幕规格、许可配乐和实际帧时间信息 |
| 不作为听音输入 | 计划口播稿、ASR 文字和制作方自评分数；模型应根据实际音频独立判断 |

原请求先编译为确定字节并登记。全包超过原图片数、图片总字节、请求总字节或时长上限时直接拒绝，不能通过减图、裁音、换声道或降低已售规格绕过。

容量验收仍待完成：本轮小尺寸合成媒体不证明官方高分辨率全套画面、完整字幕时点及最长音轨能同时装入内联请求。每个拟销售变体都须验证完整输入容量；若超限，应另行设计、认证并冻结完整材料的传输协议与费用，而不是从现有包中删帧后继续。The current small synthetic fixtures do not certify full-resolution official variants; complete-input capacity remains an admission requirement.

## 3. 结果与证据不足

返回 `PASS`、`BLOCK` 或 `INSUFFICIENT`，两条音轨分别以实际毫秒时间码连续覆盖完整时长。每段声明 `SPEECH / MUSIC / SILENCE / OTHER / UNCERTAIN`；语音段提供实际听到的文字，听不清保留不确定。结束时间采用完整帧时长的毫秒上取整。

五项观察为原声保留、清晰度、音乐掩盖、实际字幕一致性和口播事实。问题必须引用本包的音轨与画面逻辑 ID、有效时间和说明。缺段、交叠、包外引用、缺失轨道、未知字段或不完整 `PASS` 被拒绝。存在问题或不确定段不能判 `PASS`。

这些结构检查只约束证据格式，不证明模型真的听对。最终事实和风格角色使用本单全新身份独立判断、读取全部原始视觉证据；原回执和完整观察已绑定两份角色输入、推理回执、工具读取证明及交付重验，见[最终双复核与事务交付](原生声音最终双复核与事务交付-v1.0.md)。公开销售和真实服务准入仍关闭。单个听音服务的五项观察不等于五个独立评审。

## 4. 原订单费用与恢复

`listening_contract` 是原冻结合同的可选扩展，执行快照增加可选 `listening_contract_hash`。历史合同不被补写为具备新能力；没有听音合同的订单继续拒绝。新内部合同按原预算保留最多两个整包听音意图，为原整包和一次有界修复留出上限，不提供额外钱包或重置原截止。

费用按冻结的音频输入、统一文字/图片输入及文字输出费率，以整数微单位向上取整；全部思考 token 纳入输出。必须有同一个原请求、同一模型的完整流、结束原因和原始 token 用量，且不超过认证上限。当前协议要求缓存 token 为零：出现无法按模态准确分摊的缓存用量时，费用保持 `UNKNOWN`，不得按免费或估计账单结算。真实缓存/账单核对能力是后续准入待办。

| 触发 | 持久处理 |
| --- | --- |
| 首次请求 | 原子预留原订单费用，唯一意图绑定租户/订单/审查包/阶段/模型/请求 SHA |
| 发送之前 | 保存原请求私有对象，再次检查原租约、完整证据字节、资源许可、模型和当前审查包，写不可变发送标记 |
| 成功响应 | 保存原 HTTP 状态、内容类型、精确响应字节及 SHA；按原费率结算，再保存严格验证的结果 |
| 语义结果无效 | 已知实际费用仍结算，结果失败且不重买 |
| 缺失/异常用量 | 原费用保持待核对，不能释放为零成本 |
| 明确不计费错误 | 仅按冻结的供应商状态清单释放原预留 |
| 网络中断/响应丢失 | 保留 `UNKNOWN` 和原发送标记；不再 POST |
| 原响应后来已落盘 | 维护扫描只恢复该原响应；停用新请求后仍可按原费率对账 |
| 撤权/删除/原截止到达 | 阻止返回可供后续使用的结果；已经发生的费用保留，不补发请求 |

该同步协议没有经过认证的原任务查询端点，因此 `UNKNOWN` 不会杜撰轮询接口。只有已登记保存的原响应可自动恢复；缺失的原响应和外部账单需要后续真实服务对账。响应存在时也必须先核对私有对象登记归属及字节，不能只信存储路径或 JSON 自报 SHA。

## 6. 内部接入与后续准入

平台准备、两个最终角色输入/推理/受控工具/不可变报告、有声媒体验证及事务交付已按[最终双复核与事务交付](原生声音最终双复核与事务交付-v1.0.md)接通。FACTS 复用唯一原请求，STYLE/推理/报告/发布路径只读重验；语义不足或原费用未决不得继续。新正向控制响应刻意伪造中文语义 PASS，用于检验授权绑定，不能证明提示音包含中文或模型听感准确。

## 7. 最终角色接入约束（内部已接通）

下表约束现已由源码和控制夹具消费，实际完整验证以最新实现索引为准；它不代表真实声音质量、生产隔离或商业准入。不能只把同步 `requireAudioReviewAdmission` 改成检查“存在听音合同”，更不能让听音请求的 `SUCCEEDED` 代替听音语义 `PASS`。

| 边界 | 必须实现的绑定 | 必须拒绝的情况 |
| --- | --- | --- |
| 平台准备 | 在原 `REVIEW_FACTS` 租约中复用唯一听音意图；`REVIEW_STYLE` 只读取同包原结果，不创建第二次购买 | UNKNOWN 未恢复、原费用未结算、语义 BLOCK/INSUFFICIENT、原包改变 |
| 听音读取 | 从原私有登记重新校验请求/响应实际字节、原模型/费率/预算、两轨及全部画面 SHA，输出逻辑 ID 和观察 | 裸 DB 的结果自报 SHA、仅存储路径、人工填入 PASS、撤权/删除/原截止到达 |
| Codex 材料 | 两个全新角色的 `review_input` 都包含原听音意图/请求/响应/结果摘要及完整观察；全部实际画面继续进入原视觉推理 | 只给 ASR、计划台词、摘要文字或缺失中间画面，输入范围超过原认证费用 |
| 推理与工具证明 | 原 `review_input` 摘要覆盖听音材料；推理回执与 `extract_review_evidence` 的持久结果明确证明读到相同听音版本 | 角色自行拼一个听音报告、换包复用旧推理、缺少工具读取证明 |
| 最终双报告 | 保持制作/后期/事实/风格身份独立；报告原绑定除包/输出 SHA 外，还通过持久角色输入证明同一听音结果 | 两角色复用线程/实例/进程，听音未 PASS 却双报告 PASS，素材变了仍沿用旧报告 |
| 事务交付 | 选择对应原生有声的媒体验证路径；在提交事务重验听音、双报告、实际源/成片/字幕/许可及费用，不调用生成/ASR/听音重新购买 | 使用无声媒体验证器放宽音轨要求、修复换源后沿用旧包、过期或退款中的交付 |

原后期内核的 `semantic_review=NOT_PERFORMED` 是其当时技术处理事实，后续独立审查通过也不得回写原制作/POST 文件或证明。应另行关联独立听音与双角色证据。对两个生成引擎分别验证完整私有交付、原意图恢复、提交中撤权和旧报告拒绝，并继续全量回归无声路线；公开有声报价、销售开关和商业准入仍须独立验收。
