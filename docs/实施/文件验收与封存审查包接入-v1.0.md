# 文件验收与封存审查包接入

2026-10-28｜需求 v3.1 / 开发契约 v1.1 / C 设计 v1.0。

本次实现原图无声路线的确定性 QC、实际帧证据和不可变审查包。它连接已有 PRODUCTION / POST 与后续独立复核的输入边界；不代表双复核、最终发布、完整释放或真实 Codex 已经接通。完整目标保持 58 项需求、三路线、10 套 / 至少 14 变体与双小程序。

## 固定字体与已售资源

原图排版全部文字改为 Sharp / Pango 使用明确的 Noto Sans SC 文件，取消 SVG 对系统字体的依赖，包括标题、说明、页码、英文装饰及 AI 标记。固定版本来自 Google Fonts 官方仓库的提交 `a85815a42757630ce188fdad368c2dfc444d4773`，字体、OFL、元数据和来源索引位于 `assets/resources/fonts/noto-sans-sc/`。未安装系统字体。

`font.ts`固定字体与许可 SHA-256，加载前核对实际字节，并读取完整 Unicode 字符映射。未覆盖字符拒绝渲染，不能静默退回宿主字体；溢出画布拒绝。字体检查不替代真实设备或最终文字可读性评测。

数据库种子登记 `resource_licenses`，不启售任何方案。报价将字体版本、许可 ID 和字节摘要冻结进原合同；制作和 QC 重新检查许可是否撤销、过期或变更。其他资源也必须有匹配的有效许可记录。资源和模型数组还需与已售合同一致，不从作者新版本读取。当前只实现这一字体的文件、许可登记和检查，其他字体、音乐、声音、生成资源及 CPU 成本准入仍待完善。

## 实际 QC

`src/worker/review/qc.ts`实现 `QualityControlService`；Worker 在 Codex 与制作开关均开启时注册 QC。只接受 `PHOTO_LAYOUT`、`speech_mode=NONE` 且冻结 `YPCC-QC-PHOTO-1.0.0` 的订单，不能用这套规则验收生成式或中文原声路线。

处理顺序为：

1. 验证订单、执行快照、原预算/截止、父租约和资源许可；未决付费请求等待原请求结算，不再次购买。
2. 读取已完成制作与后期检查点，重新验证角色持久结果、成功工具回执、完整槽位和制作来源。要求制作与后期拥有不同 run、thread 和进程引用。
3. 读取已售原图与全部原始/后期文件，重新核对实际 SHA、PNG 解码/尺寸、文案、视频实际编码/帧数和全流解码；不使用客户端当前档案代替已售版本。
4. 对视频生成实际时间码帧，对候选图片、文案和合同建立私有证据；没有语音的路线不能伪造音轨或转写报告。
5. 通过 `completeStage` 的租约与代次门禁，在同一事务写入审查包、证据索引、逐产物确定性决定和阶段检查点。

QC 的 `PASS`仅表示对应确定性检查已通过。包状态仍为 `SEALED`，报告为空，发布决定为 `PENDING`；不会创建交付 manifest 或把订单标记为已交付。

## 全片画面与时间码

`evidence.ts`使用原生 FFmpeg，选取每秒画面、首末帧、所有计划分镜边界及实际场景变化（scene > 0.25）；后两者补充固定采样。实际 PTS 换算为 30 fps 帧索引和毫秒，核对每个应有采样位置均存在。证据为实际输出 PNG，保留来源产物 ID、实际总帧数和采样策略版本。

当前容量为每个视频最多 900 张帧证据、整包最多 1000 项证据、帧缓冲累计 128 MB；超限明确拒绝，不通过减少采样冒称完整。采样仍不是逐帧语义核验，scene 阈值也不能保证发现所有视觉变化；后续独立视觉/声音复核与质量负例评测依然必需。长片与高信息量片的容量/磁盘/CPU 调度需要后续准入测试。

## 封存、恢复与证据读取

`packet.ts`遵循开发 17 的 `sha256-utf8-json-sortkeys-v1`：固定封存字段排序、UTF-8 紧凑 JSON；数组顺序不变。该 DTO 的封存字段只使用字符串、数组与对象，实现拒绝未定义的浮点数表示，并以独立 Python 向量验证 Unicode 键排序。执行快照继续使用原 RFC8785，两者不混用。

摘要绑定订单、快照、商品锁、Skill/QC 版本、原图、完整输出、证据和制作运行身份。可变状态、报告与发布决定不在摘要内。数据库迁移 `011_sealed_review_evidence.sql`禁止修改封存内容、证据和审查报告；状态投影可按平台流程更新。

证据对象在提交前先私有存储，路径由阶段/媒体检查点派生包 ID，再以实际字节派生证据 ID。恢复时原对象必须仍符合 SHA，不能覆盖重建损坏证据；相同检查点可重建相同包，旧租约不可提交。临时工作目录在 `finally` 中移除。未提交的私有证据对象仍需后续独立回收/隐私删除消费者处理，不能把临时目录清理称为完整资源释放。

`verifySealedEvidence`检查封存 DTO、数据库索引、路径归属与每个实际证据对象的字节。`assertReviewConsensus`提供双报告身份、摘要、规则、结论和问题的必要结构检查，默认不允许 Agent 临时豁免 MINOR。此函数不具有发布权限，不能代替数据库中的独立执行、隔离、真实视觉/声音输入和资金状态核验。

## 验证与剩余工作

新增 `tests/unit/review-packet.test.ts`覆盖 Python 摘要向量、封存字段、制作上下文串用、旧报告、跨租户、复核冲突及单报告等；`tests/integration/review-qc.test.ts`通过实际 PostgreSQL、Sharp、FFmpeg 和私有文件，覆盖封存/损坏/许可撤销/UNKNOWN/旧租约/接管，以及非整秒的实际场景变化。制作前置使用明确的合成协议进程，不是真实 Codex 或 OS 隔离证据。完整测试/构建结果以 `assets/implementation/current.json` 为准。
