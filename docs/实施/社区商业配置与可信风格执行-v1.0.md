# 社区商业配置与可信风格执行 v1.0

社区发布产生独立的商品规格编号；运行时 Skill 仍来自平台可信目录。两者通过已经审核并冻结的 `community_binding` 关联，不能把社区编号直接当作官方 Skill 编号，也不能只凭作者提供的哈希选取执行能力。

## 功能与使用顺序

1. 作者按已有工作台创建声明式方案、制作私有样例、提供授权、申请审核并发布独立公开样例。发布始终不等于准入或开售。
2. 平台在项目根目录配置自己的数据库连接，以原生 Node / pnpm 执行 `pnpm community:prepare <variant-id> <version> <expected-revision> <operator> <reason>`。命令使用事务和修订号，不向作者或买家开放接口。
3. 平台入口重新核对原许可、派生许可、公开状态及当前编译结果；蓝本原内容必须与发布时一致。只能从已经完成价格和成本准入的官方蓝本复制价格、模型、原制作/修复预算及 Codex 限额，再绑定所选风格的可信 Skill。当前入口支持三条无声、平台字体路线；外部资源和有声路线要求另行配置与准入，直接拒绝，不能降级。
4. 商业配置仅冻结一次。保持 `NOT_EVALUATED`、`sale_enabled=false`，不复制官方蓝本的准入证据。平台使用原管理接口为这个社区规格提交独立完整准入证据，再决定是否开售。
5. 买家沿用拍照、选方案、规划、报价、支付、制作、后期、技术 QC、事实/风格双复核、交付和相册保存。素材和订单只属于买家；作者不能读取。

本机的官方配置仍未生产准入，因此该命令在真实配置不满足条件时会拒绝。它不产生真实成本报告或平台密钥，不会自动启售。

## 可信绑定与冻结

`bundleForSource` 校验注册目录中的组合摘要、组合编号/版本、执行引擎和声明式编译绑定。社区风格组件、平台风格编号与可信组合必须匹配。内容规划、制作、后期、生成参考身份复核、最终两次复核和有限失败修复均使用该映射；Codex 原有角色工具白名单、原始 Token / 工具 / 费用限额和独立进程校验保持有效。

受限售后在报价前冻结对应的官方 Skill 编号，以及同一社区风格的图片加字颜色；不得交付后重新选取当前方案或增加旧订单权益。报价重新核对规划来源，配置变化要求重新规划。

迁移 031 保护已冻结商业配置的价格、规格、源、模型、资源、费用、合同及配置绑定；允许独立准入、停售和治理更新。变更商业配置必须重新发布版本。已支付订单继续使用原合同和快照，社区停售不改写已售订单。许可/素材撤权仍按原业务规则执行。

同时修正生成订单参考复核服务的执行器传递：生产环境构造真实执行器，只有显式测试环境允许注入。参考身份先验和生成视频购买顺序保持不变。

## 本轮交付边界

采用有限代表性检查和源码构建，不运行全面测试或要求全量绿灯。准确结果、失败尝试和源码摘要以 [本轮证据](../verification/community-commerce-source.json) 为准；[交付包入口](../delivery/package.json) 提供当前包的位置与摘要。

商业专项使用显式合成的发布/准入记录、模型语义、用量和进程身份，结合真实原生 PostgreSQL、HTTPS/MCP、PNG/MP4 和文件摘要。该记录只证明源码流程；此前真实样例字节到公开副本的专项另有证据，不能把二者叠加宣称生产社区已验收。

真实供应商、原生受限身份清理、支付、双端真机、社区完整独立准入、生产资源/有声样例、Plus 和云部署继续待完成。所有方案禁售；`full_product_verified`、`production_admitted`、`cloud_deployed` 保持 false。C 定型原件、现有截图/录屏/GIF、旧证据原字节保留；本轮后端衔接未新增 UI，不重新录制媒体。
