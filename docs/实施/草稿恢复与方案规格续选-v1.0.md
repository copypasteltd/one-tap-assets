# 草稿恢复与方案规格续选 / Draft recovery and exact-spec continuation

2026-10-30。补齐 P01-F01/F03/F06 的客户端衔接；保留 v3.1 全部58项需求、52项P0、三条路线、官方10套/至少14变体和 C「柚子创作社」视觉定型。本轮按用户要求只做定向验证，不以全面测试绿灯作为交付包前置条件。

## 1. 用户行为 / User flow

| 编号 | 场景 | 当前处理 |
| --- | --- | --- |
| 01 | 回到首页 | 只有本机存在先前登录线索时，才恢复平台身份并读取当前账户最新有效商品草稿。新访客可直接浏览公开方案。主动退出后清除此线索。 |
| 02 | 查看“我的素材” | 同时展示服务端商品草稿和订单；草稿独立分页，每次5条，状态区分照片未完整上传、照片已上传、商品档案已整理。 |
| 03 | 继续已上传草稿 | 查询服务端当前照片/档案版本；已有档案直接显示，无需本地 analysisId，也不重新识别。已绑定照片但尚无档案时，以原分析幂等键继续同一逻辑请求。 |
| 04 | 继续已有清单 | 只有清单商品、当前档案与所选规格相符，且处于 PLANNING/VALIDATING/READY，才进入原清单。缺失、失效或不匹配时回到当前商品档案。 |
| 05 | 先选方案再拍照 | 同时保存方案ID/版本、规格ID/版本；拍照和识别完成后显示原方案及原规格清单，可直接继续制作或重新挑选。 |
| 06 | 所选版本撤回或禁售 | 不切换首个规格或新版本。保留原参考，显示不可用原因并提供重选入口；未准入、未定价或禁售时不创建规划。 |
| 07 | 照片不足或商品冲突 | 保留输入校验返回的补拍指引，不创建规划；商品档案页可重新拍照。新照片仍按新批次处理。 |

在“已经认识你的商品”中展示实际 `OBSERVED` 特征和未知项。标签OCR、推测及冲突不提升为已观察事实，不增加必填表或强制逐字段确认。

Only account/version references are stored locally. Uploaded photos and product profiles remain server-owned. Browser fixtures demonstrate UI behavior; they are not real recognition, billing, native-device or production-isolation evidence.

## 2. 状态与请求约束 / State and request boundaries

| 编号 | 约束 | 实现 |
| --- | --- | --- |
| 01 | 权威数据 | `listProducts`/`getProduct`/`getProductProfile`读取服务端；列表排除删除和到期草稿。不能把过期本地照片路径当作已上传数据。 |
| 02 | 冷启动身份 | `ypcc:last-user`仅用于判断是否尝试登录，不作为认证或访问授权。会话仍通过宿主登录交换；每个API仍校验真实账户。 |
| 03 | 账户隔离 | 账户切换清除旧恢复引用；私有响应和公开方案查询之后再次核对账户。迟到响应不能写入另一买家的恢复记录。 |
| 04 | 同账户切换商品/方案 | 规划每个异步边界重新核对商品与所选四版本引用；变化后停止后续提交和本地写入。 |
| 05 | 原分析请求 | 使用上传流程相同的 `analysis` intent，绑定商品和照片版本。恢复不会重新创建商品、重传照片或另开分析键；实际付费调用仍由服务端原意图/预算控制。 |
| 06 | 原规划请求 | 当前商品档案、商品锁及方案/规格版本形成完整请求；资格检查后使用完整请求确定原 `plan` intent。丢失ACK只继续原键，不新增订单或付款。 |
| 07 | 清除过期引用 | 换商品或换所选规格时清除派生的清单/预览/报价/订单本地快捷引用；服务器历史订单与交付权益保持各自记录。 |
| 08 | 不变费用规则 | 不修改已售快照、预算、原调用次数、UNKNOWN、修复/售后保留、独立复核或截止。客户端恢复不证明真实模型或计费准入。 |

未绑定完整照片的草稿仍需重新选图；不跨重启持久化照片字节或临时路径。已绑定且有效的照片可继续服务端识别，受原服务配置/授权/原任务结果限制。若原分析已失败，不通过换键绕过原结论；按提示重新拍摄新批次。
