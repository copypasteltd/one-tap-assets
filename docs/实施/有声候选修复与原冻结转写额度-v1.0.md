## 2. 一次首轮识别与一次可选修复识别

原`native_audio_contract.asr.max_calls`固定为1；新可选`repair`包含版本YPCC-NATIVE-REPAIR-1、additional_asr_calls=1、additional_listening_packets=1及各自原冻结费率上界和合计。合计必须在原repair_ceiling_micro内，独立听音合同max_packets仍为2。基础音频成本只记首轮识别与许可分摊，修复识别/听音使用原修复费用桶，不能重复计算或增加订单预算。

历史订单缺少该条款时仍只有原一次ASR，失败后不临时升级；UNKNOWN只能恢复原意图/任务/回执。新修复ASR必须满足首轮成功、实际账单有效、供应商终态、费用已结算及原音频摘要一致。恢复同一修复意图不会再买一次；不同来源不能冒充同一购买。

修复POST只能转写本轮已完成PRODUCTION登记的完整视频；把首轮视频或任意私有对象ID传给新POST会在购买前被拒绝。所有上下文按当前stage_run_id解析修复计划和候选，不能退回首轮原计划而验证错包。

## 4. 独立核验与后续售后

失败包允许只读原听音证据，供第二个独立风格意见及协调器重新核验；付费听音网关仍拒绝对FAILED/BLOCK包准备新采购。新修复包必须重新取得自己的听音与两个新角色，不沿用旧PASS。

修复后发布包的售后授权核对原已售合同摘要，同时按首次实际发布包读取修复后的媒体和听音。原制作合同/截止不回写，不重新打开已结束的制作实例。售后沿用原预算、角色/Token/工具、300秒/48小时/原领取期的最早截止及一次用户成功机会，平台纠错不刷新额度。
