# 受限修改执行与新版本交付

2026-10-28｜需求v3.1、开发契约v1.1、C设计v1.0。整体仍为IN_PROGRESS。本专项接入F12的一部分，不替代全部三路线、平台免费纠错、真实服务或真机验收。

## 1. 本轮可执行范围

前提为已确认付款、已经完整交付、仍有合法照片/资源与领取权限，且报价前冻结了修改能力的原图无声订单。没有冻结能力的历史订单不临时增加预算或伪造执行快照，通过问题反馈处理。

| 类型 | 用户操作 | 实际变化 |
| --- | --- | --- |
| COVER | 选择本单另一张已有图片 | 新清单的素材包封面指向该图片；不重新生成媒体 |
| ALLOWED_ORDER | 调整完整素材列表的展示顺序 | 新清单保留全部且不重复的原素材ID、字节和摘要 |
| DISPLAY_TEXT | 编辑配套文案 | 写出新的实际UTF-8文案文件与摘要，新清单替换文案项 |

一次请求只含一种操作，拒绝混合字段、原样提交、缺件/重复排序、外单素材、过期清单和新增无依据商品断言。接口不会将配套文案修改冒称为视频字幕、原生口播或画面的修改。视频内封面/允许镜头顺序/字幕、生成式及有声路线、平台错误的免费关联修复仍待后续实现与验收；F12不能标记完整VERIFIED。

## 2. 原合同与成本

首次交付起48小时内，最多一次成功的用户小修改；同时最多一份占用机会的REQUESTED/PROCESSING请求。失败释放成功次数，但费用不会重置。修改绝对截止取“本次受理后300秒、原48小时窗口、原成品到期时间”三者最早值。修改成功不延长成品领取期，不改原订单的制作截止、付款或履约事实。

报价前在FrozenContract冻结`YPCC-LIMITED-REVISION-1`：原Bundle/变体、获准运行与费率、角色推理上限、修改费用上限；ExecutionSnapshot绑定其摘要。原总预算必须同时覆盖制作和售后额度。制作预留排除已划定的售后部分，不能先花完总预算再额外增加修改额度。售价/实际成本是否可售仍须真实能力与费率准入。

每单只有一个`revision_budgets`账户，失败重试继续累计spent/reserved；`revision_cost_reservations`先保存原调用意图、金额、费率，再发起外部调用。UNKNOWN保留占用，恢复原回执后结算，不重购、不换键、不因新revision_id清零。未决费用阻止重试和私有恢复载荷脱敏。

## 3. 五阶段与三个新角色

```text
REVISION
  新POST角色 → 受控修改工具 → 检查点
REVISION_QC
  实际文件检查 → 新封存审查包
REVISION_REVIEW_FACTS
  新事实/规格角色 → 不可变报告
REVISION_REVIEW_STYLE
  新风格角色 → 不可变报告
REVISION_COMPLETE
  平台事务重查 → 原子发布关联新版本
```

每个阶段持久排队，领取依赖前阶段成功。工具检查当前角色、照片/商品与原合同、修改输入、新清单、截止、阶段及实例代次。原制作会话和原制作截止不重新开放；修改有自己的冻结输入、运行及权限。

QC核对完整候选包：实际PNG解码、实际MP4规格及全片解码、实际文案字节。没有改变的图像/视频仍需读取并验证登记字节与SHA。复用原已封存画面证据必须逐一核对原摘要；新审查包绑定本次输入与候选清单，包含全部原始照片、全部原封存视频/图片画面和新旧文案语义。不能沿用原PASS报告。

三个新角色必须有实际工具及推理回执，完成清理；运行、线程、进程和身份不能串用原制作或先前修改角色。事实与风格角色必须检查完整包并分别保存绑定新packet_hash的报告。任一FAIL、缺图、摘要错误、未决工具/费用或未完成释放均阻断发布。测试中的这些角色与身份断言为明确合成数据，不证明生产受限身份或语义质量。

## 4. 原子发布、失败与恢复

最终平台事务按归属/原订单/修改/阶段顺序加锁，重查许可、原父清单摘要、实际文件、三个角色与报告、成本、截止和租约代次。只有全部通过才写新`delivery_manifests`，一次性更新领取清单，并将修改置为COMPLETED。

新清单保留`parent_manifest_id`和`revision_id`，版本递增，原清单不可改。替换的文案有新ID和实际文件；封面及顺序操作保留媒体字节。新旧清单保留相同的成品到期时间。下载仍按当前清单逐项鉴权并验证实际摘要，不能凭旧签名读取被替换文案。

失败、截止或租约丢失停止修改权限并请求释放，原交付继续可领取，不触发原订单退款。已成功角色检查点可供同一输入的父阶段接管；UNKNOWN工具或写入只核对原意图，不另写第二份。存储PUT期间撤权时，已写到存储的迟到对象登记为待回收，由独立媒体维护器处理。

商品/账户主动删除先撤权并停止修改。REVISION角色通过原订单/商品稳定关联纳入现有33表私有内容范围；未决费用和私有对象仍阻塞收尾。这里不证明底层页/WAL、供应商、异地副本或真实OSS已全部删除。

## 5. 双端交互与协议

素材包页面内提供小修改面板，不增加普通制作步骤。页面从服务端查询历史及正在处理的请求，支持离页后恢复。受理回执丢失时先恢复原请求；失败重试使用包含先前失败请求ID的稳定意图，不重新占用已经成功的机会。完成后刷新完整素材包，并重建相册保存队列，避免沿用旧版本项目。

- `POST /v1/p01/orders/{order_id}/revisions`：本人提交，必须带8–128字符幂等键。
- `GET /v1/p01/orders/{order_id}/revisions`：本人游标分页恢复，游标绑定租户、用户和订单。
- 当前77业务/26管理接口，229业务schema、71逻辑实体；生成源为`scripts/生成Codex开发契约.py`。

双端目前只有共享源码与构建证据，不能推定真机、原生相册或视觉体验通过。

## 6. 内部流量隔离

同一API进程内，四个固定工具/推理接口对合法的活跃运行使用共享的600次/分钟桶；列表、提交、轮询与推理共同累计。按持久run_id计数，轮换capability或出口IP不能重新获得额度。归属、角色、租约及撤销状态每次重查，处理工具或推理时再次鉴权。

缺失、未知、到期或撤销令牌沿用共享IP的180次/分钟限制，随机令牌不能创建独立桶。普通接口保持原IP限制，宿主会话仍有原15次/分钟上限。推理入口在限流后、读取大请求体前鉴权。此限制仅是单API进程的流量控制；跨进程成本、工具次数和推理次数继续依赖数据库原子额度，不能用内存桶证明全局费用安全。
