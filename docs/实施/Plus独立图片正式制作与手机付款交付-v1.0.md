# Plus 独立图片正式制作与手机付款交付 v1.0

本轮优先完成一条可执行的图片制作主链路：电脑编辑已交付图片，冻结独立版本；原小程序核对内容、规格和新费用，主动付款；CONTENT、PRODUCTION、POST、QC、事实复核、风格复核依次执行，交付新的私有图片与文案。原图、原订单及原订单的修改权益继续保留。设计沿用已定型的 C「柚子创作社」。

本说明接续[手机确认与独立编辑草稿](Plus手机确认与独立编辑草稿-v1.0.md)。专项结果、原始失败、源码对应关系及媒体来源统一见[本轮准确证据](../verification/plus-render-source.json)。本机合成付款、模型回复、审核结论和进程身份只用于检验功能连通；不表示真实服务、支付渠道、系统隔离或宿主小程序已准入。

## 1. 用户操作和交互载体

| 步骤 | 载体 | 行为与可见结果 |
| --- | --- | --- |
| 01 | 支付宝/抖音小程序 | 拍照、自动商品识别、社区方案选择、首套素材制作与领取仍是基础入口 |
| 02 | 同源 HTTPS `/plus/` | 用户可选择申请“允许整理正式制作清单”，然后生成 5 分钟接续码 |
| 03 | 原小程序 | 账户与隐私 → 接续到电脑 Plus；查看新权限后明确批准，获得 1 小时独立连接 |
| 04 | 电脑工作台 | 打开本人已付款且有效的素材包，选一张图片，调整裁切、尺寸、标题与可选文字，保存独立修订 |
| 05 | 电脑工作台 | 选择已准入的图片排版风格，查看单独计价；整理一张图片及文案的制作清单 |
| 06 | 原小程序 | “电脑制作清单”打开同一版本，核对裁切、像素、待核对信息和报价；明确确认费用并按原渠道付款 |
| 07 | 云端工作流 | 预载对应风格 Skill，独立 CONTENT 规划，然后制作、后期、文件检查和两项独立复核 |
| 08 | 原小程序/电脑 | 领取新素材包；小程序沿用相册保存，电脑沿用有效期内的私有下载；旧素材包保留 |

电脑预览用于编辑，正式结果以通过检查并交付的文件为准。用户不填写基础商品表单；可选品牌与补充事实不会自动升级为已识别事实。危险宣称沿用商品证据校验，不能核实的内容不应交付。长文字必须在付款前通过实际字体测量，超出排版容量时明确拒绝，不静默删改。

## 2. 授权、版本与价格边界

旧连接默认 `allow_render_plans=false`，数据库迁移不会自动扩大权限。浏览器申请与手机批准绑定同一挑战；批准后浏览器才可整理清单。浏览器不能建立报价、订单、付款或退款，不能批准自身连接，也不能合并平台账户。原 5 分钟接续码、43 字符独立轮询秘密、1 小时固定期限、最多 5 个连接及每次请求重验撤销继续执行。凭据仅保存在页面内存；401、撤销、到期或离开页面会清理私有工作台。

制作请求冻结草稿 ID/修订、完整编辑设置及摘要、原订单/商品/清单修订/图片摘要/尺寸/字节数、原合同摘要、原图有效期、是否继承 AI 标识、风格基线摘要以及独立价格和价格版本。修改草稿不会修改已提交的制作请求；同一冻结输入重复提交返回原请求。原清单或商品档案变化时，新的制作确认须重新整理，不能把新来源混入旧版本。

Plus 图片独立计价由平台配置，不沿用原套装价格。报价仍冻结现有费用上限、Skill、模型、资源许可、运行版本、期限和受限修改合同。关闭功能会阻止新报价/订单；已付款订单仍按原合同执行。供应商费用不明、UNKNOWN、租约 fencing、免费修改次数及退款机制沿用原系统。

## 3. 图片能力和验收

| 内容 | 本轮范围 |
| --- | --- |
| 来源 | 本人已付款、已交付且仍有效的 PNG，来源清单及原合同可核验 |
| 风格 | 官方 10 套及满足现有准入条件的社区 `PHOTO_LAYOUT` 风格；非图片路线不在本次范围 |
| 输出 | 单张 `plus-image` PNG 和配套文案；此制作请求不额外生成视频 |
| 规格 | 每边 256–3840 像素，总像素最多 8,294,400；裁切完全位于原图内 |
| 文字 | 标题 80 字符、品牌 60 字符、最多 8 条各 200 字符的可选事实；实际可排容量还受完整字形测量约束 |
| 版权及标识 | 使用原冻结字体许可；来源为 AI 素材时重新覆盖可见“AI 生成”并检查实际像素，裁切不能去除该标识 |
| 交付条件 | 实际 PNG 的尺寸、编码、摘要、文件清单通过 QC；事实和风格分别用独立角色及封存证据复核 |
| 修改 | 新订单沿用冻结的受限修改能力；图片加字只在该工具既有尺寸范围内开放，不扩大旧订单承诺 |

首次整理清单要求原来源至少还有 20 分钟有效期。报价有效期最多 15 分钟，并为正式执行保留原方案截止时间；创建订单和确认付款再次核对来源。付款确认时来源已失效，进入原有取消/退款处理。主执行阶段持续验证来源，避免过期或被删除素材进入成品。

QC 在新订单下封存选中原图的精确副本，证据标为 `PLUS_SOURCE_REFERENCE`，并携带来源摘要和未核实文字提示。新订单交付后的受限修改使用自己的成品和封存证据；原订单正常到期不会使已经交付的新图片失去自身证据。商品隐私删除和媒体撤销继续走原有删除与存储登记机制。

## 4. 实现结构

```mermaid
flowchart LR
    A[Plus 保存编辑修订] --> B[手机明确批准新权限]
    B --> C[冻结独立制作请求]
    C --> D[CONTENT + 风格 Skill]
    D --> E[小程序清单及费用确认]
    E --> F[原渠道报价 / 订单 / 付款]
    F --> G[PRODUCTION 原图裁切排版]
    G --> H[POST / AI 标识 / 实际文件检查]
    H --> I[QC 封存原图与候选]
    I --> J[事实独立复核]
    J --> K[风格独立复核]
    K --> L[原子交付新 PNG 和文案]
```

| 位置 | 责任 |
| --- | --- |
| `src/shared/domain/plus-render.ts` | 编辑与制作绑定校验、派生单图规格、显式文字保持 |
| `src/api/modules/plus-render*.ts` | 本人来源验证、独立价格、风格目录、不可变制作请求与分页读取 |
| `036_plus_render_plans.sql` | 默认关闭的新权限、制作请求表、输入自然键去重、不可变更新约束与商品删除清理 |
| `plans.ts` / `commerce.ts` | 复用 CONTENT、冻结合同、报价、原渠道建单和付款后的执行入口 |
| `src/worker/media/plus-image.ts` | 实际完整字体排版、按选定区域裁切、保留比例并输出精确画布 |
| `photo-pipeline.ts` / `disclosure.ts` | 新版本渲染器、独立图片上限、后期与可见标识证明 |
| `review/qc.ts` / `review/context.ts` | 来源副本、编辑指令与候选封存、交叉核验所需的实际图像 |
| `src/web/render-panel.tsx` | 风格、独立价格、保存状态、制作请求和新交付入口 |
| `src/shared/ui/plus-render-requests.tsx` | 手机端列表与付款前版本详情；复用现有确认页与订单页 |

## 5. 新接口与配置

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/p01/plus/render-styles` | 图片风格、准入状态、独立价格及不可用原因 |
| POST | `/v1/p01/plus/edit-drafts/{draft_id}/render-plans` | 对当前草稿修订整理不可变制作清单，需明确新权限 |
| GET | `/v1/p01/plus/render-plans` | 本人制作请求分页；电脑和原小程序均可读取 |
| GET | `/v1/p01/plus/render-plans/{request_id}` | 同一版本的规划状态、冻结设置及独立原渠道订单 |

`createPlusLink` 可选 `prepare_render_plans`；连接及手机确认信息增加 `can_prepare_render_plans`，默认 false。`Plan` 可选 `plus_render_request_id` 指向手机确认详情。原 42 个契约/Skill 文件槽位兼容扩展，生成入口与运行时产物同步。旧验证契约另存 `docs/verification/contracts-d1034ff/`。

```dotenv
PLUS_IMAGE_RENDER_ENABLED=false
PLUS_IMAGE_RENDER_PRICE_FEN=0
PLUS_IMAGE_RENDER_PRICING_VERSION=
```

默认仅可保存编辑草稿。正式开放要求正整数价格及稳定价格版本、基础图片方案和 Skill 准入、Codex 运行及独立视觉复核准入、模型/字体许可和真实付款配置同时满足。单独开启开关不能替代这些条件。新增配置见项目根目录 `.env.example`；开发运行仍使用原生 Node.js/PostgreSQL，禁止 Docker、WSL 和虚拟化环境。
