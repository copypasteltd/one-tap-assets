# 生成式受限修复与原素材复用 v1.0

2026-10-30。在原图修复基础上，将内部无声 `PER_SHOT_AI`、`REFERENCE_FILM` 接入同一条最多一次的候选修复链。保持需求 v3.1、58 项需求 / 52 项 P0、十套官方风格、三路线、至少十四变体及 C「柚子创作社」设计。原生口播修复、官方完整规格、真实供应商与真机准入仍单独记录。

## 1. 使用方式

客户继续拍照、选社区方案、等待并领取素材。第一次事实与风格复核完成后，平台根据已封存证据定位问题；可修复时显示「根据检查结果优化素材」，在原订单内重制一次，再检查完整素材包。客户不填写额外表格，不承担隐含增购费用。

内部流程：原双复核 → 同事务撤销旧交付、签发唯一权限 → CONTENT 受限修复计划 → 制作 → 后期 → 新文件检查 → 全新事实/风格复核 → 交付和实例释放。不能定位、证据不足、权限或额度不足，以及第二轮失败，沿停止与原退款意图处理。

## 2. 如何确定重制范围

平台读取旧 POST 产物中的实际 `generation_sources`，重新核验原成功任务、实际来源 ID/SHA、原制作阶段和已结算费用。CONTENT 不能自行扩大可购买的节点集合。

| 定位的失败素材 | 可重购节点 | 其余节点 |
| --- | --- | --- |
| 单张生成图片 | 该图片的 `image:<slot>` | 复用原图片、参考帧和视频 |
| 逐镜路线的视频 | 该成片实际引用的参考帧和逐镜视频 | 复用未受影响图片 |
| 整片路线的视频 | `reference:film`、`film:original` | 复用未受影响图片 |
| 仅配套文案 | 不授予生成购买 | 仅修改获准的文案范围 |
| 影响整个包的已定位共享内容 | 原包实际来源的并集 | 仍不允许新增商品、规格或节点 |

没有实际素材或有效证据位置时拒绝授权。当前视频的来源粒度为完整成片所引用节点，不宣称已实现视频内任意秒段的局部重绘。

## 3. 修复计划和提示词

CONTENT 继续使用本单冻结的风格 Skill、目标规格和原角色限额。商品、身份锁、输出列表、时序、时长、声音/人物绑定、原台词不可变。局部图片修改不能顺带修改其他图片；修改镜头必须拥有相应参考帧和视频权限。共享标题/文案/场景仅在全包被定位时允许修改。

生成节点可在保留原计划时，根据原失败意见重试视觉生成；提示词明确绑定来源包摘要、节点和有界失败意见。意见被作为数据处理，不能授予工具、预算或平台权限。无论计划是否改变，新 QC 仍要求获准目标的实际文件 SHA 改变；换任务编号或复制原文件不能通过。

## 4. 原素材复用与参考核验

复用仅限本单、同商品、同原制作阶段、未受影响且成功的来源。读取时重验原模型/冻结协议、`SETTLED` 费用、私有存储登记、实际文件摘要和授权；未知费用不能当作免费素材或补购理由。未变节点携带修改后的提示词或参考会被拒绝。

每次新候选仍调用新的独立参考身份核验角色，覆盖完整商品原图和当前参考帧。复用的视频还必须通过它最初的参考报告，并且其实际参考 ID/SHA 与本轮参考一致；重制参考帧后不能套用旧视频。新参考报告、新最终事实/风格报告都需新运行身份和进程标识，不能复用旧 PASS。

POST、QC 与交付分别重新读取新旧来源的确切组合。生成来源、当前参考批准摘要、修复计划摘要和新文件进入新封存包；交付事务再验，原候选持续不可领取。

## 5. 费用、恢复与释放

只使用原订单总额内预先出售的修复保留额、调用次数、角色次数、输入/输出 token、工具次数及绝对截止时间。每个获准生成节点最多一次新购买；CONTENT、参考核验和后续角色同样消耗原额度。合同未预留足够能力时拒绝，运行中不补额度。

未知提交恢复原任务与原回执，不重新发送创建请求。未受影响节点的复用不生成新购买意图或新费用；文件读取和后期仍受原操作、存储和角色权限约束。最后按原机制交付、回收实例并处理到期文件。

原生口播合同只出售一次整轨 ASR；本专项继续阻断原生口播修复，避免重制音轨后隐含增加 ASR、听音或授权采购。

## 6. 本轮交付边界

按用户要求采用类型、服务端构建和修复定向原生检查，不要求全面测试绿灯。详细结果及初始失败记录见 `docs/verification/generated-repair-source.json`；旧原图验证保留在 `repair-candidate-source.json`。

检查使用真实原生 PostgreSQL、HTTPS/stdio/MCP、PNG/MP4、费用和封存交付，外部模型、语义、计量和隔离身份为合成夹具。不能据此宣称真实生成质量、商业计费、操作系统隔离或完整官方变体验收。页面交互与 C 设计未修改，沿用原截图/录屏/GIF并验证字节。

## 7. 主要实现入口

- `src/worker/repair/generation.ts`：从真实产物来源推导权限及选择新旧来源。
- `src/worker/repair/context.ts`、`planning.ts`：受限计划与原 CONTENT 运行。
- `src/worker/generation/gateway.ts`、`requests.ts`：获准重购、原任务复用与失败意见。
- `src/worker/generation/reference-material.ts`、`reference-report.ts`：混合参考帧和新身份核验。
- `src/worker/generation/outputs.ts`：新旧精确来源、原费用及实际文件重验。
- `tests/integration/generated-production.test.ts`：局部图片修复与整片视频重制的定向链路。
