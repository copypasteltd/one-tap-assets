## 3. 同一构建可重复打包

原打包器使用固定构建编号创建ZIP，使用 `wx` 防止覆盖，因此第二次打包同一构建会撞名。现在每次打包创建独立 `package_id` 和输出目录；兼容保留 `id` 为原构建编号，继续记录原源码摘要、构建产物SHA和逐文件清单。

运行 `pnpm delivery:package` 或 `.\scripts\run.ps1 delivery:package`。相同源码下可复用 `docs/delivery/current.json` 所指向的成功产物，只更新文档也可重新打包；修改应用、脚本、测试、契约或字体后仍须重新构建。源码或原产物改变仍拒绝打包，不会因新编号跳过检查，也不会覆盖旧包。`docs/delivery/package.json` 指向最近成功生成的包。
