# 客服接单、回复与处理工作台

当前增补承接[订单反馈与售后记录](订单反馈与售后记录-v1.0.md)，为原有帮助页补齐可操作的客服端。需求仍为58项、52项P0，支付宝/抖音小程序优先，三条制作路线、10套官方风格及至少14种规格保留。C「柚子创作社」定型原件未修改。

当前版本提供独立的浏览器客服工作台：`/ops/support`。它使用实际管理接口和数据库；用户继续通过小程序原订单或帮助页查询处理进展。客服工作台不属于面向客户的 Plus 编辑器。

## 1. 完整交互

| 编号 | 操作者 | 操作与结果 |
| --- | --- | --- |
| 01 | 客服 | 在服务的 `/ops/support` 输入独立访问令牌，加载工单队列；不会借用小程序用户登录态。 |
| 02 | 客服 | 按已受理、处理中、已处理、已关闭筛选，可分页，选择工单后查看原说明、订单编号和当前接手人。 |
| 03 | 获授权客服 | 逐张查看该工单原证明图片；额外检查本人原附件关系、用途、有效状态、私有对象登记和实际文件摘要。 |
| 04 | 客服 | 接手已受理工单，进入处理中；并发接单只允许一个当前版本成功。 |
| 05 | 原接手人 | 发送回复并保持处理中，或回复并标记已处理；没有回复不能解决工单。 |
| 06 | 原接手人 | 关闭已有回复的已处理工单，保留最新回复；关闭后没有继续编辑或隐式重开的动作。 |
| 07 | 用户 | 在本账户的帮助页点击“查询最新处理状态”，查看最新状态、客服回复与回复时间，返回关联订单领取素材或查退款。 |
| 08 | 客服 | 回执丢失后点击“继续确认原操作”，沿用原工单、版本、正文和幂等键；未确认前不能改写或处理其他工单。 |
| 09 | 客服 | 退出清空当前页面正文、图片、访问令牌和连接状态；访问令牌、图片与通信正文不写入浏览器持久存储。 |

`OPEN → PROCESSING → RESOLVED → CLOSED` 是主要状态流；`PROCESSING → PROCESSING` 用于追加进展回复。每次成功写入递增版本，必须提交查看时的原版本。其他接手人不得代替原客服回复或关闭；强制转派、客服消息时间线与用户追加消息尚未实现。

## 2. 接口、身份与内容边界

业务接口保留77个操作，管理接口由26增至30个。新增管理路径统一以 `/v1/internal/p01` 为前缀。

| 方法与路径 | 权限 | 内容 |
| --- | --- | --- |
| `GET /support-tickets` | `support:read` | 按状态分页；队列仅返回工单元数据，不返回用户说明、回复正文或证明图片内容。 |
| `GET /support-tickets/{ticket_id}` | `support:read` | 授权读取说明与最近回复，追加只含摘要的读取审计。 |
| `GET /support-tickets/{ticket_id}/evidence/{asset_id}` | `support:evidence` | 返回当前工单已关联的有效PNG及摘要，逐次授权并记录读取审计。 |
| `POST /support-tickets/{ticket_id}/process` | `support:write` | 按版本执行 `CLAIM/REPLY/RESOLVE/CLOSE`，要求管理幂等键。 |

管理令牌由服务端配置的令牌摘要校验，与购买者 Bearer 完全独立。现有配置表示服务的全局客服角色，不提供按租户分配客服的控制台；不能将其解释为租户管理员隔离已验收。生产身份发放、轮换和权限治理仍待部署阶段落实。

证明图片通过已鉴权且 `no-store` 的接口按次读取；不生成公开链接或复用素材交付链接。输入照片仍限制10MB，上传后的规范PNG读取上限为40MB，前后核对登记及实际字节的SHA-256。错误用途、他人工单附件、过期、撤销、未登记、待删除或摘要变化均拒绝。

回复正文保存在原 `support_tickets.private.response`，沿用既有私有字段脱敏机制。公开 `data` 只记录状态、版本与更新时间；本人查询时才按允许范围投影回复。管理幂等记录只保存无正文的元数据；读取与写入审计只保存摘要。没有新增含私有正文的审计表或历史副本。

订单私有内容撤销后，读取立即隐藏说明、回复与附件，禁止继续写入；历史操作幂等重放只返回原元数据，不恢复正文。当前对已撤销订单的新通信同样受此限制，不能承诺删除后继续提交正文仍可由客服处理。

## 3. 本地使用

按[交付指南](../delivery/README.md)完成原生初始化、构建和后端启动，不使用 Docker、WSL 或虚拟机。客服页面与API同源，服务端读取当前构建目录下的 `preview/support.html` 及其固定构建资源；缺少页面构建时明确返回503，不改用演示队列。

`YPCC_BUILD_ROOT` 必须指向项目 `runtime/` 内实际构建目录。使用 `delivery:build` 后，可从 `docs/delivery/current.json` 读取 `build_root` 并传给 `local:start`。工作台访问地址为原API地址加 `/ops/support`，例如本地 `https://localhost:3100/ops/support`，以实际环境配置为准。

本轮采用 `delivery:build --skip-mini`，交付服务端、网页及两端完整源码，最终快照不含小程序编译物。ZIP中的成功产物统一位于 `runtime/build/`，直接从ZIP启动时使用这个目录；仓库内构建则使用记录中的独立输出目录。

为本地测试配置单独的客服角色时，可以在启动服务的 PowerShell 窗口中设置以下环境变量。不要将真实令牌写入仓库或截图；不要覆盖已有生产身份配置。

```powershell
$supportAccessToken = Read-Host -MaskInput '输入本次本地客服令牌'
$supportTokenDigest = [Convert]::ToHexString(
  [Security.Cryptography.SHA256]::HashData(
    [Text.Encoding]::UTF8.GetBytes($supportAccessToken))).ToLowerInvariant()
$env:MANAGEMENT_TOKENS_JSON = ConvertTo-Json -Depth 4 -Compress -InputObject @(@{
  actor = 'local-support-owner'
  token_hash = $supportTokenDigest
  permissions = @('support:read', 'support:write', 'support:evidence')
})
$supportBuild = Get-Content -Raw docs/delivery/current.json | ConvertFrom-Json
$supportBuildDirectory = Join-Path (Get-Location) $supportBuild.build_root
if (-not (Test-Path -LiteralPath $supportBuildDirectory -PathType Container)) {
  $supportBuildDirectory = Join-Path (Get-Location) 'runtime/build'
}
$env:YPCC_BUILD_ROOT = $supportBuildDirectory
.\scripts\run.ps1 local:start
```

打开同源客服工作台，输入同一个本地令牌。令牌本身不存数据库；配置保存摘要。客服账户初次连接只查询，不自动接单或执行财务动作。

## 4. 本轮验证与交付边界

当前精确结果见[本轮来源](../verification/support-desk-source.json)、[构建记录](../delivery/current.json)与[录屏来源](../media/support-desk/README.md)。仅执行本轮关键检查；没有以全面绿灯作为打包条件，历史失败和原来源保持原样。

API专项使用原生PostgreSQL、实际API、实际PNG上传与本地对象字节。浏览器工作台直接连接本轮原生API和独立测试数据库，接单、回复和关闭是实际事务；客户、订单、图片、访问令牌和回执丢失故障均为合成夹具。用户端真实状态和回复通过实际本人查询接口核验；小程序真机回复显示、生产客服身份和真实客户工单尚未验收。

工单已处理或关闭仅表示沟通状态。平台纠错的自动诊断/重制、原生口播修复及其新验收、真实退款到账、真实云端模型与支付、生产隔离与发布均未由本轮完成。不得因客服操作提高原订单预算、重置截止、把 UNKNOWN 当作成功，或绕过独立复核重新交付。官方方案禁售及完整产品/生产准入/云端部署为false的状态保留。
