# 工具队列原子领取与并发租约 / Atomic tool claims and concurrent leases

版本 v1.0，2026-10-29。适用源码：[工具消费者](../../src/worker/tool-gateway/consumer.ts)、[原生回归](../../tests/integration/tool-consumer.test.ts)。最新完整执行以[实现索引](../../assets/implementation/current.json)和[验证来源](../verification/README.md)为准。此项不改变 v3.1 的 58 项需求、52 项 P0 或生产准入状态。

## 问题与实现 / Problem and implementation

Worker 中的受控工具消费者原先每次领取都显式执行 `BEGIN → SELECT FOR UPDATE SKIP LOCKED → UPDATE → COMMIT`，即使空队列也要执行三条语句。消费者在无工作时每 250ms 再查一次，这些事务没有产生业务结果。

`claimToolIntent` 现在用一条 CTE 选择候选并原子更新租约。PostgreSQL 在同一语句事务中锁定候选；其他消费者跳过已锁定行，因此同一有效租约代次只会被一个消费者领取。过期接管产生新代次，旧执行者仍须被原提交门禁拒绝；领取互斥不等于旧进程已经停止。空轮询仍然查询真实数据库，不依赖内存队列或假定任务不存在。

Previously, every claim opened an explicit transaction, including three statements for an empty queue. The consumer polls again after the existing 250ms idle delay. A single CTE now selects and locks a candidate, then updates its ownership within the same statement transaction. Other consumers skip locked rows. An expired takeover creates a new fence; existing commit checks must reject the old owner. Exclusive claiming does not prove the old process has stopped. Empty polls still check the durable database.

## 保留的语义 / Preserved semantics

| 编号 / No. | 条件 / Rule | 当前处理 / Behavior |
| --- | --- | --- |
| 01 | 可执行时间 / Availability | 仅 `available_at <= now()`；UNKNOWN 原任务未到恢复时间不提前领取 / No early UNKNOWN retry |
| 02 | 处理器白名单 / Handler allowlist | 只领取本消费者实际注册的工具；空白名单不领取 / Only registered tool names |
| 03 | 顺序 / Ordering | 保留 `available_at, created_at, id` 排序 / Original deterministic priority |
| 04 | 并发 / Concurrency | `FOR UPDATE SKIP LOCKED` 跳过其他事务正在锁定的任务 / Skip another transaction's locked candidate |
| 05 | 租约 / Lease | QUEUED、到时UNKNOWN或已过期RUNNING可领取；未过期RUNNING不被接管 / Preserve eligible states and expiry |
| 06 | 代次 / Fence | 原记录增加一次 `fencing_token`，保存本次 `lease_owner`，45秒租约 / Increment original fence and assign a 45-second lease |
| 07 | 执行与提交 / Execution and commit | 原能力、输入摘要、父阶段/实例代次、撤权和提交前活租约复查保持；不是领取成功就可交付 / Existing live authority and commit checks remain |
| 08 | 心跳、重试与限制 / Heartbeat and limits | 保留10秒心跳、250ms空闲间隔、原UNKNOWN延迟、原预算/次数/截止与输出容量 / Existing limits and recovery behavior remain |

这里只减少领取事务的往返。处理器输出、业务提交、私有对象写入、付费调用、UNKNOWN 恢复和撤权检查仍使用原事务边界；没有批量合并它们。

This change reduces claim round trips. It preserves the existing transaction boundaries for handler commits, private-object writes, paid operations, UNKNOWN recovery and revocation checks.

## 已执行的对照 / Executed controls

使用隔离的真实原生 PostgreSQL 测试 schema，同一消费者逻辑各做64次空队列领取，全部返回 `null`。查询计数从192条（64 BEGIN、64 SELECT、64 COMMIT）变为64条 WITH。源码摘要及原始计数随验证证据留存；这不是统计性能基准，也不能证明历史120秒超时的根因。

A controlled empty-queue run used an isolated native PostgreSQL schema and 64 claims for each implementation. All returned `null`. Observed query counts changed from 192 to 64. Source digests and original counts are retained with the verification evidence. This is not a statistical benchmark or proof of the earlier timeout's cause.

新增原生回归使用六个并发领取者及另一个持行锁事务，验证：被锁候选可跳过、唯一可执行任务仅被领取一次、未来UNKNOWN与不支持工具不被领取、未过期任务不被接管、过期接管增加原代次且保留45秒租约、到时UNKNOWN使用原记录恢复。原四项能力撤销、父阶段代次、结构化计划和跨能力次数限制回归仍执行。

The new native regression uses six concurrent claimers plus an independent row-lock transaction. It checks one claim for the only eligible unlocked task, future UNKNOWN availability, handler filtering, active-lease protection, expired takeover with an incremented fence and the unchanged 45-second lease. Existing capability, stage-fence, structured-plan and shared-quota regressions remain.

## 原超时诊断的边界 / Limits of timeout diagnostics

原文件写入授权撤销用例，在优化前后各一次定向诊断中均在原120秒时限内通过，分别约95.9秒、49.8秒，两次均记录142次原生命令。诊断只增加忽略目录内的进程/数据库耗时观察，不记录SQL参数、客户数据或原生命令敏感参数。计时和轮询数量会随宿主负载变化，不能把两次耗时差全部归因于此优化，也不能用定向通过代替完整测试。

The original-write revocation case passed two focused diagnostics within its original 120-second cap: approximately 95.9 seconds before and 49.8 seconds after. Both recorded 142 native media commands. Ignored diagnostic snapshots observe process/query durations without SQL parameters, customer data or sensitive command arguments. Timing and poll counts vary with host conditions. The difference is not attributed wholly to this optimization, and focused passes do not replace full verification.

原失败记录继续留存。当前原生检查结果、完整/未完成范围与来源以[验证证据](../verification/README.md)为准；完整产品、真实模型/付款/中文听感、生产隔离、宿主真机和官方全变体仍待验。没有调用 Docker、WSL、虚拟机、外部模型或浏览器；既有页面/音频/标识媒体与 C 冻结设计没有因本项实现而重录。

Earlier failures remain in the history. See the current verification evidence for actual complete/incomplete checks. Full-product, real provider/payment/audio, production isolation, native-device and full-variant acceptance remain pending. This work uses no virtualization, external model or browser; existing media and frozen C design keep their provenance.
