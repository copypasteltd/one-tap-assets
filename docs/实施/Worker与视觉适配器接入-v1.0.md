## 当前可运行内容

独立入口为 `src/worker/main.ts`。它会校验数据库迁移、预热并核对19份 Skill / 14个 Bundle 摘要，启动阶段调度、独立工具消费循环、心跳和周期恢复；HTTP请求不承担长任务执行。

```powershell
./scripts/run.ps1 exec tsx src/worker/main.ts --once
./scripts/run.ps1 dev:worker
./scripts/run.ps1 build:server
```

`--once`只执行本轮维护、已注册事件/阶段及工具队列，不是完整产品验收。支付/生成开关默认关闭；此时只运行本地维护和缓存校验。若显式启用了真实交易或模型，Worker 将按对应原始意图调用获准服务，不能把该命令当无副作用检查。

目前阶段执行器已接入 ANALYZE、PLAN，以及 PHOTO_LAYOUT 的 PRODUCTION / POST / QC（三者要求生成与Codex开关同时启用），付款创建/原单查询/退款通过配置启用。已接内容工具和原图制作/后期/实际媒体检查/角色结果保存，详见[原图阶段接入](原图制作与后期阶段接入-v1.0.md)。原图无声QC及私有封存见[文件验收接入](文件验收与封存审查包接入-v1.0.md)。生成式路线、有声QC/独立双复核/交付等阶段与其余工具尚待实现，未注册任务保留在持久队列，不伪造成功。生产环境若开启生成但完整阶段表仍缺项，入口会拒绝启动。

ANALYZE是内容阶段的照片证据准备子任务，适配真实视觉请求。PLAN已有受控角色和推理费用出口程序，协议夹具通过真实HTTPS/MCP贯通工具与计划提交；真实Codex、原生隔离器及实际计费上界尚未准入，见[内容规划接入](Codex内容规划与受控运行接入-v1.0.md)。因此局部子链不代表完整Codex内容阶段已验收。

## 视觉服务配置

配置键为 PROVIDER_BASE_URL、PROVIDER_API_KEY、PROVIDER_ALLOWED_HOSTS、VISION_MODEL_ID、MODEL_REGISTRY_VERSION、VISION_CONTRACT_PATH、VISION_DAILY_BUDGET_MICRO。密钥仅保存在未提交的本地/服务端配置，不发送给小程序或 MCP 子进程。

[协议示例](../../assets/config-examples/vision-contract.example.json)有意保持 NOT_EVALUATED，价格/认证输入上界为空，直接使用会被拒绝。将实际审核后的文件保存在本项目受控目录，配置其绝对或项目相对路径；不得把示例或测试夹具的虚构摘要作为真实准入证据。

| 协议字段 | 约束 |
| --- | --- |
| actual_model / base_url / registry_version | 与服务配置完全匹配，生产模型使用获准固定标识 |
| official_documentation / capability_evidence_sha256 | 指向协议依据并绑定实际能力/成本验证记录；字段存在本身不构成验证 |
| valid_until | 过期后停止新调用，不能悄悄延长原任务合同 |
| 图片与请求上限 | 限定3–5张、缩放边长、总像素、负载字节和输出token；超出即拒绝 |
| certified_max_input_tokens | 必须覆盖规定图片处理和全部提示词的真实计费输入上界，不能用平均值或字符估算替代 |
| input/output_micro_per_million | 已审核费率，以人民币微单位记录，必要的汇率转换也须由冻结费率版本覆盖 |
| per_request_ceiling_micro | 覆盖完整输入/最大输出成本，调用前原子预留；实际回执越界会暂停同一合同 |
| no_charge_http_statuses | 仅填供应商确有“未收费”依据的状态；默认空，错误响应不自动释放费用 |

当前协议使用 OpenAI Chat Completions 图片输入和 json_schema 输出形式。使用兼容网关也须单独验证参数与计费，不能假定所有接口支持 store、max_completion_tokens 或同样的图像计费。[官方图片输入说明](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)、[官方结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)。模型名称、价格和能力没有填入未经验证的默认值。

代码检查协议结构、配置匹配、有效期、输入尺寸/字节和响应用量；费用硬上界依赖经验证的供应商输入/计费保证，人工把 state 改成 ADMITTED 并不能证明该保证。真实质量、费用和准入门槛仍按开发18及全量验收执行。

## 识别与恢复时序

1. API固定照片集、模型/协议摘要，创建分析任务和180秒截止。
2. Worker检查照片归属、当前版本、实际文件SHA，生成不含EXIF的受控JPEG识别副本。
3. 在数据库事务内校验阶段租约，按本人/中国业务日的独立平台成本域预留上界，并写唯一供应商意图；该费用不记入尚未存在的付费订单。
4. 提交真实图片字节。返回结果写入确定性私有回执对象，再以用量和冻结费率结算，记录回执/合同摘要。
5. 模型输出必须通过本地结构、照片范围、证据、事实/OCR、归一化框及商品身份检查；最多一轮已完成结果的内容重试，继续占用同一日平台上限。
6. 最后在租约校验事务内再次检查照片集未变，才提交商品档案与身份锁。期间换图/删除不能被旧识别覆盖。

网络断开、取消或无法确认完成时，成本保持UNKNOWN。对于当前不可查询的 store=false 协议，接管者只检查原私有回执，绝不重新POST同一请求；没有可验证回执则等待原截止后失败，未决成本仍保留对账。新建会话或接管不重置费用和重试次数。

回执对象已写而数据库未提交时，新Worker可按原确定性对象键补录回执，关闭对象存储与数据库之间的提交窗口。已登记回执摘要不一致会被拒绝。所有回执私有，不记录到普通运行日志。

## Worker 与工具边界

阶段和 outbox 均有45秒租约、周期续期与递增代次。执行器只领取已注册类型，提交时再次校验；失去租约会向当前动作发送取消，旧结果不得覆盖新执行。维护扫描独立运行，长调用期间仍能发现其他超时订单。

到期扫描与原领取流程独立：已付超时订单终止阶段、撤销网关能力、记录唯一原单退款请求与释放事件；未付款到期只关闭本地履约窗口并查询原交易，不把超时当未付款证据。晚到账仍沿用原单退款。

工具从入队到执行/提交均核验角色、阶段、实例/阶段代次、快照、封存包和调用摘要。多个 capability 共用同一 run 的原子调用额度。内容暂存工具只写当前run检查点，不能直接改变阶段成功、付款、预算或交付状态。

当前角色退出已有撤权、原生隔离器清理调用及独立回执检查，测试使用明确替身；实际原生隔离器可执行程序、独立释放/孤儿消费者、隐私删除消费者、真实模型账单对账及全阶段处理器仍未完成。不以“事件已写入”或测试替身回执声称生产释放或删除完成。
