# 私有对象登记与媒体物理回收

2026-10-28｜需求 v3.1 / 开发契约 v1.1｜受控对象删除已实现，完整隐私删除与生产准入仍未完成。

本专项补齐实际照片、成品、QC 证据和私有回执的写入登记、撤权、删除队列和到期执行。它继续服务完整双小程序与三路线目标，不缩减原需求。文件删除成功不能替代主库私有内容脱敏、供应商/复制副本处理或备份恢复删除标记重放；隐私请求当前保持 `PARTIAL_BLOCKED`，不得宣传完整删除已通过。

## 写入与撤销边界

六类现有写入点已统一登记：照片上传、图片/视频/文案产物、媒体操作清单、视觉识别回执、Codex 推理回执、QC 证据。对象 I/O 发生前必须已有 `WRITING` 记录和不可更换的租户、用户、商品/订单/资产/运行、对象键、类型及 SHA。

对象写入结果分为 `STORED` 与 `UNKNOWN`；有数据库检查点失败也能找到登记记录。`WRITING/UNKNOWN` 不自动覆盖重写，不把“当前查不到文件”当作永远不存在；后续专项已增加UNKNOWN原字节核对；WRITING和缺失/摘要不符仍保留未决。普通迟到写入在完成后重查到撤权，将记录置为 `STORED + delete_requested`，对业务返回 410。迟到计费回执允许受控落盘，以便原费用结算，不复活商品或制作权限。

隐私入口在同一事务内完成：

1. 冻结本次商品、订单与资产集合；有排队/制作订单时要求已有在途确认。
2. 标记商品删除，撤销订单媒体访问，取消未交付阶段并递增执行代次、撤销角色能力、请求实例释放。
3. 已确认付款的未交付订单只创建一份退款请求；不把请求退款当成已经到账。已交付订单保留原资金与履约事实，但停止媒体访问。
4. 标记资产、写不可变删除标记并排入对象删除；撤回相关商品、上传、计划、预览、报价、下载及保存会话的幂等私有响应。
5. 已删/过期商品与档案查询返回 410，商品列表不再列出；必要交易查询继续保留。

锁顺序为用户媒体事务锁 → 订单 → 商品 → 资产 → 对象。幂等操作与隐私处理也经过该用户锁；付款和删除互斥，不会先删图再把它作为有效冻结输入延期。账户媒体删除只处理请求时的集合与此前记录，后续新建商品不受旧请求追扫。

## 删除、失败与保留期

后台每 60 秒扫描到期与待处理隐私请求；逐个领取可删除对象。删除租约为 60 秒、每 10 秒续期，失败等待 60 秒重试。回写核对用户、写入代次、删除代次、执行者及有效租约；旧执行者迟到不能覆盖新结果。

每次有效删除尝试追加 `object_erasure_receipts`，不能覆盖旧失败回执。清理适配器必须同时证明当前对象与全部历史版本已不存在；只有普通 `delete()` 的适配器不会被当成完成。回执仍处于 SUBMITTING/UNKNOWN 或相关费用预留未结清时，暂缓删除，不释放未知成本。

本地删除只访问登记的精确键及本地上传函数生成的同键临时文件；逐层拒绝符号链接/junction，保留相邻文件和其他用户内容。不是遍历整个租户目录删除。

OSS 流程为普通删除停止当前访问 → 按精确前缀分页列出版本/删除标记 → 仅删除完全相同 Key 的全部 versionId（包括字符串 `null`）→ 再次列举并 HEAD 核验。版本超过界限、游标不前进、响应结构不完整或缺少权限时均留待重试，不出完成证明。响应最多 2 MB、每页最多 999 项、最多 20 页和 1,000 个目标版本；固定 HTTPS、不跟随重定向。

旧系统数据从数据库已知定位登记：输入资产、产物、QC 证据、未提交操作清单、预览和已结算的识别/推理回执。不会扫描整个桶猜测归属。未结算外部请求保留待对账，不占位截断迟到费用回执。

到期执行会终止过期商品访问、登记/回收旧照片、撤销到期交付媒体，并保留交易事实。扫描在锁内重新读取期限，尊重已付款冻结照片延期和交付领取期；不因过时的扫描候选删除刚延期的输入。付款延期同时覆盖相应原始对象和商品识别回执，交付对齐订单对象保留期。

## OSS 官方依据

普通删除在版本化桶中会新增删除标记，永久删除需要指定版本，删除指定版本需要相应权限：[DeleteObject](https://www.alibabacloud.com/help/en/oss/developer-reference/deleteobject)。

版本清单包含历史版本和删除标记，支持双游标分页；该列举操作本身计入 OSS 请求费用：[ListObjectVersions](https://www.alibabacloud.com/help/en/oss/developer-reference/listobjectversions)。因此关闭模型/支付制作开关不等于真实 OSS 维护没有运维费用。

当前沿用既有 V1 适配并补充 `versions/versionId` 子资源签名；真实签名与生产接入仍须账户实测。官方建议采用 V4，升级/STS 属于后续生产准入工作：[签名规则](https://www.alibabacloud.com/help/en/oss/developer-reference/include-signatures-in-the-authorization-header)。
