# 本人预览执行与私有恢复

2026-10-28｜需求 v3.1 / 开发契约 v1.1 / C 设计 v1.0｜实现范围：原图方案的可选首图预览。整体产品继续 IN_PROGRESS。

## 用户入口与交付边界

支付宝和抖音的“确认素材清单”页面共用本人预览组件。用户可直接继续查看费用，也可先生成自己商品的首张图片示意。预览明确显示“本人预览 · 非最终素材包”，使用当前完成计划的首图、标题、文案和风格，缩放至最大720像素宽并加入独立说明区。正式订单仍执行四阶段Codex与独立双复核。

生成受理后轮询QUEUED/GENERATING，READY后申请300秒授权链接并查看实际PNG。客户端保存账户范围内的previewId；返回页面查询原预览，丢失受理响应可使用原意图重放。相同有效计划返回原记录，不另扣额度。链接不保存到本地恢复记录；查看失败可重新获取。字体和版式沿用既有资源，C冻结设计稿保持不变。

当前适配10个官方原图风格及已有受控风格映射；生成式本人效果预览、额外资源及复杂社区版式继续待接入。生成式方案受理返回明确能力错误，保持无额度和付费副作用。不能将原图示意描述为已生成的AI场景、人物或视频。

## 冻结与额度

`createOptionalPreview`在事务内先获得媒体所有者锁，再核对本人READY计划及当前商品版本。冻结计划/照片集/档案/商品锁/源方案摘要、风格、资源许可、执行器版本和绝对到期，保存input_hash后创建PREVIEW持久阶段。

同版请求串行化并复用24小时内的原预览；每日新预览额度为Asia/Shanghai业务日5次，原子递增。已存在的预览查询与领取、已购订单制作不消耗此额度。预览创建不延长原图、商品和计划的保留期，也不创建订单或占用订单预算。有效期取受理后24小时与当时商品保留期的较早者，制作绝对截止不超过120秒及原有效期。

PREVIEW使用已经完成的内容计划和确定性媒体工具，无新增模型推理、生成视频或收费供应商调用。正式订单的预算、价格和能力准入保持各自持久合同。

## 实际执行与恢复

`OptionalPreviewService`注册到独立Worker。执行前及提交时核对owner、原计划、商品当前照片版本、全部照片集合摘要、资源许可、阶段租约与递增代次。实际读取选中照片并核对SHA，再用固定OFL字体及原版式生成PNG；解码检查实际尺寸和去除元数据。

在对象I/O之前，先持久化输出意图：确定对象键、SHA、字节数、宽高、来源asset/slot及input_hash。`private_object_writes.preview_id`将实际写入绑定预览、商品和所有者，写入仅一次。对象键固定为tenant/previews/preview_id/preview.png。

原写入已STORED时读取并核对原字节；WRITING/UNKNOWN只等待原调用/原键核对，不重复PUT。独立媒体维护器核对UNKNOWN原文件后，下一租约可继续完成同一检查点。输出意图、归属、绝对有效期及已完成对象位置均由数据库不可变约束保护。

READY与阶段SUCCEEDED同事务提交；提交前再核对登记状态、实际字节及活租约。旧Worker、到期阶段、输入变更、被撤销资源和损坏文件均不能发布READY。旧计划仍保留自己的状态，预览失败不把原计划或订单标失败。

## 访问与撤回

状态和链接接口核对账户归属；链接及实际下载均核对当前商品/计划、冻结摘要、资源许可和有效期。下载读取实际PNG，检查登记字节数及SHA，并在发送前再次复查授权。预览能力票据的itemId必须等于该previewId。

隐私删除持媒体所有者锁，停止相关PREVIEW阶段并递增代次，将预览标FAILED、私有文件请求物理回收。写入期间删除仍保留登记；迟到PUT最终变为STORED且delete_requested=true，由独立媒体维护器删除实际字节。新增private恢复载荷随optional_previews纳入现有33表逻辑脱敏，不保留原文案/源计划副本。

截止扫描对PREVIEW使用owner→预览→阶段的锁顺序，避免与提交和删除交叉持锁。自然对象到期仍按原保留期回收；公开社区样例的单独授权和既有已售订单不归预览额度管理。
