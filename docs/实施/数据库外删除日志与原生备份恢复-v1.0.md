# 数据库外删除日志与原生备份恢复

2026-10-28｜需求 v3.1 / 开发契约 v1.1｜受控日志、恢复门禁与原生 PostgreSQL 恢复演练已实现；完整隐私、财务恢复和生产灾备准入仍未通过。

本专项承接[主库脱敏与原回执](主库私有内容脱敏与原回执对账-v1.0.md)。数据库恢复到删除前的备份时，旧行和旧文件可能重新出现，不能仅依赖同一备份里的删除标记。目标是在恢复流量之前，从数据库备份之外核验并重放原授权删除范围。

## 写入、签名与失败语义

日志只保存删除所需的内部归属、原请求 ID、原时间、范围及冻结集合，不保存照片、商品文案或密钥。它仍属于敏感运维数据，不能放进公开构建包或普通日志。

每条记录包含递增序号、前条摘要、冻结意图及独立 HMAC 签名；head 绑定 source_id、key_id、最后摘要与序号。单条集合及读取大小有上限，完整核验拒绝缺项、分叉、篡改、错误来源或旧检查点。达到日志容量上限时拒绝继续写入，需要另行完成受控归档轮换。

追加同时持有数据库事务级锁与独占文件写锁。先以排他创建、fsync 和 head 替换保存外部日志，再写数据库不可变回执和检查点，最后由调用方提交删除事务。外部日志失败时数据库事务回滚；日志已落盘、数据库未提交时，两个检查点不一致，服务保持阻塞，之后重放原授权意图。不能把这种情况简单当作删除未发生而丢弃日志。

数据库和文件系统没有被宣称为同一原子事务。中途遗留 writer.lock、未封存条目或损坏文件可能使恢复继续阻塞；目前没有自动清除残留或修补日志的功能。运维须隔离所有写入进程、留存原文件并核对独立检查点后处理，不能通过删除记录、重建空 head 或手动改库制造就绪状态。

逐层拒绝符号链接/junction，并使用固定项目 runtime 子目录。文件 fsync、普通目录检查和测试通过，不证明 Windows 断电持久性、目录元数据落盘、受限身份 ACL、磁盘故障或远端副本耐久性。

## 配置与首次切换

示例键见[.env.example](../../.env.example)：PRIVACY_JOURNAL_ENABLED、DIRECTORY、SOURCE_ID、KEY_ID、HMAC_KEY。开发默认关闭；生产配置强制要求开启并提供独立于服务签名密钥的保护密钥。目录始终位于本项目 runtime 内，由运维配置单独 ACL、持久卷或备份策略；不得在恢复数据库时覆盖这份日志。当前本地目录不等于已具备异地灾备能力。

首次切换须停止业务和制作进程，在受控环境注入配置并启用日志，然后运行：

```powershell
./scripts/run.ps1 privacy:journal initialize
./scripts/run.ps1 privacy:journal status
```

initialize 导出现有删除请求与标记，全部追加完成且内外检查点相符后才标记 initialized。非空旧日志丢失、签名不符或数据库检查点不一致时不能重建空日志。重新执行初始化不会清除已经存在的财务恢复阻塞位。

status 只输出来源、序号、检查点摘要、就绪与错误代码，不输出日志正文或密钥。首次初始化不产生财务恢复阻塞；真正的重放会产生该阻塞。

## 恢复顺序与开放限制

1. 停止业务、制作和工具消费，核对数据库备份来源；由运维从独立保存的最新日志核验并固定 head SHA256。不能从待恢复数据库或旧备份推算“最新”。
2. 运行 block 固定外部阻塞文件后，在隔离环境恢复数据库与对象。即使数据库也恢复了旧 initialized=true，外部阻塞与检查点比较仍拒绝访问。未部署独立日志的旧环境必须保持入口隔离，不具有自动恢复保障。
3. 使用同一外部摘要执行 replay。先验全部签名和链，再按原商品/订单/资产集合和原时间提交重放事务；每条同时写不可变重放回执。备份中不存在的原用户/商品记录为 no-op，不凭空重建业务。重复执行不扩大原范围，也不把账户删除时间之后的新商品纳入旧请求。
4. 独立 media-maintenance 核对原对象/费用回执、撤权、实例释放、受控对象删除及32表在线内容脱敏。未知副作用不被释放或重购；该维护不依赖制作进程成功退出。
5. finish 重新核验完整日志、全部重放回执及受控对象/数据库清理状态；缺项继续阻塞。通过后只完成受控隐私收尾，并保留 financial_recovery_required=true。

```powershell
# 将占位符替换为运维在数据库备份之外核验并保存的最新64位摘要。
./scripts/run.ps1 privacy:journal block --expected-head-sha256=<最新独立检查点>
./scripts/run.ps1 privacy:journal replay --expected-head-sha256=<最新独立检查点>
./scripts/run.ps1 privacy:journal finish --expected-head-sha256=<最新独立检查点>
```

编译后可使用 start:privacy-journal 传递相同参数。健康探针 healthz 仍用于进程/数据库存活判断；readyz、业务、媒体和受控推理入口在恢复未完成时返回维护状态，Worker 和工具也不领取新生产动作。

隐私重放不能恢复备份之后丢失的付款、计费意图或 UNKNOWN 请求。当前没有经验证的财务恢复和解除功能。因此，隐私收尾后只允许非生产、支付/生成/Codex 三类开关全部关闭的预览；生产或任一付费开关开启时继续 FINANCIAL_RESTORE_PENDING。不能把 finish 当作恢复收费服务的授权。
