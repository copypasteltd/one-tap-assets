# 完整展示文字与购买前排版校验 v1.0

本专项修正实际素材中的文字丢失与断言漏检，不改变需求 v3.1、开发契约 v1.1、官方 10 风格 / 14 变体或 C 设计原件。完整产品、真实服务、生产与云端准入仍未完成。原任务恢复、售后修改和交付前自动修复是不同功能；本专项不实现自动修复。

## 问题与证据

在提交 `6cd0319ed1ba7209cafc32830456fa28b9e86996` 的源码上，以项目自绘纯色图和原生 Sharp 复现两项问题：

1. `shots[].intent` 会绘制为原图短片字幕，原计划断言检查只覆盖标题、配套文案、图标题与口播，遗漏这部分实际可见文字。只在 intent 中加入无证据的“治疗失眠”仍能通过。
2. 旧换行器按字符宽度近似并在达到行数后停止；超过容量的文案会丢失后缀。151 字标题和配套文案分别以“甲”“乙”结尾时，两个实际 PNG 的 SHA 完全相同，证实末尾没有进入图片。

原控制的源码摘要、PNG 摘要与验证边界随[回归记录](../../assets/implementation/regressions/visible-text-layout.json)留存。该控制没有浏览器、客户照片、付费模型或支付请求。新测试还检查实际章节、页脚、AI 标识与标题/字幕的安全距离。

## 实现与调用边界

| 编号 | 位置 | 行为 |
| --- | --- | --- |
| T01 | `src/worker/compiler/plan.ts` | 实际可见的 intent 纳入原高风险断言检查；无观察证据的价格、规格、效果词同样拒绝。 |
| T02 | `src/worker/media/text-layout.ts` | 使用固定 Noto Sans SC / OFL 字体实际栅格化和测宽，按 Unicode grapheme 换行，转义 Pango 标记，检查全部字形与完整后缀。 |
| T03 | `src/worker/media/layout.ts` | 标题最多两行；配套文字方图最多两行、竖图最多三行。按实际行数扩展上下安全区，商品图片使用剩余区域，不缩小字体、不加省略号、不截断。 |
| T04 | `src/worker/media/plan-layout.ts` | 以同一个排版器预检全部图片槽位；原图短片逐镜检查实际绘制的标题与 intent。社区方案使用冻结的 `platform_style_id`，否则使用原请求 preset ID。 |
| T05 | CONTENT / quote / PRODUCTION / POST | 规划验证与持久化、发布报价、启动制作角色/购买生成参考前，以及受控媒体工具内重复预检。报价同时核对完整 creative SHA 与原 plan hash。 |
| T06 | 原媒体操作恢复 | 升级制作器版本；同一阶段/phase 锁定原输入。已有不同 input hash 时返回 `MEDIA_INPUT_CHANGED`，不创建第二个媒体操作，不替换原回执。 |
| T07 | 原始方案选择 | 内容工具使用真实创建流程保存的 `PlanRequest.preset_id`；历史记录缺少此信息时返回 `PLAN_INPUT_CHANGED`，不从变体名猜测风格，也不替换原阶段结果。 |

标题、章节、配套文字和页脚使用实际 PNG 字形边界检查画布范围与彼此重叠。生成图另外避开冻结的左上 AI 标识；原生视频已有右上字幕策略保留。空白只为画面统一换行符/制表符/连续普通空格，完整 copy 文件仍保留原 UTF-8 文本。

测宽按每行实际字形宽度二分查找完整 grapheme 前缀，检查拼接结果等于规范化后的完整文字。单次展示文案限制为 1,000 grapheme；现有 JSON Schema 长度上限仍生效，但不再被当作实际可排版容量。不能承诺“任何 200 字标题都能排下”。

短文案（最多64个grapheme）先实际栅格化完整一行，确认宽度可容纳后复用该 PNG，避免正常短标题/配套文案仍反复测量多个前缀；放不下时继续原完整二分换行，全部字形检查在这条路径前完成。28次原生对照的PNG字节、完整文字、尺寸及超长/缺字错误码保持一致。记录的单次耗时不是统计基准，也不证明原测试超时的根因。

## 用户逻辑与费用

用户仍只拍照、选社区预设；内容角色依据有证据的档案生成合适长度的标题与配套文案。验证工具报告超长或缺字后，角色只能在原次数、费用、截止和权限内调整，再次验证。没有额外的用户填表步骤，也不自动新增一次付费推理。

在正常新规划中，只有有效完整计划才可进入 READY；报价再次校验，防止历史或被篡改的计划绕过。制作入口在新角色及任何生成参考购买前检查，媒体工具还会再次检查。预检本身仅调用本地固定字体与 Sharp，不访问模型、支付或供应商。它不撤销已经发生的合法内容规划费用，也不保证任何故障都可自动修好。

| 错误码 | 含义 | 处理边界 |
| --- | --- | --- |
| `UNSUPPORTED_CLAIM` | 展示/口播含原观察无法支持的受控高风险断言 | 依据证据改写；不能将 OCR 标签或猜测升级为事实。 |
| `FONT_GLYPH_UNAVAILABLE` | 完整文案含固定字体不支持的字符，包括旧截断处之后的字符 | 改为字体支持的原意文案，不静默调用系统回退字体。 |
| `LAYOUT_TEXT_OVERFLOW` | 完整文案超过行数、宽度或安全区域 | 报价前缩短；不在输出中丢字或降字号。 |
| `LAYOUT_TEXT_OVERLAP` | 文字与其他文字或 AI 标识实际边界重叠 | 阻断该排版，不以技术文件有效替代画面有效。 |
| `LAYOUT_TEXT_INCOMPLETE` | 换行拼接未保留全部规范化文字 | 内部错误，拒绝输出。 |
| `MEDIA_INPUT_CHANGED` | 原媒体操作与当前制作输入/版本不同 | 原操作保持原样；不自动改键重做、重买或补写历史证明。 |
| `PLAN_INPUT_CHANGED` | 原规划记录缺少用户选择的 preset ID | 重新选择方案；不补造历史输入或覆盖已保存结果。 |

制作器为 `YPCC-PHOTO-PIPELINE-1.2.0`、`YPCC-GENERATED-SILENT-1.1.0`、`YPCC-NATIVE-ORDER-PIPELINE-2`；本人预览为 `YPCC-OPTIONAL-PHOTO-PREVIEW-1.1`。已有不同版本的订单/预览不得被当作新版本验收完成。尚无完整历史订单迁移与自动素材修复服务。

## 验证与媒体

新增 1 项单元与 5 项原生专项，包含：字幕断言负例及有观察证据正例；原截断控制；末尾缺字；中文/Latin/标记完整换行；十套风格方图和竖图 20 个实际 PNG 的全部不透明字形像素、末字和商品区域检查；规划拒绝后状态/报价/角色/供应商提交计数；版本变化保留原媒体操作。既有十风格与实际 30 帧 FFmpeg 测试保留。

全套检查还暴露了旧内容工具夹具漏存 `PlanRequest` 的问题：实际创建流程会保存该输入，手工夹具没有，导致 `analyze_photos` 返回内部错误。已补齐夹具，并在原成功用例中加入历史输入缺失的明确拒绝断言，核对原输出摘要、结果和父阶段没有被替换。该修正不提供历史数据自动迁移；完整失败与复查记录单独保留。

完整执行结果以[实现清单](../../assets/implementation/current.json)和[验证来源](../verification/README.md)为准；不能用定向测试中的 skipped 或异常退出后的部分报告代替整套通过。一次定向测试出现 Windows 原生进程 `0xC0000374`，同源码复查通过，根因与生产长期稳定性尚未确认，不放宽断言或时间上限。

完整执行也保留参考核验未持久化、原180秒类型检查超时，以及参考成片交付后有一个实例未释放的失败记录；单例复查通过不证明这些原失败的根因。释放检查已增强为保留未释放实例的角色、状态和清理错误码，仍要求结果为空，不允许手改状态通过。更早失败的详细行状态已随测试schema清理；旁路只读诊断自身超时、没有收集到观察，也不作为通过证据。生产稳定性继续待验。

另一次完整原生执行14项通过后，在“撤销声音许可后拒绝QC封存”用例达到原120秒上限；完整结果仍判失败。后续短文案复用只减少重复栅格化，不更改该上限、拒绝条件、费用或隔离要求；最终完整结果和定向复查分别绑定来源。

短文案复用后的第七次完整执行仍失败：13项通过后，“撤销原文件写入授权后拒绝QC封存”用例达到同一120秒上限。随后仅增加测试诊断，记录原始阶段的开始、结束、耗时、进程内存及Sharp缓存；没有减少媒体帧数、跳过断言或放宽期限。定向执行同样超时，记录到准备约9.5秒、制作约42.4秒、后期约68.5秒，未进入QC准备；另一个选中的声音许可用例未执行。该次失败不能算通过，也不能证明只因整套累计运行或已找到根因。诊断原始文件留在忽略的runtime目录，对外只发布去除业务载荷的阶段摘要及文件SHA。

第八次完整执行仍为13通过/1超时；同一文件另9项未执行、其余34个集成文件未完成。该次记录准备/制作/后期约14.8/50.1/56.4秒，仍未进入QC准备。类型与71项单元通过；之后按同一341份源码及原时限单独执行的服务端/支付宝/抖音构建通过。它们不能替代失败的完整原生执行。当前发布检查继续阻断，Git仅同步明确标注限制的源码进度，不表示云端部署、启售或完整产品交付。

[标识示例](../media/ai-disclosure/README.md)已由同源码实际重新生成，图片演示完整长文案和末字，原生视频/GIF仍是自绘商品静帧。浏览器页面与声音内核没有变化，沿用其原有捕获来源；C25 文件和归档保持原 SHA。

## English implementation contract

Visible shot intent now shares the existing evidence-based high-risk claim gate. All rendered titles/copy use measured pinned-font glyphs, grapheme wrapping and full-suffix validation. Text either fits in its complete allowed line count or is rejected; it is never silently truncated, ellipsized or shrunk. Actual text rectangles clear each other and the frozen AI mark. Original UTF-8 copy-file bytes remain intact.

Short copy first measures a complete raster and reuses it only when its actual width fits; otherwise the same full wrapping search runs. A 28-call native control preserves exact PNG bytes, text, dimensions and rejection codes. Its observed timing is not a statistical benchmark or proof of a prior timeout's root cause. The original 120-second revoked-license QC limit remains unchanged.

The identical renderer preflights persisted content, quotes and media execution before new production roles or generation-reference purchases. Community styles resolve from their frozen platform style mapping. Quote compilation rechecks the complete creative hash. Renderer versions advance, and an existing media operation with different inputs blocks without replacing the original operation or buying again.

Content tools resolve the original selection from the persisted PlanRequest. Missing historical selections now fail explicitly with PLAN_INPUT_CHANGED; no style is inferred from a variant name. The legacy manual fixture was aligned with real creation inputs, and the same case verifies that rejection preserves the original result and running parent stage. This is not a historical migration service.

Tests use actual native PNG/FFmpeg/PostgreSQL plus explicit synthetic business/model controls. One focused native process exits with `0xC0000374`; the unchanged retry passes, without establishing a root cause. Complete test/build results and exact source bindings are published separately. Updated self-drawn disclosure media demonstrates complete wrapping, not real generative quality or host certification. Bounded automatic repair, complete historical migration, real semantic review, provider/payment/isolation admission and full-product acceptance remain incomplete.

Incomplete full runs also retain a missing reference result, the original typecheck timeout and one unreleased instance after reference-film delivery. Focused retries pass without proving those root causes. The release assertion now records role, state and cleanup error codes while still requiring no unreleased instances; a separate read-only diagnostic timed out without collecting observations. Production stability remains unverified.

The seventh full attempt still times out after 13 passing cases, despite the short-copy raster reuse. A diagnostic-only focused run also exceeds the unchanged 120-second limit before QC preparation: setup approximately 9.5 seconds, production 42.4 seconds and POST 68.5 seconds. The other selected case does not execute. These phase observations neither establish a root cause nor prove cumulative-suite-only slowdown; failed attempts remain failed. Diagnostic traces contain no published customer payloads, and neither assertions, actual frame counts nor deadlines are reduced.

Attempt eight also ends at 13 passes and one timeout, leaving nine cases in that file and 34 other files incomplete. Setup/production/POST take approximately 14.8/50.1/56.4 seconds before QC preparation. Types and 71 unit tests pass; the same source subsequently passes separate server, Alipay and Douyin builds under the existing caps. Those builds do not replace the failed native suite. Publication stays blocked; Git synchronizes explicitly limited source progress without deploying or admitting sales.
