# 主库私有内容脱敏与原回执对账

2026-10-28｜需求 v3.1 / 开发契约 v1.1｜受控主库逻辑脱敏、UNKNOWN 原文件核对及退役会话回执对账已有源码和专项测试。完整产品与完整隐私删除仍未通过。

本专项承接[私有对象登记与媒体回收](私有对象登记与媒体物理回收-v1.0.md)，不改变双小程序、三条制作路线、58项需求和真实服务验收范围。数据库 UPDATE 证明在线内容字段已经替换，不证明旧磁盘页、WAL、备份、复制库或供应商副本已物理擦除。

## 独立维护顺序

`dev:media-maintenance` / `start:media-maintenance` 在原生 Node 进程内独立运行。每60秒按以下顺序维护，不需要开启付费制作，也不需要有效的买家角色能力或模型密钥：

1. 核对已返回 UNKNOWN 的原对象写入；只读原键并检查写入前登记的 SHA，不发起新 PUT。
2. 核对已保存的视觉与 Codex 原回执，按原请求冻结的合同、费率和预留结算；不调用新模型请求。
3. 执行保留期及隐私范围扫描，登记旧文件定位、排队永久删除。
4. 所有受控对象已删除且运行/费用门禁通过后，分批替换数据库私有内容；最终隐私请求仍保留备份和外部副本门禁。

原回执先结算，再删除回执文件和费用恢复参数。换用当前模型、当前价格或新会话重新购买，都不属于恢复。

## 对象写入恢复

`src/api/storage/private-objects.ts` 将同一对象键视为一次性、内容不可变的写入。相同归属和摘要的已存对象重放直接返回，不再次 PUT；不同摘要、删除中或已经删除的对象拒绝重写。这避免旧写入在删除后再次提交同一键。

`reconcileUncertainObjectWrites` 仅领取 UNKNOWN，按原写入代次检查实际完整字节。摘要匹配后恢复 STORED，保留已有 delete_requested；不复活产品或业务权限。没有文件、读取失败、文件超过读取上限或摘要不匹配，继续保留 UNKNOWN。WRITING 可能仍有活跃调用，不由该扫描器推定完成；进程崩溃遗留的 WRITING 仍需要额外终结证据，不能宣传所有未知写入已解决。

## 原费用回执

- 视觉：`VisionAnalysisService.reconcileReceipts` 通过原 ANALYSIS 阶段、商品/所有者及对象登记连接定位，核对对象 SHA、冻结合同摘要与原响应费用。当前配置变更或生成开关关闭不会阻止历史费用核对。对账只结算，不发布被取消任务的商品档案。
- Codex：`InferenceGateway.reconcileReceipts` 通过原 run、私有回执键和登记 SHA 定位，使用原 admission 和预留 token/费用核对 SSE。实例 RELEASED、角色撤权后仍可结算；不会把回执交还旧能力。
- 两类结算均在事务中锁定原请求。重复或竞争对账不会重复计费；不存在完整回执、摘要不符或费用证据不足时保留未决费用。视觉响应已处理但计费仍不可信时记 blocked，不计入已结清。

## 主库授权脱敏

迁移 `015_private_content_redaction.sql` 新增关系作用域视图和 `privacy_redactions`。归属从商品、计划、报价、订单、阶段、实例和运行的关系字段解析，不依赖即将删除的 private JSON。

覆盖32张内容表：商品、资产、照片集版本、档案、身份锁、纠错、识别及尝试、计划、场景/分镜/参考帧、预览、报价、订单、执行快照、制作任务/阶段、供应商请求、实例/运行/工具/推理、媒体操作、产物、QC、审查包/报告/证据、交付清单、修改请求和支持请求。

只替换固定白名单内的 data/private/spec_json 内容字段，写入 privacy_deleted 标记；订单保留 media_revoked。交易金额、支付/退款状态、预算及实际成本、关系标识、原执行/商品/媒体摘要不被该路径改写。操作性、交易性字段依其原职责保留；这不是删除全部账户身份或授权审计数据。

每一行先写不可变回执，记录匹配的删除标记、作用域、字段列表和替换前后摘要，再替换内容。摘要算法明确为 `postgres-jsonb-text-utf8-sha256-v1`；事务固定 UTC，整行在 PostgreSQL 内计算，不经 JavaScript 浮点数往返，也不在回执保留原文。

数据库会验证标记归属、实际撤权、白名单字段和两个摘要。原不可变快照触发器仅允许这一精确替换；不关闭触发器、不放开普通修改。延迟约束保证回执与内容替换在同一事务提交；跨用户标记、错误摘要、仅登记回执不删除内容均不能提交。

已有脱敏回执后，不得重新写回私有字段。删除范围也拒绝新建生产/识别派生内容。用户后续主动新增的支持通信作为新操作保留到下一次维护脱敏，不作为制作任务恢复入口。

## 门禁、批次与读取

`privacy-redaction.ts` 由持有用户媒体锁的维护事务调用，每批最多500行。以下任一条件不满足时保留恢复载荷，并列出具体阻塞原因和实际剩余行数：

- 商品/订单已撤权，受控对象均已删除。
- 关联实例全部 RELEASED，角色能力均已撤销，制作阶段已终止。
- 工具没有 QUEUED/RUNNING/UNKNOWN，推理及供应商费用已结清。
- 平台/订单预算不再存在相关 RESERVED/UNKNOWN。

已完成行靠不可变回执跳过；后续批次继续相同作用域。原报价和修改读取在 DTO 转换前检查商品/订单撤权，返回410；不因内容已替换而变成500。必要订单/支付/退款查询继续有效，删后迟到付款只记资金事实并请求一次退款，不创建新执行快照。

隐私结果记录 controlled_media.database 的 BLOCKED/PENDING/REDACTED 和行数。数据库 REDACTED 只移除 PRIVATE_DB_REDACTION_PENDING；BACKUP_REPLAY_PENDING 和 PROVIDER_COPY_BOUNDARY_PENDING 继续保留，请求仍为 PARTIAL_BLOCKED。
