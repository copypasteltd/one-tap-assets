# 生成服务持久调用与媒体转存

2026-10-28｜需求 v3.1 / 开发契约 v1.1 / C 设计 v1.0｜应用仍为 IN_PROGRESS。

## 1. 实现范围

新增火山方舟图片、视频协议适配及内部 `GenerationGateway`。它提供真实 HTTP 出口代码、持久购买意图、原视频任务查询、原订单成本结算、私有回执恢复与实际媒体检查。尚未调用真实模型或确定生产模型、费率、商用能力；测试使用合成供应商响应与真实 PostgreSQL、文件、Sharp 和原生 FFmpeg。

后续[购买门禁与MCP接入](生成式购买门禁与MCP工具接入-v1.0.md)已补齐两路线强制参考身份绑定、整片参考生成及3个受控工具。该模块仍不是完整生成式制作器；`MediaStageService`继续拒绝尚未实现的生成式编排，也不会将其替换为原图制作。三条路线、四个生成式变体、最终双复核和交付仍为原P0，完整生成式产线未完成。

## 3. 供应商协议依据

协议依据为火山引擎官方的[图片生成 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)、[创建视频任务](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)和[查询视频任务](https://docs.volcengine.com/docs/ark/get-video-generation-task-api?lang=zh)。模型能力和参数支持范围须按具体模型版本核验。

图片使用 `/api/v3/images/generations`，请求明确单图、尺寸、授权参考和 Base64 响应；仅对支持的模型发送显式关闭组图参数。视频使用 `/api/v3/contents/generations/tasks`，区分首帧与多参考模式；接受原任务 ID 后，仅查询该 ID。生成音频、时长、分辨率、比例和执行参数均来自冻结协议及计划。

未发现并验证可以按本地意图安全重购的供应商保证，因此不把客户端请求头当作跨服务幂等证明。提交响应丢失、且原回执无法核对时保留 UNKNOWN 和原预算，不能新建任务冒充恢复。供应商任务的最小执行有效期可能长于平台订单截止，迟到财务回执仍须核对，迟到媒体不自动进入交付。

## 4. 模型与报价冻结

每个生成模型的 `provider_model_versions.private.ark_contract` 保存确切协议。模型登记必须为 ADMITTED，且 `data` 的 provider、actual_model、registry_version、role、rate_snapshot_id、capability_hash 与协议一致。`capability_hash` 是完整协议的既有项目 hash，而不是任意声明字段。

协议包含实际/请求模型名、端点、有效期、能力证据摘要、请求/响应/下载大小、参考数量/像素、媒体域名、确定不收费的 HTTP 状态，以及原费率、最大计费单位和单次成本上界。视频另包含支持的时长、分辨率/比例与实际尺寸对应表、参考模式、原声能力和查询次数/间隔。

当前本地实现边界为请求至多 64 MB、供应商响应至多 90 MB、下载及规范化产物至多 120 MB；实际订单可冻结更小上限。回执 Base64 封装仍落在现有 125 MB 原键恢复边界内。所有数值均为执行边界，不声明供应商对任意模型均支持这些规格。

生成式报价需要唯一图片协议和唯一视频协议。协议保存于 `FrozenContract.generation_contracts`，随原合同 hash 一起固定；快照既有 model_versions 的 capability_hash 绑定相同内容，无需绕过既有不可变执行快照。

报价同时核对图片输出、逐镜参考图、视频次数、Agent、售后及修复成本上界是否落在原订单总预算内。当前尚无已验证的人物/原生声音绑定，因此有声生成式报价明确拒绝准入，不能用静音片或额外 TTS 替代。真实费率和销售能力仍未准入，全部真实付费开关继续关闭。

## 5. 独立出口配置

既有 `PROVIDER_*` 继续用于识别。可通过以下空白示例配置独立生成出口：

```dotenv
GENERATION_BASE_URL=
GENERATION_API_KEY=
GENERATION_ALLOWED_HOSTS=
IMAGE_MODEL_ID=
VIDEO_MODEL_ID=
```

`GENERATION_ALLOWED_HOSTS` 列出确切 API 和媒体域名。显式配置独立生成地址后，空生成密钥不能借用识别密钥；未配置独立地址时沿用既有统一出口模式。密钥只来自服务端配置，不进入模型合同、数据库回执或工具结果。

实际 HTTP 层限制 HTTPS、公网 DNS、批准域名、TLS 验证、响应大小与超时，禁止重定向。视频下载使用冻结 media_hosts 且不携带 API Authorization；供应商 API 凭证仅用于原 API 主机。

绝对购买截止在 DNS/传输开始前就合并进 AbortSignal；不会等 DNS 完成才开始计算剩余时间。超时结果仍按原 UNKNOWN 占用与回执恢复处理。

## 6. 内部执行顺序

1. `submit` 接受原订单 PRODUCTION 阶段租约；校验租约、订单、冻结合同、完整照片集 hash、所选实际照片字节与目标节点。原图路线不能购买生成服务，未出售的输出节点不能扩张调用。
2. 图片节点只对应冻结图片槽或逐镜参考帧；整片视频对应原时间轴和原声约定。逐镜视频在实际参考帧身份复核接通前拒绝执行。
3. 在同一数据库事务持久化原模型、输入摘要、操作标识和购买意图，从原订单预算预留一次费用。相同节点并发由唯一键与锁收敛；输入改变被拒。
4. 请求体作为私有对象登记并写入；实际 POST 前再次检查原阶段与处理租约。记录发送标记后只提交一次，不依赖进程内记忆。
5. 原响应以完整响应字节、状态、请求/合同摘要封装，保存到确定私有键。只有实际登记字节与摘要一致，才解析 ACK、状态和用量。
6. 视频 ACK 固定原 task_id。每次查询预先追加独立回执指针和递增序号；原回执不可替换，查询间隔与次数不会因恢复而重置。
7. 终态用量按冻结费率结算原预留；未知费用继续占用。明确且已经冻结为不收费的提交错误才释放预留。错误模型、额外工具、超界或缺失用量不伪造零成本。
8. 实际媒体先检查，再登记私有产物，最终提交再次核对租约。输出摘要、规格和键保持不可变；还不生成正式完整素材包 manifest。

每个生成操作有独立 180 秒处理租约和递增代次，原制作阶段仍使用其已有租约/续期机制。旧代次即便拿到远端结果，也不能提交当前媒体结果。等待远端任务以持久状态恢复，不持续占用 HTTP 请求。

## 7. 实际文件与恢复

图片检查真实 JPEG/PNG 解码、页数、方向及尺寸；转为去元数据 PNG 后记录其实际字节摘要。不会因为请求期望 PNG 就把供应商 JPEG 标成 PNG。

视频使用原生 ffprobe 检查真实尺寸、帧率、帧数、时长和音轨，并由 FFmpeg 完整解码。原始视频的原生帧率只是中间媒体属性，不能视为最终 30 fps 成品。实际尺寸必须匹配冻结的分辨率/比例尺寸表，时长和原声须符合原请求。

私有写入复用现有“先登记、后 PUT、原键核对”的机制。回执或媒体 PUT 的确认丢失后，不重复 PUT；维护器核对原文件后才恢复。缺失、损坏、WRITING 或摘要不符保留阻塞，不从损坏输出重新购买或重新下载冒充恢复。

取消、截止、隐私撤权或旧阶段接管后，迟到的确定费用仍写回原财务账；不向客户端开放媒体。原请求/回执/生成媒体纳入既有订单、商品和 provider_submissions 的私有删除范围。未决供应商任务及 UNKNOWN 原预算继续阻塞完整隐私收尾，不能因对象已删除宣称处理完毕。

媒体删除器同时识别既有 result_key、新生成 request_key 和全部原回执指针。供应商未终态或原费用仍为 RESERVED/UNKNOWN 时，原请求和回执保持 BILLING_RECEIPT_PENDING，不执行物理删除；原费用结算且任务终态后才能按既有删除意图回收。专项使用独立原生数据库模式及实际文件验证了结算前保留、恢复后删除。修复前的两个红色回归与前一版完整通过记录分别保留，避免用历史通过掩盖新增场景。

`reconcileReceipts` 在收费开关关闭、原模型准入过期或角色进程退役后仍能核对本地原回执。查询远端原任务要求原服务出口仍可用；它不会开启新购买。独立维护器的结果也不代替订单交付授权。

## 8. 验证与剩余工作

专项测试覆盖实际图片/视频、并发唯一 POST、未知购买、回执/媒体 PUT 确认丢失、原视频查询、查询次数与错误、成本结算/占用、独立凭证、错误域名/重定向、实际错误尺寸、冻结内容与终态不可变、旧代次和取消后的财务恢复。测试报告保存在 `runtime/test-results/generation-gateway.json`；全量命令和覆盖边界以 `assets/implementation/current.json` 为准。

生成入口在原客户/订单锁之后，核对数据库中阶段的订单、类型、名称、输入摘要及截止时间；网络绝对截止取已冻结执行快照。同一客户两单的有效租约不能串绑，也不能通过传入更晚的 Date 延长购买。两个修复前回归均曾错误地成功购买，证据留在 `runtime/test-results/generation-stage-binding-red.json`。修复后生成专项共 29 项。另有原生数据库心跳回归检查关系到期值、JSON 到期值与原字段保留，并验证接管、到期和释放后的续租拒绝；该回归不证明真实受限身份或生产进程树隔离。

全量验证曾因 480 秒总时限失败，保存在 `runtime/test-results/attempts/20261028-generation-full-timeout/`。原生 PostgreSQL 日志记录到检查点磁盘同步耗时 448 秒，后续维护检查点仍出现 173 秒同步；当时未见本项目遗留 Node 测试进程，但有两个已无数据库客户端的中断测试模式，已按测试模式精确清理。没有关闭 fsync 或降低断言。前一版 230 项集成全通过只作历史证据，当前版本以最新完整报告为准。

当前源版本完整验证已通过类型检查、50项单元、235项集成、服务端及双小程序构建；集成370.60秒，480秒总时限保持。主库21份迁移摘要一致。原生数据库持久化与原模式清理证据分别记入 `runtime/test-results/native-verification-cleanup.json`；源码、契约、资源及设计留存复核见 `runtime/test-results/final-audit.json`。
