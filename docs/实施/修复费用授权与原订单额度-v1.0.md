# 修复费用授权与原订单额度 v1.0

2026-10-30。需求 v3.1，开发契约 v1.1，C 设计 v1.0。关联 F09、F46、F55；它们的完整验收继续待完成。本次增加交付前修复所需的费用授权组件，不开放新的 HTTP、管理或 MCP 权限。

## 1. 本次实现及边界

此前首轮制作已经保护修复、售后两个保留额，但所有订单付费调用都只能进入首轮费用域。现在四个付费入口根据平台数据库中的实际阶段选择费用域：生成、Codex 推理、整轨转写、独立听音。客户和模型不能传入 `purpose=REPAIR` 来取得额度。

原图、逐镜生成、参考成片共用这一入口。模型、费率、角色轮次、token、工具和原生声音的原有次数检查继续执行。原生转写的唯一原任务、听音的原包上限并未因修复费用授权而放开；目前也没有支持更换音轨后重买这些调用的完整流程。

**尚未接入自动修复调度器。** 新组件不会自动定位问题、改文案/提示词、重制候选、封存新包或取得两个新 PASS。普通订单的失败处理仍执行既有停止/退款逻辑，不能据此启售或标记 F09/F46/F55 完成。

## 2. 平台内部的授权入口

源码：[cost-authorization.ts](../../src/worker/repair/cost-authorization.ts)。未来调度器必须在同一数据库事务内准备新候选的六个阶段，再调用 `authorizeRepairCosts`；任一步失败全部回滚，不得先提交可领取的新阶段。

| 编号 | 授权前提 | 拒绝情形 |
| --- | --- | --- |
| 01 | 已确认付款、仍可执行、未撤权，原截止有效 | 取消、删除、过期、付款状态失效 |
| 02 | 原订单合同/快照完整，两个原保留额仍可用 | 改总额/截止/调用上限，或历史支出已占用保留部分 |
| 03 | 当前首轮 QC 包为 FAILED/BLOCK | PASS、未封存、过时包、不是首轮 QC |
| 04 | 平台重验已完成独立报告、图片/推理/工具/隔离/Skill 证据 | 伪造报告、未提交阶段、摘要不符、证据不足 |
| 05 | 所有原付费调用已核对 | RESERVED/UNKNOWN、未决推理或供应商任务 |
| 06 | 原任务尚未用修复轮次，首轮阶段均已结束或撤销 | 原阶段仍 READY/RUNNING/UNKNOWN 等，或试图再开一轮 |
| 07 | 六个新阶段均为 attempt=2、READY、未领取，串行依赖完整 | 混入旧阶段、旧 PASS、其他订单/任务或另一快照 |
| 08 | 拟额外生成节点属于原制作已完成的同类原操作 | 新增节点、重复节点、原购买 UNKNOWN/失败、超过原总次数 |

六阶段为 `PRODUCTION → POST → QC → REVIEW_FACTS → REVIEW_STYLE → DELIVER`。所有阶段保留原快照和截止。两个复核阶段必须是新阶段；后续真实执行仍须由现有独立身份、材料摘要和交付门禁验证。

`generationNodes` 由未来平台修复计划传入，当前入口只验证节点确属原制作、唯一且在调用上限内；**尚未实现从复核问题语义推导“哪些节点受影响”**。不能把这项结构检查称为问题定位或完整修复计划。

证据不足的报告目前不能获得新费用授权，继续阻断。不得将不足改成 PASS、删除 blocker/major 或覆盖旧报告。未来证据修复策略必须单独实现并验证。

## 3. 不可变费用授权

新增迁移：[026_repair_cost_authorizations.sql](../../src/api/db/migrations/026_repair_cost_authorizations.sql)。

`repair_cost_authorizations` 每个原订单/任务最多一条，记录原包/快照摘要、原修复额、总额外调用上限、原截止、六个新阶段 ID 及已声明的原生成节点。授权不可更新或删除；相同请求只取回原编号，不能以另一个阶段或节点集合重建。

成功授权同时把原任务 `repair_rounds` 与公开 Job 数据中的对应值改为 1。失败事务不消耗轮次。不会创建新订单、支付、售后修改次数或新的服务截止。

该表只保存平台 ID、哈希、金额和操作节点等核算索引，不复制照片、提示词、报告详情、商品档案或凭证。它不属于可恢复媒体载荷；删媒体后索引留作核算，不赋予原订单访问权。新的调用仍逐次检查原订单撤权、租约、模型及许可。主库私有字段和外部副本的完整物理删除准入仍是既有待办，不能由此升级为 COMPLETED。

## 4. 原订单费用如何使用

源码：[reservations.ts](../../src/worker/budget/reservations.ts)。

设原总额为 T、修复保留额为 R、售后保留额为 A，则首轮上限为 `T − R − A`。修复授权不增加 T；交付前制作与修复合计不能超过 `T − A`，修复自身也不能超过 R。

例如 T=100、R=30、A=20：首轮最多 50，修复最多 30，交付前合计最多 80。先用 30 修复并不会把剩余的首轮 50 冻结掉；首轮也不能反过来占用未花的 R 或 A。

每笔订单费用记录新增 FIRST_PASS/REPAIR 用途。修复费用同时绑定原授权、实际新阶段和节点键。原归属、金额、规范化费率与用途不可修改；修复 SETTLED/RELEASED 结果不可回写。历史记录按 FIRST_PASS 保留，不把旧 UNKNOWN 或实际支出重新标成修复。

UNKNOWN 按原预留额计入使用量；原回执核对后只释放实际未使用的差额。即使原调用明确不收费或预留金额为零，该次新增修复调用仍计入原额外调用次数。不能通过结算、释放、重启会话、换新意图或新 Worker 重置次数。

每个已授权 IMAGE/VIDEO 节点最多一次额外购买，同一原意图重放返回原费用编号。即使该额外购买最终明确不收费，也不能再为此节点发起第二次新购买。未知响应继续查原任务。

## 5. 事务、并发与恢复

- 所有用途先锁定同一原订单，再取得原费用意图锁；同订单并发首轮/修复共用同一核算顺序。
- 修复调用必须具有实际当前阶段的租约、代次、原快照、原任务及不可变授权；不能只凭 `attempt=2` 购买。
- 首轮和修复均再次核对数据库阶段的原订单、任务、快照和阶段名；不能把同一用户其他订单的编号放入一个有效阶段租约来扣费。跨租户访问仍由原归属门禁拒绝。
- 等待订单锁后按 `clock_timestamp()` 重新检查原截止，不能用事务开始时间放行已过期购买。
- 原意图只有租户/订单、金额、规范化费率和费用绑定完全一致时才能重放。
- 归属、费用用途和原已关联供应商编号均不可换；允许原记录首次关联其真实供应商提交。
- 结算仍在原订单 `spent_micro`/`reserved_micro` 中完成；不会建立独立可充值的修复钱包。
- 转写、听音、推理和生成各自的原购买恢复、实际账单、模型/许可和额度检查保持有效。费用授权不代表供应商任务获准重发。

## English

This change adds an internal, durable cost authorization for one pre-delivery repair. It does not connect an automatic repair coordinator, produce a changed candidate, seal its new packet or obtain two fresh PASS reports. Existing failure/refund behavior and all sale/admission restrictions remain.

The coordinator port revalidates the original failed packet and completed independent reports, rejects insufficient evidence and unresolved paid calls, checks the original sold snapshot/budget/deadline, and requires six fresh, sequential candidate stages. The single immutable authorization also binds declared original generation nodes. Affected-node diagnosis itself is still missing.

Generation, inference, ASR and listening derive their cost purpose from the actual platform stage and lease. The original total, repair/aftercare holds, inference/token/tool limits, original ASR/listening limits and provider contracts remain. UNKNOWN keeps its obligation. Released and zero-cost extra calls still count; each authorized generation node permits at most one extra purchase. Replaying an original intent cannot issue a second provider purchase.

Migration 026 leaves historical reservations as FIRST_PASS and adds immutable repair cost bindings. Its authorization table contains only financial/technical IDs, hashes and node keys, without source media, prompts or report text. Retaining this accounting index never restores revoked media access.

Native PostgreSQL tests cover concurrent accounting, original replay, UNKNOWN, exact fee purpose, released-call counts, node limits and post-lock wall-clock expiry. A separate photo/media/HTTPS/stdio/MCP fixture uses deliberately synthetic external roles/usage/isolation to exercise failed-report admission. It stops before repaired-candidate production or publication. The preliminary JSONB-array failure remains archived separately. See the verification index for actual current-source results and the full unfinished product scope.
