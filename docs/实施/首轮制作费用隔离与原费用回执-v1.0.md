# 首轮制作费用隔离与原费用回执 / First-pass costs and original accounting

2026-10-30。对应 F09、F46、F55 的费用前置条件；不是完整自动修复的完成证明。自动选择问题节点、新候选制作、新封存包和两次全新独立复核仍须继续实现。全部方案禁售，真实付款、模型、生产隔离与云端未准入。

## 已实现的规则 / Implemented rules

原订单总预算包含首轮制作、冻结修复额度和冻结售后额度。`productionCeiling` 从原订单私有合同计算首轮上限，`reserve` 在锁定原订单后使用这个上限原子扣费；客户端和社区方案数据不能提供新额度。

| 示例 / Example | 原总预算 / Sold total | 修复保留 / Repair hold | 售后保留 / Aftercare hold | 首轮可用 / First pass |
| --- | --- | --- | --- | --- |
| 合成微单位 / Synthetic micro-units | 100 | 30 | 20 | 50 |

这两个保留额是原总预算内不可供首轮使用的部分，没有另开钱包、补充预算或延长订单截止。所有调用订单 `reserve` 的生成、Codex 推理、ASR、独立听音和预付许可分摊共享该保护；这不代表这些服务已通过真实接入验收。

An order's original total includes first-pass work, its frozen repair hold and its frozen aftercare hold. The shared reservation function derives the first-pass ceiling while holding the order row lock. All existing order-cost callers share this boundary; it creates no additional allowance or extended deadline. Real-service admission remains pending.

原费用意图按原归属、金额及规范化费率摘要重放。UNKNOWN 继续占用原费用；只有原回执确认实际金额或明确不收费才释放未用部分。相同意图但更换客户、订单、金额或费率返回 `COST_INTENT_CONFLICT`，不能伪装为一次正常恢复。重放原账目本身不授予再次调用供应商的权限，实际调用仍需原任务、租约、授权与期限核验。

An original intent replays only for the same tenant, order, amount and canonical rate snapshot. UNKNOWN keeps its original hold. Settlement releases only the unused bound proven by the original bill, or the original bound when non-charging is confirmed. Accounting replay never authorizes new provider I/O.

新增费用必须属于已确认付款、尚在执行且媒体访问未撤销的原订单。等待行锁后用实际时钟重查原截止。冻结保留值须为非负安全整数，总和不能超过原总额；格式不明或超界明确拒绝，不将其视为零额度。

New reservations require confirmed payment, an executable order, current media authorization and the original wall-clock deadline after lock acquisition. Malformed, negative, fractional or overflowing holds fail closed.

## 恢复与使用 / Recovery and use

正常开发仍使用[快速启动](../guides/QUICKSTART.md)的 API、Worker 与独立维护入口，无新增客户端操作或公开费用接口。新规则直接作用于现有订单调用链，不需要数据库迁移。

历史费用不会被改写、删除或视为免费。若旧执行已经占用本应保留的部分，保留其原有 UNKNOWN 和真实账单，阻止继续购买；不能补高预算、重建新订单或改原回执来使其通过。旧合同未声明的保留项沿用零值；显式无效值不能按缺省处理。

Existing API/Worker/maintenance commands remain unchanged; no database migration or new public budget endpoint is needed. Historical obligations remain payable and recoverable. If historical work already consumed a protected hold, new spending stops while original accounting remains intact. Missing legacy hold fields default to zero; explicitly invalid values do not.
