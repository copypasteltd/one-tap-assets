按用户进一步聚焦方案内容与云端封装的要求，新增 [生成式方案专项设计](方案驱动的云端服务与小程序封装-2026-10-27.md)：包含逐镜AI、参考图原生整片、人物/商品锁、声音与后期，并将10套官方方案映射到具体配方。下文继续提供通用业务底座；新增执行变体需另行实现、验证和排期。

## 1. 技术决策与目录

采用双小程序＋独立业务API＋原生媒体Worker。支付宝、抖音共享业务状态与schema，原生能力使用不同适配器；网页Plus为P1。前端候选为Taro/React/TypeScript，S0先验证两端相册与支付后冻结版本；跨端框架支持宿主并不等于视频保存/支付参数完全一致。[Taro官方资料](https://taro-docs.jd.com/)。

服务端拟采用TypeScript模块化单体，例如Fastify路由层；PostgreSQL保存业务与任务，私有对象存储保存原图/产物，独立Node Worker驱动图片处理和原生FFmpeg。首版不引入分布式微服务或必须依靠Docker/WSL的本地组件。PostgreSQL可以用项目内原生实例或已授权开发服务，不能擅自连接/改写其他项目数据库。

SQLite适合原仓库的本地工具；这里选择PostgreSQL主要是为了付费订单事务、任务锁和多人并发，避免把页面内执行器当后端。API和Worker直接调用领域服务，不通过请求Origin拼接内部HTTP调用。相册队列只负责设备保存，不承担服务端渲染推进。

拟建目录如下；路径清单不是“已经有代码”：

```text
src/

  mini-douyin/          # 同上，使用抖音交易和相册能力
  shared/
    contracts/         # API、档案、预设、计划、manifest运行时schema
    mini/              # 共享页面/组件/状态机，禁止依赖DOM/Electron
    policy/            # 展示层可用枚举；可信判定仍在服务端
  api/
    modules/
      identity/ assets/ products/ analyses/ presets/ community/
      quotes/ orders/ payments/ refunds/ deliveries/ support/ audit/
    db/migrations/     # 事务、唯一约束、到期任务
    adapters/          # 模型、支付、私有存储；密钥仅后端
  worker/
    queue/             # 租约、心跳、恢复、发件箱
    analysis/          # 视觉任务和事实边界
    compiler/          # ProductProfile + PresetVersion -> RenderPlan
    renderers/         # photo-image、photo-video、poster、copy
    qc/                # 严格合同QC与质量信号
    lifecycle/         # 到期清理、受影响订单、失败处置
  web/                 # Plus与独立鉴权的内部运营界面，P1/必要运营入口分开

```

若选择受许可约束地复用仓库合成器，应放入可追溯的独立来源目录，记录固定提交、修改和许可证，不与“独立原创实现”混写。现有克隆仍保留在 `runtime/repository-review/one-tap-ads/`；本次没有迁入生产源码。

## 2. 小程序交互：拍照、选择、自动制作、保存

底部导航建议为“制作 / 方案社区 / 我的”。普通买家默认在制作入口完成，创作者功能位于社区，不给买家增加发布或分享关卡。

| 页面 | 用户看到和做什么 | 状态与实现要求 |
| --- | --- | --- |
| 制作首页 | 拍商品；也可先浏览方案 | 不先问品类/材质/卖点，不要求配置模型key |
| 拍摄/素材页 | 拍3–5张；整体、角度、细节用短提示指导 | 逐张上传/成功保留；拒权、坏图、非同商品可补拍；不上传整相册 |
| 识别中 | 显示实际阶段：照片检查、识别商品、整理可见特点 | 进程离开页面后由服务端继续；不展示伪造百分比 |
| 方案选择 | 顶部轻摘要“识别为…；可见…”；推荐官方/社区方案 | 无强制确认；“识别有误”是可选纠错；识别失败明确重试，未收费 |
| 方案详情 | 授权样例、作者/来源、风格、节奏、图/视频清单、价和适用范围 | 清楚区分样例与本人商品；可收藏/用同款，不能复制示例商品数据 |
| 制作确认 | 照片缩略图、方案、必交清单、金额、预计时间、领取期限 | 收费时主动确认付款；不增加事实填表或人工审稿关卡 |
| 制作进度 | 排队、排图、合片、验收；后台可继续，回来恢复 | 订单付款、制作和退款分别显示；用户不需保持页面在线 |
| 成品页 | 用途有序的图片/视频，复制文案，保存整套/只存图片/视频/单项 | 每项保存状态；显示期限与失败项续存，不让手机解压ZIP |
| 我的作品/订单 | 草稿、处理中、可领取、退款、到期 | 订单与本机保存分开；丢失客户端缓存也能从本人订单找回 |
| 帮助/售后 | 补拍、相册权限、续存、有限修改、识别纠错与退款入口 | 不要求升级Plus或分享才能领取 |

先选方案时，拍照后仍必须完成视觉识别和输入充分性检查；先拍照时，识别完成后推荐方案。两条路径最终使用同一ProfileVersion和RenderPlan，不能维护两套事实源。

### 2.1 相册适配契约

共享逻辑调用以下内部接口，不把这些名字当作官方API：

```ts
interface HostAdapter {
  login(): Promise<PlatformLoginCredential>;
  capturePhotos(options: CaptureOptions): Promise<LocalPhoto[]>;
  downloadMedia(url: string, options: DownloadOptions): Promise<LocalMedia>;
  saveImage(local: LocalMedia): Promise<SaveResult>;
  saveVideo(local: LocalMedia): Promise<SaveResult>;
  openPermissionSettings(): Promise<void>;
  pay(request: ApprovedHostPaymentRequest): Promise<ClientPaymentSignal>;
}
```

官方SDK调用、最低宿主版本、权限声明、下载域名由各端适配器实现和记录。支付宝境内视频保存参数与基础库目前未核验完成；抖音视频需合法下载到本地再调用保存并满足授权条件，不能把远程链接直接当本地视频路径。[抖音官方保存接口](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/api/media/video/tt-save-video-to-photos-album)。

用户点保存才启动串行队列，或采用真机证明可靠的低并发：取新短链→下载一个→保存→记回执→清理临时文件→下一项。预算暂定100MB临时空间/单媒体30MB，最终用最长20秒包实测；不能因此私改已售分辨率。

每项状态为 `PENDING_DOWNLOAD → DOWNLOADING → READY_TO_SAVE → SAVING → SAVED`，失败按下载/权限/空间/格式分类。后台中断可暂停；成功项不重存，链接到期重新授权；回调丢失为UNKNOWN，提示可能已保存，由用户检查或明确再存。没有系统相册哈希查询保证，不能承诺绝对去重。客户端回执不能改变服务端付款和履约状态。

## 3. 上传与视觉商品档案

### 3.1 输入处理

1. 平台登录交换本产品会话；服务端从会话确定tenant，不接收客户端自报归属。
2. 建立ProductDraft，用户正常不填名称/品类等事实字段。每个私有Asset保存原图哈希、解码格式、尺寸、质量、所属草稿和到期时间。
3. 首版按主规格只接JPEG/PNG，单张≤10MB、3–5张总量≤50MB、短边≥640、解码像素≤30MP；这些是产品上限，仍要服从模型更严格的输入限制。HEIC等若宿主能安全转换则转换，否则清晰提示换图，不把改扩展名当转换。
4. 验证文件签名和实际解码，剥离定位EXIF，限制解码内存；拒绝SVG/脚本和远程任意下载。模型使用受控缩放副本，保留坐标回原图映射，渲染仍用合格原图。
5. 做照片角色、模糊/主体截断和跨图商品一致性检查。可通过补拍或选择同一主体解决，不要求填写长表。

字段状态枚举和类型由服务器schema校验，拒绝数值名称、任意类别、伪证据ID、越界框、外租户Asset等。证据ID由服务端归一化产生；模型输出的证据文字仍需语义与质量评估，不因有ID就视为真实。

模型自报置信度可作为诊断信息，平台记录独立 `verification_status` 和采用/省略原因，不用自报0.99代替准确率。包装“纯棉”只能记录为“标签写有…”，对高风险材质/功效等默认不进入确定卖点。用户可选纠错形成新版本，来源标USER_CORRECTION，也须适用事实政策；不是所有用户输入都自动成平台认证事实。

### 3.3 服务流程和失败语义

`POST /products/{id}/analyses` 返回202和analysis_id；客户端轮询本人状态。Worker先检查输入版本，再调用已批准视觉配置，不接受客户传baseURL/API key/model绕过服务端策略。结构化输出模式按真实模型能力接入，仍做本地schema、证据归属和语义过滤。[阿里云视觉文档](https://help.aliyun.com/zh/model-studio/vision-model)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

识别状态 `QUEUED/RUNNING/RETRY_WAIT/SUCCEEDED/NEEDS_PHOTOS/FAILED`。初始加最多1次自动重试；超时、坏结构或证据错误有明确错误码，不静默返回空档案。视觉服务失败时没有有效报价/付款动作；有效照片但部分属性未知，可用中性名称和真实图片继续，不能靠全部UNKNOWN伪造识别成功率。

缓存键含tenant、规范化照片集哈希、模型配置、提示词/政策版本；只在本人数据有效期内复用。删除原照片连同档案/视觉副本缓存清理，不跨用户缓存命中暴露信息。免费识别和创作者样例单独限频，已购权益不能被免费额度挤掉。

## 4. 预设契约、编译器与真实素材引擎

### 4.1 从设计配置到可执行发布版本

当前 [10套配置](../../assets/presets/presets.v2.json) 是DESIGN草案，不能直接设sale_enabled。执行发布版至少增加：

| 区块 | 必须约束 |
| --- | --- |
| 身份与版本 | preset_id、version、source、author、parent_version、schema_version |
| 授权与发布 | author_license、resource_licenses、sample_consent、review_record、publication_state |
| 输入 | 3–5张、照片角色、支持类别、主体规则、缺细节时的真实降级 |
| 图片 | 稳定slot_id、用途、固定尺寸/格式/顺序、布局模块ID、照片/特征选择规则 |
| 视频 | 30fps整数帧时间轴、总帧数、approved motion/transition ID、文字与可选音频资源 |
| 文案 | 可采用字段状态、最大长度、安全词规则、逐句claim_refs、未知字段省略策略 |
| 履约 | 所有必交slot、质量与成本基准、renderer版本、失败处置和可售PriceVersion |

社区配置只使用批准的模块ID、颜色/数值范围、许可资源ID。禁止自定义JS/Python、原始FFmpeg filter、任意本地路径、外链URL、网络模型工作流和无约束prompt。名称/简介等文本视为数据，不拼接为系统指令。已发布版本内容寻址并禁止UPDATE覆盖，草稿另存。

### 4.2 编译步骤

输入是冻结的AssetSet、ProductProfileVersion、PresetVersion、RendererVersion。输出是 `RenderPlan + ExpectedManifest + CostEstimate`：

1. 校验版本可用/许可、输入归属和充分性；只读当前订单照片/档案。
2. 将overall/angle/detail角色映射到槽位；同一原图允许合法不同裁切，但不伪称未拍视角，不减必交图片数量。
3. 从可采用观察生成受约束标题/卖点，每句绑定claim_refs。文案LLM不可用时按同一Profile用规则文案继续；没有Profile不能走规则冒充识别。
4. 按模块选择版式、主色、文字区、安全边距和保真策略。背景或抠图不可靠时按预设衬框保留原图，不能改变商品颜色/轮廓。
5. 将秒时间转换为整数帧，计算转场重叠和源片段需提供的帧数。全局timeline以 `[start_frame,end_frame)` 表示，边界必须连续、无负帧/缺口；总长从0到target_frames。
6. 产出图片、视频和文案计划及全部资源哈希，规范化JSON后计算plan_hash；报价冻结该哈希，不能由客户端手动改清单。
7. 发布审核的每个版本先跑输入变体和完整QC，不在买家付费后才发现无法编译。

极简纯净的计划固定4张PNG（hero/angle/detail为1080²、poster为1080×1920）和1条10秒视频。其时间段0–3.5–7–10秒对应帧边界0、105、210、300。选择淡化时必须在这些叙事边界内安排重叠/预留把手；不能直接把三个片段时长相加。观察已证明3×3秒加两次0.5秒淡化会变8秒。

官方10套视频目标帧数如下，图片清单以配置各自slot为准：

| ID | 图片数 | 视频秒数 | 30fps目标帧数 | 实现重点 |
| --- | --- | --- | --- | --- |
| minimal-clean | 4 | 10 | 300 | 浅色留白、轻推拉、商品主体保真 |
| warm-handmade | 5 | 15 | 450 | 暖色版面，禁止无依据宣称手工工艺 |
| quiet-luxury | 5 | 15 | 450 | 深色细节、控制暗部和文字对比，不改商品色 |
| fresh-daily | 4 | 12 | 360 | 均匀轻快、短标题、真实细节 |
| appetite-flash | 4 | 10 | 300 | 食物实拍快慢切换，不补造切面/蒸汽事实 |
| home-calm | 5 | 18 | 540 | 原有空间照/角度图、舒缓停留，不生成不存在的家居场景 |
| feature-cards | 5 | 15 | 450 | 一段一个可见特征；不足时改为真实角度/中性细节说明 |

| launch-story | 5 | 20 | 600 | 初见—整体—角度—细节—收尾，不伪造开箱 |

### 4.3 图片与视频执行

图片层拟用受限布局描述加原生图像处理库（例如Sharp）实现：原图裁切/缩放、批准衬框/色块、字形测量换行和安全区；图片/文字区域不能相互遮挡。服务端生成安全SVG或等价图层后栅格化，不接收作者上传的SVG执行。主图、角度、细节和海报是独立输出，不用视频抽帧代替全部图片。

每个slot都记录使用的asset_id、crop、transform、claim_refs和license_refs。足量有证据细节可以突出展示；不足时使用当前原图的保守裁切/留白，明确可接受的质量下限，收费前不能满足则要求补拍。

视频层接收整数帧计划，统一缩放/填边、轻推拉/平移、转场和文字；目标1080×1920、30fps、H.264/yuv420p MP4。可静音；配乐仅来自已核验许可库，不默认调用外部“免费”TTS或下载任意音乐。argv传参、shell关闭、资源路径白名单、超时/内存/并发预算和子进程取消不可省略。

Worker在 `runtime/jobs/{job_id}/{attempt}/` 下工作，字体等使用受控相对资源路径，清理只限已解析且确认位于该任务目录的路径。中文/空格路径、缺字、长标题、Emoji或不可用字形均有确定回退与测试，不能重新引入绝对字体路径失败。

### 4.4 严格QC和发布

| 硬门槛 | 检查方式与失败处理 |
| --- | --- |
| 清单完整性 | slot ID集合、必交数量、顺序和类型与ExpectedManifest一致，缺一不发布完整包 |
| 图片 | 实际解码PNG、尺寸精确、非空/非损坏、文字不溢出、来源合法 |
| 视频 | 全片可解码，实际尺寸/编码/pixel format/恒定30fps符合，帧数和时长误差≤1帧 |
| 内容与事实 | 文案逐句可回溯、无禁止高风险事实，照片/特征来自本订单输入 |
| 权利与隔离 | 资源有效、私有产物归属正确、没有他人图片和私有短链 |
| 文件预算 | 满足已售规格及已公开单媒体上限；超限重新编码而不偷偷降规格 |

黑场、音量、冻帧和美观度作为按预设解释的质量信号，静音方案没有音频是合法；实拍静图长停留不能一律判为冻帧失败。自动检查不能完全证明商品语义保真，仍需官方逐套样例和独立识别评测。

通过后上传私有暂存对象→核对全部对象哈希/规格→数据库事务写唯一DELIVERED版本/manifest→返回可领取。对象上传和数据库不是同一事务，因此用不可变对象＋最后的可见性提交＋孤儿对象清理；不把“多文件先后上传”误称原子发布。失败的临时文件没有下载权益。

manifest记录order/profile/preset/plan哈希、renderer版本、每项尺寸/帧数/sha256/顺序/来源/期限、copy条目。正文与manifest作为业务数据，手机相册仅保存PNG/MP4，不保存JSON/TXT。

## 5. 报价、付款、Worker与退款

### 5.1 业务对象与约束

| 表组 | 核心字段/约束 |
| --- | --- |
| users / tenants / platform_identities | platform+app_id+subject_id唯一；租户归属在服务端确定；跨端不按昵称合并 |
| product_drafts / assets / profile_versions | owner、输入哈希、不可变档案内容、策略版本、expires_at；Asset必须属于草稿和租户 |

| resource_licenses / public_samples / reviews | 公开样例独立对象/许可；审核绑定具体配置与资源哈希 |
| favorites / forks / reports / appeals | 收藏(user,preset)唯一；父版本许可检查；状态/处置审计 |
| compositions / quotes | profile/input/preset/resource/plan/manifest_hash、price_version、amount_fen、expires_at；报价15分钟 |
| orders / payment_events / entitlements | 平台/应用/商户/订单/实付金额固定；provider_event唯一，order entitlement唯一 |
| outbox_events / jobs / job_attempts | 业务去重键唯一；lease_owner/token/until、attempt、deadline、heartbeat、stage、错误 |

| refunds / refund_events | 原渠道、退款幂等键、累计金额≤实付；所有资金状态可查单 |
| save_sessions / save_receipts / audit_events | 用户/设备安装/媒体/尝试唯一；遥测不改变账务 |

含tenant的关联必须在数据库约束或Repository联查校验归属，不能只在最外层路由做一次登录。敏感日志脱敏，模型完整响应若需排障放私有短期日志并受审计访问，不混入公开统计。

### 5.2 状态与幂等

付款状态 `UNPAID/PENDING/PAID/FAILED/UNKNOWN/CLOSED`；制作状态 `NOT_READY/QUEUED/RUNNING/RETRY_WAIT/DELIVERED/FAILED/CANCELLED`；退款状态 `NONE/REQUESTED/PROCESSING/SUCCEEDED/FAILED/UNKNOWN`。不同轴独立记录，不用单一字符串同时表达“支付中”和“制作失败”。

客户端支付成功回调只促使服务端查单，不直接发权益。服务端验证签名、app_id/商户/渠道、原始订单和金额，记录事件并在事务内置PAID、创建唯一权益与outbox。提交后dispatcher消费outbox创建唯一job；失败可重试。20次相同通知只对应一份权益/一次有效履约。

自有API统一 `Idempotency-Key` 按租户/动作/请求规范化摘要绑定，相同键不同参数409；重复同参返回原资源。支付/退款还必须使用通道支持的原始业务单号查单，不靠HTTP幂等键代替通道幂等。

报价前检查识别成功、版本仍可用、输入充分、价格已发布和容量；报价后换图/档案/预设则失效。单价为整数分，平台后端决定；社区作者不能在配置中注入价格。未定价DESIGN预设不得收款。

### 5.3 持久队列与故障恢复

Worker消费PostgreSQL任务表。以下仅示范原子领取，正式实现还需迁移、字段/隔离测试和恢复器，不能直接作为完整队列库：

```sql
WITH picked AS (
  SELECT id FROM jobs
  WHERE state = 'QUEUED'
    AND next_run_at <= now() AND deadline_at > now()
    AND attempt < max_attempts
  ORDER BY priority DESC, created_at
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
UPDATE jobs AS j
SET state = 'RUNNING', lease_owner = $1,
    lease_token = lease_token + 1,
    lease_until = now() + interval '45 seconds',
    heartbeat_at = now(), attempt = attempt + 1
FROM picked WHERE j.id = picked.id
RETURNING j.*;
```

`SKIP LOCKED`适合多个消费者争抢任务的场景；不将这种不一致读用于普通账务查询。[PostgreSQL官方SELECT说明](https://www.postgresql.org/docs/current/sql-select.html)。

拟定心跳10秒、租约45秒是初始参数，S0/负载测试后冻结；每次心跳和完成写入带lease_token，过期旧Worker不能发布。恢复器先核查旧执行/供应商任务/已完成产物，再决定接管；已有外部任务ID则查询，不盲重提。原生FFmpeg未完成则终止/隔离旧进程后按预算重做。

普通识别和制作各允许初始＋最多1次自动重试，必须持久attempt记录。传输查询/状态恢复不应无限增加实际执行次数；如果不能证明外部付费请求未受理，标UNKNOWN并查原请求。已完成且哈希匹配的中间产物可复用；其来源和合同不能改变。

扫描器处理已付未入队、过期租约、到期未完整交付、UNKNOWN支付/退款、孤儿对象与过期私有数据。截止从确认可履约并收款进入任务时固定，不因重试/心跳延后；10分钟仍未交完整包则进入平台失败退款，不用无限排队隐藏违约。

取消/开始/交付/退款通过订单锁和条件状态转换裁决。已付未开始取消则原额退款；任务在退款决策后晚完成不得再提交有效发布或收费。退款请求幂等，实际到账依通道查询，未知和失败不能显示已退。多次退款合计不能超过实付。

## 6. 社区预设：发布配置、保护买家数据

### 6.1 小程序基础编辑器

提供“从模板派生 / 新建方案”，可选批准版式、色板、文字槽位、图数/比例、镜头节奏和许可音乐。不是桌面时间线的缩小版，使用卡片化分段和规格选项；关键操作均能在两端完成。

草稿编辑按expected_version乐观锁保存；变更输出数量/总帧数时即时校验。创作者用自己的或有授权的3–5张照片生成私有样例，消耗独立公开额度，不产生虚假消费者支付。主动选择另行授权的样例用于公开，不能从买家订单挑图发布。

提交时固定配置哈希/样例哈希/资源许可，执行编译、清单、事实、性能/成本和权利检查，进入 `PENDING_REVIEW`；运营可退回明确原因或发布。审核可人工，买家每单制作无需人工参与。

### 6.2 生命周期和数据边界

发布状态为 `DRAFT/VALIDATING/PENDING_REVIEW/CHANGES_REQUIRED/PUBLISHED/PAUSED/RETIRED/FORCE_DISABLED`。发布版本不可变，新编辑创建新版本并重新审核；目录的最新版本指针变化不影响历史订单。官方10套走同一校验，但来源和维护身份清楚标官方。

发现页支持官方/社区、风格/节奏、品类标签、素材数筛选。收藏幂等；用同款创建当前买家自己的composition，只复制许可允许的方案。热度基于有效用户和真实复用去重，不刷假订单。

派生必须指定父版本，核查允许派生、商用输出、资源限制和署名保留；子方案记录完整来源链，不以复制JSON洗掉作者。父版本有第三方音乐许可，不自动等于子作者有任意分发权，资源由平台台账判断。

普通下架停止新单，旧单使用已冻结许可继续；强制禁用按违规资源/版本定位受影响未交订单，冻结执行、通知并退款/补偿，不悄换方案。已保存相册媒体无法由平台远程收回。

作者仅看自己草稿、审核和脱敏聚合使用指标，不读买家原图、档案、付款信息、产物下载链接。投诉处理最小展示必要信息。举报/暂停/申诉/恢复均有审计，管理员不能直接改已售配置和已付金额。P0方案免费分享，平台制作价单独报价；不实现作者分成/提现。

## 7. API契约和错误处理

完整端点表见 [业务架构](../03-架构数据与接口.md)。路径前缀 `/v1/p01`。所有私有端点先查租户/归属，返回统一 `code/message/retryable/trace_id`；客户端不得从模型原始错误推断私有信息。

| 动作 | 请求关键字段 | 返回/保证 |
| --- | --- | --- |
| POST /sessions/platform | platform、app_id、临时登录凭证 | 服务端换会话；真实平台验证，客户端不自选user_id |
| POST /products、/assets | 草稿、图片字节和上传凭据 | 无必填事实字段；媒体真实检查、明确上传完成 |
| POST /products/{id}/analyses | asset_set_version、Idempotency-Key | 202，异步识别，不回伪空档案 |
| GET /products/{id}/profile | 本人草稿ID | schema版本、档案/轻摘要、证据、unknown/conflict |
| POST /quotes | product/profile版本、preset_version、platform | 有效15分钟、金额/清单/hash，已验证可履约 |
| POST /orders | quote_id、渠道上下文 | 原渠道批准付款动作，不能信客户端金额 |
| GET /orders/{id}、/jobs/{id} | 本人ID | 支付/制作/退款分别返回、实际阶段/期限 |
| GET /orders/{id}/deliverables | 领取权益 | 完整有序manifest、文案和到期信息 |
| POST /deliverables/{id}/download-link | 本人权益和媒体ID | 5分钟私有短链，过期重新授权，不重复收费 |
| POST /preset-drafts/{id}/submit | expected_version、样例/许可/配置hash | 待审结果，不能直接设PUBLISHED |
| POST /presets/{id}/forks | parent_version、许可确认 | 新草稿和保留来源链，不带任何买家素材 |

拟定错误码至少包括 `ASSET_INVALID/ASSET_EXPIRED/INPUT_NEEDS_PHOTOS/ANALYSIS_UNAVAILABLE/PROFILE_INVALID/PRESET_UNAVAILABLE/QUOTE_EXPIRED/QUOTE_INPUT_CHANGED/PAYMENT_PENDING/PAYMENT_UNKNOWN/RENDER_FAILED/REFUND_PROCESSING/ENTITLEMENT_EXPIRED`。可恢复错误明确重试动作；不把所有故障写成“生成中”。设备权限/空间错误在相册层分类，不能混成服务端渲染失败。

支付协议、SDK字段、验签规范不在此自造；按真实开通产品实现server adapter和沙箱/实付契约测试。支付宝网页Vibe Pay不是境内小程序权限证据，赛事认可路径也需单独核验；抖音不得外跳支付宝网页绕过本端交易限制。

## 8. 运维、隐私与成本

Windows原生分开启动API、Worker、数据库；脚本全部在 `scripts/`，数据与日志进入本项目runtime，启动先验证工作根目录和必要工具。不得执行仓库README中的Docker命令；不得扫描、迁移或删除其他项目数据。生产方案另以实际授权环境部署，本文不代表已部署。

对象分私有输入/私有输出/公开授权样例；私有响应不采用一年public缓存，短链过期和撤销传播需测试，且已下载到用户相册的副本不受服务端控制。未付款照片/档案24小时清理，已付款输入/档案7天覆盖修改窗口，完整输出交付后7天；订单必要账务记录只留最少版本/hash与依法需留的信息，不保留全照片作永久账本。

记录每个analysis/job/slot的trace、模型配置、CPU时间、峰值内存、字节、p50/p95、重试、退款与资源成本。免费识别、社区样例/审核、下载和支持时间也入成本。p95≤120秒是待测目标；一次6秒测试片的6670ms不能外推。

初始限制每Worker一个1080p视频，图片设置受控并发，实测内存/CPU后扩展。根据吞吐容量给报价/排队，不能无限接单再靠10分钟退款掩盖容量。私有照片不用于训练/营销，公开案例单独许可；模型处理目的/去向和保留政策须与真实供应商协议一致。
