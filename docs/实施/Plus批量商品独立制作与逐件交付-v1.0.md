# Plus 批量商品独立制作与逐件交付 v1.0

本轮落实需求 P01-F18 中的批量商品图片制作。电脑可一次选择2至10份已保存图片草稿，逐件冻结版本、风格和费用；原支付宝或抖音小程序逐件核对、主动付款，再独立制作、复核和交付。某件草稿失效、整理失败或未付款时，其他商品可以继续。

本能力接续[单图正式制作方案](Plus独立图片正式制作与手机付款交付-v1.0.md)。产品仍以支付宝和抖音小程序为主，Plus 承担大屏编辑和批量整理。P01-F18 的视频精剪、字幕和复杂预设作者工具仍未完成，批量图片通过不等于整项需求或58项产品验收通过。

English: Plus prepares 2–10 independently versioned image drafts as one recoverable group. Every product retains its own plan, frozen fee, native checkout, payment, job, budget, reviews and private delivery. One stale, failed or unpaid item never authorizes or blocks another item. This extends image production; video/subtitle editing and advanced preset authoring remain open.

## 使用与交互

| 编号 | 载体 | 用户操作与系统行为 |
| --- | --- | --- |
| 01 | 小程序 | 拍商品照片，由多模态识别商品及特征；沿用现有方案选择、制作和领取流程。 |
| 02 | 手机与 Plus | 电脑生成接续码，申请「整理独立制作清单」。手机核对同一接续码并主动批准；旧连接不会自动提升权限。 |
| 03 | Plus 单图编辑 | 打开本人已交付素材，调整裁切、尺寸、标题和可选品牌/事实，保存独立图片草稿。原素材和订单继续保留。 |
| 04 | Plus 批量制作 | 一次选择2至10份不同草稿。可先选默认风格，再逐件调整；风格标识与版本一同冻结。卡片显示真实原素材缩略图、草稿版本、规格和逐件价格。 |
| 05 | Plus 批次进度 | 点击「整理这批独立制作清单」。逐件显示整理进度及失败原因，记录可刷新、翻页和重新打开。刷新草稿会明确清空选择，不静默换用新版本。 |
| 06 | 原小程序 | 「账户与隐私 → 接续到电脑 Plus → 批量制作记录 → 逐件核对这批」。打开每件已就绪的清单，核对内容和完整费用，再分别主动付款。 |
| 07 | 独立云端任务 | 每个已付款订单按自己的合同运行制作、后期、QC、事实与风格双复核。其他未付款或失败商品不参与这件的执行。 |
| 08 | 小程序或 Plus | 每件通过后得到独立私有 PNG 和配套文案。小程序继续支持原有领取与相册保存；Plus 可打开该件新素材包。 |

批次不合并扣款，也不会因为勾选商品或建立清单而自动购买成品制作。每件价格以其冻结版本和原渠道报价为准。网页没有支付、退款和发布权限。

手机复用现有设置页及清单确认、订单、素材包页面，页面总数仍为17。Plus 批量入口位于工作台顶部，可返回单图编辑；断开电脑连接时清空内存中的批次和选项。

## 数据与状态

新增迁移 [037_plus_render_batches.sql](../../src/api/db/migrations/037_plus_render_batches.sql)，保留已发布的前36次迁移原字节。

| 记录 | 内容与约束 |
| --- | --- |
| `plus_render_batches` | 本人租户/账户、请求键摘要、输入集合摘要、2至10件数量和建立时间；不可修改。租户、账户与请求键摘要唯一。 |
| `plus_render_batch_items` | 批次内位置、本人商品关联、明确的草稿修订与风格版本、既有制作请求或安全失败原因；不可修改。 |
| 既有制作请求 | 继续冻结原素材、原合同、清单、裁切/尺寸/文字、方案/Skill、模型和独立价格。批次不复制或改写付费合同。 |
| 批次摘要 | 动态计算已建立清单、整理失败和素材移除数量。三项数量之和等于原选择数量。 |

| 单件状态 | 含义与恢复 |
| --- | --- |
| `PREPARED` | 已建立独立清单；内部继续显示规划、待手机确认、待付款、制作、交付或失败状态。 |
| `PREPARATION_FAILED` | 该次所选版本无法建立清单，其他商品不回滚。刷新草稿后重新选择这件，可建立新的批次；相同成功内容仍复用原请求。 |
| `SOURCE_REMOVED` | 商品已删除或过期，或对应制作记录已移除；保留原位置，输入、成品信息与失败内容全部返回 `null`。 |

批次和单件没有共享执行预算、共享付款状态或共享工作实例。单件的实际执行状态来自现有清单和订单，避免维护第二套容易失真的任务状态。

## 接口与重复提交

三项新业务接口均位于 `/v1/p01`，使用现有本人身份和响应校验，共新增9个 schema、2个逻辑实体。

| 方法与路径 | 作用与权限 |
| --- | --- |
| `POST /plus/render-batches` | 仅已获手机明确批准制作权限的 Plus 连接。输入 `request_key` 和2至10个不同草稿，每件有 `draft_id`、`expected_revision`、`variant_id`、`variant_version`。 |
| `GET /plus/render-batches` | 本人在原小程序或有效 Plus 连接中查看批次，沿用签名游标分页。 |
| `GET /plus/render-batches/{batch_id}` | 本人查看逐件当前状态；其他账户返回404。 |

`request_key` 为22至128位允许字符的随机意图标识，数据库只保存其摘要。同键同输入重试时读取实时批次；同键变更输入返回409。数据库不缓存私有响应正文，删除或撤销后不能通过重试复活旧内容。该接口不使用通用幂等响应缓存；其他原生报价、订单和付款继续遵守既有幂等规则。

客户端在结果不明时保留本次内存请求键与原选择，重试同一操作。改变选择或刷新草稿视为新的意图；页面刷新后可从本人批次历史恢复。凭证、意图与私有草稿不写入浏览器持久存储或分享链接。

## 执行与失败隔离

批次在现有业务事务内建立，先锁定账户并核对有效权限，再逐件使用数据库保存点。成功项建立独立的既有 PLAN 任务；某件版本冲突、失效或未准入时，只回滚该保存点并保留安全失败原因。身份失效或制作权限失效会终止整个请求。请求过程不购买模型推理，任务提交后才由现有 Worker 领取。

成功项沿用既有内容摘要自然键，所以网络重试或在新批次重选同一份已保存内容，不会再生成相同清单任务。两个商品的清单、报价、订单、工作任务、原素材和预算始终分别绑定。付款仍检查当前资格、来源、价格版本和有效期限；已失效内容不因属于批次而放行。

每件依次使用已有 CONTENT、PRODUCTION、POST、REVIEW_FACTS、REVIEW_STYLE 角色和确定性文件 QC。方案、目标素材及 Skill Bundle 在合同中冻结，五个角色分别隔离执行并释放实例；批次不持有长期客户实例。双复核未通过时沿用原有修复、退款和失败处理，不能以批次成功数替代单件质量结论。

## 隐私与资源

所有查询按租户和账户限定。商品删除触发单件记录删除；原制作请求删除也级联删除对应批次项。历史批次只保留摘要、数量和时间，读取时补回脱敏位置。商品到期的输入和详情同样在读取时隐藏；后续实际清理继续由现有生命周期处理器负责。

缩略图使用实际私有原 PNG，同源签名地址，禁止第三方来源、重定向与缓存；仅进入视口附近的卡片加载，同时最多两份。解码后只保留160像素缩略图，关闭位图、撤销对象地址；关闭批量工作台或电脑连接时取消尚未完成的预览。缩略图不冒充最终成片。

本轮不扩大既有底层数据库页、WAL、备份、供应商及存储副本删除的验收范围，也不改变现有生产准入约束。

## 配置与验证

复用现有 `PLUS_IMAGE_RENDER_ENABLED`、独立图片价格及价格版本，并继续要求付款、方案、模型、Skill、资源和 Codex 复核准入。默认真实服务和销售关闭；无准入时可以读取和编辑草稿，不开放正式制作。具体配置见[环境模板](../../.env.example)和[快速启动](../guides/QUICKSTART.md)。

最终源码、原始专项记录、编译、媒体和本机启动以[本轮证据](../verification/plus-batches-source.json)为准。四组原生专项覆盖权限、三件中单件旧版本失败、同意图去重/冲突、跨账户隔离、逐件报价付款、实际 PNG/双复核交付、另一件保持未付款、原素材保留、商品删除/到期脱敏及连接撤销。仅执行这条链路和交付所需检查，未执行全面测试。

[截图、实际成品及 MP4/WebM/GIF](../media/plus-batches/README.md)访问实际本机 HTTPS、PostgreSQL、MCP 和 PNG 管线。原订单付款/验收元数据、身份、模型回复、支付事件、语义结论与进程身份均为合成；手机操作使用原生服务接口，录像展示 Plus。编译成功不等于小程序宿主真机、真实模型质量、真实支付、生产隔离或云端上线通过。
